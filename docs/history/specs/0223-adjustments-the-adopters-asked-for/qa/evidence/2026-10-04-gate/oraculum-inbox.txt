# `branch.prefix` é decisão obrigatória do Baseline e não deixa o repositório ficar só com a regra normal de nome de branch

## O pedido do mantenedor

O mantenedor quer poder **desligar** a decisão `branch.prefix`, ou pelo menos torná-la
opcional, para que o nome das branches siga só a regra normal: `<type>/<descrição>`
pelo tipo do Conventional Commit, que já está na cláusula de commits do guia e na
regra global do mantenedor. Hoje o repositório não consegue deixar de ter um valor
próprio para isso.

## O que acontece

No Oraculum, em 2026-10-01, com Roundfix 0.23.0 (fonte em `origin/main` `35c01f49`):

1. `internal/baseline/assets/modules/core.json` coloca `branch.prefix` em
   `requiredDecisions`, ao lado de `language.generated`, `verification.gate` e
   `verification.incremental`. Todo profile carrega o módulo `core`.
2. `internal/baseline/assets/templates/guides/agent-instructions.md:7` interpola o
   valor sem condição: `The branch-prefix pattern is {{branch.prefix}}; ...`.
3. `internal/baseline/assets/decisions.json:154` define a decisão com
   `"default": "<type>/"` e um efeito de render sob `"when": {"present": true}`. O
   formato da decisão já prevê ausência, mas o módulo e o template não deixam ela
   acontecer.

Reprodução no Oraculum, com profile próprio `.roundfix/baseline/profiles/oraculum-backend.json`
(revertida depois, nada foi gravado):

```sh
# 1. Tirar "branch.prefix" da lista decisions do profile do repositório
sed -i '' '/"branch.prefix",/d' .roundfix/baseline/profiles/oraculum-backend.json
roundfix baseline profile validate oraculum-backend --format text
# -> oraculum-backend: valid (repository) ...   exit 0

roundfix baseline update --repo . --no-skills --format json
# -> exit 2, state failed, category manifest:
#    setup manifest is incompatible: resolve Setup Manifest decisions: normalize
#    Baseline decisions: decision "branch.prefix" is not selected by profile "oraculum-backend"
git checkout -- .roundfix/baseline/profiles/oraculum-backend.json
```

Também tirar a decisão do Setup Manifest leva ao mesmo erro de render medido hoje com
`verification.incremental` quando ela faltava no profile:
`render managed entry "guide.agent-instructions": missing render value for token ...`
(exit 2). Isso é inferência por analogia: esse segundo passo não foi executado para
`branch.prefix`.

O validador de profile aceita a remoção e o update recusa. Os dois comandos
discordam sobre se a decisão pode faltar.

## Por que isso importa

- **O valor só repete o que o guia já diz.** Com o padrão `<type>/`, a linha
  "The branch-prefix pattern is `<type>/`" duplica a cláusula de commits do mesmo
  guia ("Name new work branches `<type>/<description>` ... never use personal names or
  initials as branch prefixes"). A decisão só tem efeito quando carrega um prefixo
  próprio, e esse é justamente o caso que a política da frota proíbe desde 2026-09-08.
- **O prefixo pessoal sobrevive pelo manifesto.** O Oraculum ainda tinha `ma/`
  gravado até hoje, porque a decisão já assentada é reaplicada a cada `baseline update`.
  Ele foi trocado para `<type>/` editando `docs/agents/setup-context.json` e rodando
  `roundfix baseline update` (commit `9ff79081` do Oraculum, branch
  `chore/update-skills-set`). Outros repositórios da frota adotados antes de 09/2026
  podem estar na mesma situação.
- **Contexto anterior.** O finding
  `docs/history/findings/2026-09-08-run-branches-ignore-the-selected-prefix.md`
  (origem: `inbox/roundfix/_triaged/2026-09-08-branches-internas-do-run-ignoram-o-prefixo-do-repositorio.md`)
  e o commit `7f95346b fix: use purpose-based work branches and Roundfix run names (#177)`
  mudaram a política para branches por tipo de trabalho, mas mantiveram
  `branch.prefix` como decisão obrigatória. O que sobrou é esta decisão que não se
  desliga.

## O que esperaríamos (opções, a decidir pelo dono)

- Tirar `branch.prefix` de `requiredDecisions` do `core` e renderizar a linha do guia
  só quando a decisão estiver presente (o efeito `when: present` já prevê isso). Sem a
  decisão, vale só a cláusula de commits.
- Ou aceitar um valor explícito de desligamento (por exemplo `none`) com o mesmo efeito.
- Em qualquer caso: um caminho de migração para manifestos que ainda carregam um
  prefixo pessoal, e o validador de profile e o `baseline update` concordando sobre
  se a decisão pode faltar.
