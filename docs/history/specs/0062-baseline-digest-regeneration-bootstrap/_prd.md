# Baseline digest regeneration bootstrap

`make baseline-digests` cannot refresh the derived pins it exists to refresh.
Every step loads the embedded catalog; catalog validation rejects a formatter
`goldenDigest` that disagrees with the goldens on disk; only those steps rewrite
that pin. An ordinary Baseline module edit changes the generated guide, which
changes the goldens, which invalidates the pin, which refuses the load, which
prevents the refresh — and the command's printed remediation is the command
itself. A second defect compounds it: adding a Normative Clause reports
`catalog.sourceBaseline.required-clause.missing` for every new clause, because
the regenerator maintains digests and spans for manifest rows that already
exist but never creates one, and the diagnostic never says the tool cannot
supply it. Both surface on any module edit that changes a generated guide,
which is the ordinary case, so they block the autonomous Spec loop rather than
being incidental to one change. Evidence:
[`make baseline-digests` cannot bootstrap a Baseline module edit](../../findings/2026-07-30-baseline-digest-regeneration-cannot-bootstrap.md).

- Identifier strategy: not applicable — no project-owned Internal Identifier is
  created; diagnostic codes, profile identifiers, clause identifiers, and
  manifest row identities keep their existing contracts. Source:
  `docs/agents/domain.md`.
- Authentication and HTTP: not applicable — the governing clause prohibits
  reading, printing, committing, or generating secrets and forbids inventing
  authentication, authorization, transport, or deployment policy; this Spec
  handles no credential and opens no transport, since all behavior is local
  catalog validation and derived-artifact regeneration. Source:
  `docs/agents/agent-instructions.md`.
- Active ADR obligations: applicable — ADR-0081 keeps sanctioned digest
  regeneration a fallout of the authorized edit rather than an independent
  mutation; ADR-0085 establishes that a regeneration run is not gated on the
  pins it rewrites while every other load stays strict. Source:
  `docs/agents/domain.md`.
- Tooling authority: applicable — express maintainer authorization: on

  bounded files: `Makefile`. The maintainer expressly declined a marker file at

  Source: `docs/agents/agent-instructions.md`.

## Goals

- A Baseline module edit that changes a generated guide can be regenerated by
  running `make baseline-digests` once, with no hand-editing of derived pins.
- Outside regeneration, a derived pin that disagrees with its source still
  fails closed exactly as it does today.
- A diagnostic that the regenerator cannot resolve says so, and names what the
  human must do first.

## Core Features

1. Catalog validation gains an explicit regeneration mode in which a derived
   pin that disagrees with its regenerated source is deferred rather than
   fatal. Only the update path enables it; every other load stays strict.
2. `make baseline-digests` completes in one invocation from a Baseline module
   edit that changes a generated guide, rewriting the pins the edit invalidated.
3. A diagnostic the regenerator cannot satisfy — a Source Baseline manifest row
   that does not exist — states that the regenerator maintains rows but never
   creates them, and names the row the human must add first.
4. The change is bounded by a characterization corpus captured before it: every
   catalog that loads today still loads, and every diagnostic that fires today
   still fires outside regeneration mode.

## Non-Goals / Out of Scope

- Generating Source Baseline manifest rows automatically; this Spec makes the
  limitation legible, it does not remove it.
- The frozen parity corpus reading as a derived artifact — the finding's third
  defect, explicitly excluded by the maintainer's authorization.
- Changing what any diagnostic means outside regeneration mode, relaxing the
  Verification gate, or altering retention of derived artifacts.
- Changing Baseline profile or module content beyond what the regeneration path
  requires.

## Success Metrics

- Adding a clause to a Baseline module and running `make baseline-digests` once
  succeeds and rewrites the invalidated pins, proven by a regression fixture
  that reproduces the reported cycle.
- Outside regeneration mode, a formatter `goldenDigest` mismatch still fails
  with the same diagnostic code it emits today.
- A missing Source Baseline manifest row produces a diagnostic that names the
  row and states the regenerator cannot create it.
- Every catalog in the characterization corpus loads with the same diagnostics
  after the change as before, outside regeneration mode.

## Decisions

- Regeneration mode is explicit and scoped to the update path; the strict
  behavior is the default everywhere else. See
  [ADR-0085](../../adr/0085-a-regeneration-run-is-not-gated-on-the-pins-it-rewrites.md).
- This Spec evolves the regeneration path and never regresses validation. The
  single declared break is that a derived-pin mismatch stops being fatal
  **inside regeneration mode only**; any other change to diagnostic behavior is
  a defect.
