# Approved authority for Spec 0207

On 2026-09-30 the maintainer approved the program for waves 7 to 9 and, for this
Spec, decided that a repository with several stacks gets a built-in composed
profile (a Go CLI plus a TypeScript monorepo) with a composed setup, clauses
scoped by language or workspace, and one root `make verify` that calls the Go
and Bun Verification, and that the frontend layout becomes a recorded decision
like the HTTP Contract Decision, with the systems layout as the stated
suggestion, a recorded decision never overwritten, and existing adopters keeping
their current behavior. The same day the maintainer answered "Autorizar os
dois" to a structured question that named `internal/baseline/assets/` and the
guides under `docs/agents/`, which covers the Baseline source, its generated
guides and this repository's Setup Manifest. The maintainer also said
"considere autorizado a ajustar todas as skills se necessário" and authorized
`.roundfixrc.yml`; this Spec edits no skill and no Project Config and relies on
neither statement.

The governed set was measured with `GovernedPath` on `5f182757`, through a test
overlay that wrote nothing to the repository. Thirteen of the forty-three paths
the Tasks declare or create are governed.

## Why each governed path is unavoidable

- `decisions.json` is the only source of the Frontend Layout Decision
  (task_01).
- `modules/frontend.json` holds the systems clauses that gain their decision
  gate and the new repository-layout clause (task_01).
- `modules/go.json` records the Go guide's version, which the scope sentence
  raises (task_03).
- `templates/guides/frontend.md` and `templates/guides/go.md` are where the
  layout sentence and the Go scope sentence stand, and `templates/index.json`
  records their tokens and versions (task_01, task_03).
- `profiles/standard-typescript-monorepo.json` selects the new decision and
  states the layout suggestion; it also holds the formatter digest pin the
  regeneration rewrites (task_01).
- `profiles/go-cli-typescript-monorepo.json` is the new built-in profile
  and carries the gate-part markers (task_03) that task_04 validates and reads.
- `setups/go-cli-typescript-bun.json` is the composed Setup Snapshot, seeded by
  hand with its identity and composition and written in full by the asset sync
  (task_02).
- The Standard TypeScript Monorepo `frontend.md` formatter golden is
  regenerated by `make baseline-digests` and never hand-edited (task_01).
- `internal/baseline/derived_ownership_test.go` enumerates the sanctioned
  regeneration's outputs; the composed snapshot is a new one, and that is the
  only line that changes (task_02).
- `internal/cli/baseline_human_test.go` holds the decision-defaults table that
  gains the frontend layout row, and the scripted interviews that gain one
  answer for the new question or keep selecting the same profile after the new
  profile is listed (task_01, task_03).
- `docs/agents/setup-context.json` is this repository's Setup Manifest; the
  public Managed Refresh rewrites it after every Task, because every Task
  changes the catalog digest.

## Sanctioned regeneration

The grant names the command, and the tree names its outputs. No digest pin,
golden or generated guide is hand-edited.

```yaml
command: make baseline-digests
```

The composed snapshot's skills and activation bundles are written by
`go run -buildvcs=false ./cmd/roundfix baseline assets sync --source-dir <checkout>/setups --format text`
against the commit the `go` snapshot pins, never by hand. This repository's
managed guides and Setup Manifest are rendered by the public Baseline update,
`go run -buildvcs=false ./cmd/roundfix baseline update --repo . --no-skills --yes --format text`.
A second refresh must report `File changes: 0`.

## Limits

- No clause is renamed or removed, and the two systems clauses keep their
  identifiers, enforcement and guidance bytes. One clause is added.
- No setup snapshot other than `go-cli-typescript-bun` changes, and no
  `minimumVersion` changes.
- The Source Baseline corpus, the retention transitions and the parity corpus
  stay byte-identical.
- No skill, upstream skill, `~/dev/skills` content or other repository is
  edited.
- No Makefile target, lint, formatter or test-runner configuration, CI
  workflow or dependency changes.
- No top-level test is renamed or removed, and no exported function signature
  changes.
- No paid API use, release, tag, deployment or branch-policy exception.
- Verification stays Daemon-owned, and Task status stays Daemon-written.
