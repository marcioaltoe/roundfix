## Findings

### F01 — Friction — a failed proof appends a misleading session-cleanup failure

- Actor / journey: maintainer running `profiles validate` or `doctor` with a
  configured profile whose proof fails (R05's failing sequence).
- Expected: the failure names the real cause and its recovery, nothing else.
- Actual: the classification is correct (`model_not_advertised`, naming the
  affected `data` category and the advertised catalog), but the output appends
  `close disposable Agent Session "roundfix-preflight-…": … No named session …
  for cwd … and agent opencode; recovery: rerun Agent Selection readiness after
  the Session can be closed; next: restore Agent Session cleanup` — a second,
  misdirecting instruction about a cleanup problem the maintainer does not have.
- Reproduction: scratch repo with `data.preferred` = `runtime: opencode`,
  `model: opencode-go/not-a-real-model`, `reasoning_effort: ""`; run
  `roundfix profiles validate --category data` or `roundfix doctor`. Observed
  identically in both commands; never observed on a passing proof (R03, R04).
- Evidence: `qa/evidence/2026-08-08-qa-gate/failing-profile-validate.txt`,
  `doctor-failing-profile.txt` (tails).
- Impact tier: Friction — the refusal itself is right; the tail sends the reader
  toward a non-existent cleanup fault.
- Affected rows: none blocked; R05's observables were all reached.

### F02 — Friction — `runtime_managed` is user-facing but absent from the CONTEXT.md glossary

- The glossary check (task_08 req 7) against `CONTEXT.md`:
  - **Coined:** the proof encoding `runtime_managed`, introduced by task_03 and
    printed by `profiles validate` (`"encoding":"runtime_managed"`) and by the
    Run journal's selection events. `CONTEXT.md` has no entry for it. Its
    siblings `model_managed` and `independent` predate the Spec and are equally
    unglossed, so the Spec extended an existing undocumented convention by one
    rather than starting it. The roundfix skill does explain the
    `runtime_managed`/`model_managed` distinction in its Doctor Command section,
    so an operator is not without documentation.
  - **Changed:** none. Agent Selection Profile Readiness still reads true as
    glossed ("every distinct tuple"); Exact Agent Selection Proof's definition
    is untouched, and ADR-0106's reading — an empty reasoning assignment is
    applied by assigning nothing — keeps it that way.
  - **Dropped:** none.
  - **What was done:** task_07 was explicitly forbidden from editing
    `CONTEXT.md` ("a glossary gap, if any, is raised by the closing gate"), so
    this gate raises it here. Suggested follow-up: a glossary entry for the
    proof encodings, or a deliberate decision that encodings stay code-level
    vocabulary.
- Impact tier: Friction (documentation gap on a user-visible term).
- Affected rows: none blocked; R09 passes because recording this result is its
  criterion.
