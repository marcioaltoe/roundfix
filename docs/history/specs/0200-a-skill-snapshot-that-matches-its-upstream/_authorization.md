# Approved authority for Spec 0200

On 2026-09-30 the maintainer approved the program "Três ondas", whose block
"skills em dia" covers the skills and the Baseline. The same day the
maintainer expressly authorized editing the Baseline source and its generated
guides, answering "Autorizar os dois" to a structured question that named
`internal/baseline/assets/` and the guides under `docs/agents/`, and said of
the skills "considere autorizado a ajustar todas as skills se necessário". For
the upstream skills the maintainer decided "Corrigir lá e atualizar o pin",
then that upstream skills are vendored content Roundfix does not edit, and
fixed this Spec's content as the snapshot refresh to `a4e18e4`, the renames,
the `go-tui` setup and the dispatch validator. The governed set was measured
with `GovernedPath` on `9e439dbb`, through a test overlay that wrote nothing to
the repository.

## Why each governed path is unavoidable

- The four setup snapshots are what the refresh changes; `go-tui.json` is the
  new snapshot the maintainer's `go-tui` decision requires. The asset sync
  writes them (task_02).
- `internal/baseline/assets/profiles/go-cli-tui.json` names its setup, which
  becomes `go-tui` (task_02).
- `internal/baseline/assets/modules/core.json`, `go.json`, `rust.json` and
  `typescript.json` name the renamed skills and the required skills (task_02;
  `core.json` again in task_03 for `exa-web-search`).
- The Standard TypeScript Monorepo `skill-dispatch.md` golden and profile pin
  are regenerated by `make baseline-digests` and never hand-edited.
- `internal/baseline/derived_ownership_test.go` compares the sanctioned
  regeneration's outputs with a frozen 2026-08-06 enumeration. The new
  snapshot is a new output, so the test names that one addition (task_02). No
  other line changes.
- `docs/agents/skill-dispatch.md` and `docs/agents/setup-context.json` are this
  repository's managed guide and Setup Manifest; the public managed refresh
  rewrites them (task_02, task_03).
- The twelve `.agents/skills/` files are the bytes the public
  `baseline update` restores at `a4e18e4` for `context7-cli` and the three Go
  skills, and the one file of the obsolete `context7` directory, deleted after
  `baseline skills reconcile` removes its lock entry (task_04). They are
  upstream content, written only by those commands.
- `skills/baseline_skill_contract_test.go` pins the digest of every upstream
  skill the lock declares; the constant takes the value the test reports once
  the lock set changes (task_04). No other line changes.

## Sanctioned regeneration

The grant names the command, and the tree names its outputs.

```yaml
command: make baseline-digests
```

This repository's managed guides and Setup Manifest are rendered by
`go run -buildvcs=false ./cmd/roundfix baseline update --repo . --no-skills --yes --format text`,
and a second refresh must report `File changes: 0`.

## Limits

- No clause is added, removed or reworded, and no clause changes its
  identifier or enforcement level.
- No `minimumVersion` in a setup snapshot changes, and no Roundfix-owned skill
  is edited.
- No upstream skill is edited, and no `.agents/skills/` file outside the list
  above changes.
- `~/dev/skills` is read only.
- No Makefile target, lint or formatter configuration, CI workflow or
  dependency changes.
- No top-level test is renamed or removed, and no exported function signature
  changes.
- No paid API use, release, tag, deployment or branch-policy exception.
- Verification stays Daemon-owned, and Task status stays Daemon-written.
