# An audit that reads the authorization it was given

The changed-path audit refuses any file a Task commit touched that the authorization record does not name. It refuses two kinds it should not. Derived artifacts regenerated by the sanctioned command are refused, although an accepted decision already settles that they are deterministic fallout of the authorized edit and need no separate authorization — so the workaround is to list every consequence in the record, which is exactly what that decision rejected when it kept the grant drawn around the cause. And production code is refused, because the audit reads every changed path as governed, which forced one Spec to split a Task whose only fault was touching an ordinary Go file alongside an authorized asset. A third disagreement sits beside them: the PRD template tells an author to record `applicable` when no tooling changes, and the detector refuses that exact wording.
