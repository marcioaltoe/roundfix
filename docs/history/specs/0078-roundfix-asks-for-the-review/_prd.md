# Roundfix asks for the review

CodeRabbit's rate limit is counted per developer identity over a rolling seven
days, and the ladder is progressive: at 60 or more reviews in seven days a Pro
account drops from five reviews per hour to one. This repository's Supervisor
opens many Pull Requests a day, and every automatic review it never wanted —
an archive Pull Request carrying `+4/-1`, a rebase, a changelog fix — spends
from the same bucket as the reviews that matter.

The maintainer's answer is to stop reviewing by default and start asking. The
configuration decided on 2026-08-05, which task_04 commits:

```yaml
reviews:
  auto_review:
    enabled: false
    description_keyword: "coderabbit:review"
```

A Pull Request is reviewed when its body says `coderabbit:review`, and never
otherwise. The keyword is written explicitly because the Review Source schema
defaults it to the empty string, and `enabled: false` with an empty keyword
reviews nothing at all. That makes consumption intentional, and it breaks the
autonomous loop.

`watch --until-clean` pushes a round's fixes and then waits for Review Source
Evidence bound to the new head. With automatic review off, no review runs, no
Evidence appears, and — since Spec 0077 closed the fail-open default — the
Evidence correctly resolves `pending` and stays there until the Run times out.
Roundfix already computes the exact comment that would fix this, carries it in
`ManualReviewCommand`, and prints it on stderr for a person to paste. Nobody is
watching an unattended Run's stderr.

The measured shape, from Pull Request #124 under the old configuration:

| Head | What it was | Review |
| --- | --- | --- |
| `4a03df27` | Pull Request opened | one |
| `83edf0ea` | the round's fix push | one |
| `065c71db` | the artifact-only docs commit | none — `path_filters` excludes it |

Two reviews for one Pull Request with one round. This Spec keeps that number
and removes every review nobody asked for, by making the request explicit and
bounding it to one per Round.

## Goals

- A Round that pushes ends with the review actually requested, so an unattended
  Run advances without a person pasting a comment.
- Review consumption per Pull Request is bounded and predictable by
  construction: one at open, then at most one per Round.
- A configuration that would strand the loop is refused before the Run starts,
  not discovered when it times out.

## Core Features

1. After a Round's Final Push, `watch` and `resolve` publish one review request
   for the pushed head through the Review Source, then wait for Evidence bound
   to that head as they do today.
2. The request is idempotent per head SHA: a Round that pushes twice, a
   resumed Run, and a replayed completion all produce at most one request for
   the same head.
3. `fetch` never publishes a request. It is the read-only command and stays
   read-only.
4. The request is configuration, not a default. A repository states whether
   Roundfix asks, and Preflight Validation refuses a pair that cannot work —
   automatic review off with asking off strands every Run; automatic review on
   with asking on buys a second review for every Round.
5. A request the Review Source refuses — rate limit, quota, or any explicit
   decline — resolves as the `skipped` Evidence Spec 0077 already produces, and
   the Run stops and names it. No retry, no backoff, no capacity wait.
6. Requests are bounded by the Round cap: at most one per Round and never more
   than the Run's Max Rounds, so a Run's worst-case review consumption is
   readable from its configuration before it starts.
7. Each request and its outcome are recorded in the Run Event Stream, so an
   operator can tell a review that was never asked for from one that was asked
   for and refused.

## Non-Goals / Out of Scope

- Backoff, attempt limits beyond the existing Round cap, capacity detection,
  and waiting for the Review Source to recover. A refusal ends the Run; the
  operator decides what happens next.
- Changing the Evidence classification Spec 0077 shipped. This Spec produces
  the signal that classification reads; it does not reinterpret it.
- Changing how Review Issues are fetched, fingerprinted, or resolved.
- Opening Pull Requests, writing their bodies, or inserting the
  `description_keyword` that starts the first review. That is the author's
  action, and Roundfix opens no Pull Request.
- Choosing or configuring the Review Source, its plan, or its limits.
- Changing QA verdict semantics, owned by ADR-0080.

## Success Metrics

- With automatic review disabled, an unattended `watch --until-clean` Run
  completes a Round and reaches its next Evidence without a person commenting,
  where today it waits until the Review Source timeout and ends unverified.
- One Round produces exactly one review request, asserted for a Round whose
  Final Push is followed by the artifact-only docs commit.
- A configuration pair that would strand the Run is refused by Preflight
  Validation with the offending keys named, before any Agent Session, Review
  Source mutation, commit, or push.
- A refused request ends the Run naming the refusal, and no second request
  follows it in the same Run.
- With asking disabled, every command behaves exactly as it does today,
  asserted over the existing tests unchanged.

## Decisions

- Roundfix asks once per Round, immediately after the Final Push that carries
  the round's fixes. The artifact-only docs commit inherits its parent's
  Evidence under ADR-0036 and is not worth a review of its own.
- Asking is opt-in configuration rather than a new default, because the
  correct value depends on the repository's `.coderabbit.yaml`, which Roundfix
  does not own.
- Preflight refuses an incoherent pair instead of warning. A warning on the
  stderr of an unattended Run is the failure mode this Spec exists to remove.
- No retry. The Round cap is the only limit, and the operator sees the refusal.
  Backoff and capacity detection are policy, and this Spec is already the
  second half of an urgent correctness fix.
- `max_rounds` drops to `2` for this repository, capping a Pull Request at
  three reviews. Pull Request #124 closed in one Round; the second exists for
  the case that does not.
- This Spec evolves the review boundary and never regresses it: asking never
  substitutes for Evidence, and a repository that does not opt in keeps every
  behaviour it has today.
