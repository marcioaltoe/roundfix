# Tooling authorization — Spec 0082, Baseline update command (2026-08-07)

On 2026-08-07 the maintainer authorized the protected tooling boundary for
Spec 0082, after reviewing the evidence that an already-adopted repository
cannot refresh its Baseline without answering every settled question again:

> Autorização de tooling para a Spec 0082 — Skills + module assets, limitado
> ao propósito.

The grant is bounded by purpose. It permits exactly the tooling changes that
teach the new update path to the repositories that consume it, and nothing
else. `docs/agents/spec-routing.md` states that generic implementation
approval is not authorization, so the maintainer's standing authorization for
autonomous action does not reach these paths by construction; this file is the
operative source Spec 0082 cites.

## Authorized paths

### Roundfix-owned Skills

- `skills/setup-context-driven/**` and its `.agents/skills/setup-context-driven/**`
  mirror, regenerated by `make skills-sync`.
- `skills/roundfix/**` and its `.agents/skills/roundfix/**` mirror, regenerated
  by `make skills-sync`.

The `setup-context-driven` skill documents the `roundfix baseline` command
family and is not covered by the 2026-08-04 standing skill-sync grant, which
is limited by purpose to `.agents/skills/roundfix/**`. The `roundfix` skill
pair is restated here so the CLI skill-sync HARD RULE has one citation for
this Spec rather than two.

### Baseline module assets

- `internal/baseline/assets/modules/*.json`, limited to teaching the update
  command to generated repository guidance.

This permits a module asset to name the update path where its generated
guidance already names `roundfix baseline`. It does not permit changing any
module's Normative Clauses, decisions, capabilities, or template selection for
an unrelated reason. A module edit outside that purpose needs a new grant.

## Sanctioned fallout — no separate grant

Derived pins rewritten by `make baseline-digests` after an authorized source
edit are deterministic consequences of that edit, per the sanctioned
digest-regeneration HARD RULE in `docs/agents/specific-repository.md`:

- `internal/baseline/testdata/catalog.digest`
- `internal/baseline/testdata/catalog.normalized.json`
- `internal/baseline/testdata/parity-corpus/v1/**`
- `internal/baseline/assets/setups/**`

A hand-edited pin value remains an unauthorized mutation regardless of this
grant.

## Not authorized

- Any `internal/baseline/assets/modules/*.json` change that alters guidance for
  a reason other than the update command.
- Any other member of `OWNED_SKILLS`.
- `internal/baseline/assets/profiles/**` and `internal/baseline/assets/templates/**`.

## Commit choreography

This record lands as its own commit, before the commit of any Task it
authorizes. A prerequisite fix — one repairing something already red before the
Task — is also its own commit, in either relative order. A consequent fix, one
made necessary only because the authorized change made something else stale,
is its own commit landing after the Task commit. Either kind folded into the
Task commit fails the tooling-authority gate.
