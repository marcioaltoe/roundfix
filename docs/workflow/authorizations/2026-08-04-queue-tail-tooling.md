On 2026-08-04 the maintainer authorized the three outstanding tooling
boundaries at the tail of the Spec queue:

> Os 3 pontos em 0073, 0059 e 0065 estão autorizados, pode fazer as
> modificações necessárias para que funcionem.

The three points are the ones surfaced from each Spec's Tooling authority row:

`docs/agents/spec-routing.md` states that generic implementation approval is
not authorization. Spec 0072's F-001 cost four gate executions for exactly the
defect this file prevents — a PRD citing an authorization it was not listed in.

## Addendum — 2026-08-04 — Spec 0070 and the QA gate skill

Spec 0070's PRD records `Tooling authority: not applicable — no protected
tooling mutation is proposed or authorized; the work is product code, CLI
surface, and documentation`. Authoring its TechSpec showed that is wrong, and
the row is corrected in the same change that adds this addendum.

Core Features 2, 3, 7 and 8 all land in `.agents/skills/qa-gate/SKILL.md`,
which is where the blocked-cause taxonomy, the verdict rules, the
`rows_blocked_*` frontmatter fields, and the code-caused versus
environment-caused classification are defined. No product code path can
deliver them: the gate's behaviour is the skill. `qa-gate` is a member of
`OWNED_SKILLS`, so editing it is a protected tooling mutation.

The maintainer authorized it on 2026-08-04, choosing this over splitting the
Spec so that Core Feature 7 — a static-gate failure blocking only the rows it
implicates — ships with the rest. That feature is the one whose absence cost
two full gate cycles the same day: one governance finding marked fifteen of
twenty-four rows blocked on Spec 0072, and thirteen of fifteen on Spec 0064.

- **0070** — `.agents/skills/qa-gate/**` and its `skills/qa-gate/**` mirror,
  regenerated by `make skills-sync`. Deterministic digest fallout is
  sanctioned by ADR-0081.

The grant is bounded to that one skill. It does not reach the other members of
`OWNED_SKILLS`, and a later Spec in this queue that needs one asks separately —
the per-Spec boundary is what makes a citation checkable.

## Addendum — 2026-08-04 — Spec 0070, close, and the Roundfix Skill

Spec 0070's QA gate reported F-001: the Archive Command's operator-facing
contract still teaches the pass-only rule the Spec just widened.
`docs/user-guide/commands.md` and `.agents/skills/roundfix/SKILL.md` describe a
command that refuses what the shipped binary now accepts. The built help and the
real archive journey are already correct — only the documentation lies.

The repository's own HARD RULE makes the skill update a precondition rather
than a nicety: "before opening any PR, confirm the roundfix skill still matches
the shipped CLI behavior; a PR that changes CLI behavior ships the skill update
too." Spec 0070 changes CLI behaviour, so the Spec cannot close without it.

The Spec 0070 addendum above bounds this Spec to the `qa-gate` skill and says
plainly that it "does not reach the other members of `OWNED_SKILLS`, and a later
Spec in this queue that needs one asks separately." This is that asking. The
maintainer authorized it on 2026-08-04, following the precedent set at Spec
0072's close, where the same surface was recorded rather than assumed.

- **0070, close** — `.agents/skills/roundfix/**` and its `skills/roundfix/**`
  mirror, regenerated by `make skills-sync`, for the Archive Command contract
