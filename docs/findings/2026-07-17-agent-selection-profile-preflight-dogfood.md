# Agent selection profiles — generated defaults block Vortex runs (2026-07-17)

Vortex dogfooding used a Project Config generated by `roundfix setup` and the
latest publicly available ACP toolchain. Preflight correctly created no Run,
but it proved that the generated profile defaults and the canonical invocation
guidance are not operational together.

## 1. Generated GPT-5.6 defaults fail disposable-session proof

- **Symptom / evidence**: `roundfix profiles validate --json` exits `2` for
  `codex / gpt-5.6-sol / high`. The adapter rejects
  `session/set_config_option` for `reasoning_effort=high` with ACP `-32602`.
  Earlier proof also showed that `gpt-5.6-terra / max`, which `roundfix setup`
  generated as the fallback, is not advertised by the installed adapter.
- **Environment**: macOS Apple Silicon; Codex CLI `0.144.5`; ACPX `0.12.0`;
  `@zed-industries/codex-acp` `0.16.0`. These were the latest public package
  versions returned on 2026-07-17.
- **Root cause**: `builtinProfiles` and `DefaultConfigYAML` hard-code
  `gpt-5.6-sol / high` and `gpt-5.6-terra / max`. ADR-0040 records that the
  GPT-5.6 family requires model-managed reasoning with the pinned adapter, but
  setup output, built-ins, recommendations, and examples still encode explicit
  effort values. The generated configuration was never proven against the
  supported runtime tuple before it became the default.
- **Action / suggestion**: do not generate an operational default until its
  exact runtime, model, and reasoning tuple passes disposable-session proof.
  With this toolchain, use `gpt-5.6-sol` with model-managed reasoning and a
  separately proven fallback such as `gpt-5.5 / xhigh`. Keep Terra and Luna as
  unavailable recommendations until the installed adapter advertises and
  proves them.

## 2. Canonical `--agent codex` guidance masks category profiles

- **Symptom / evidence**: after replacing the fallback with
  `gpt-5.5 / xhigh`, this command exits `2` before Run creation because the
  resulting Preferred Selection duplicates the fallback:

  ```text
  roundfix implement --spec 0006-uniformidade-uuidv7 --agent codex --qa --detach
  ```

  Review Run `run_20260717T142229Z_194a8e725fb8e7e6` independently confirmed
  the selection behavior. The Project Config preferred
  `gpt-5.6-sol / high` for `review`, but `resolve --agent codex` ran with
  `gpt-5.5 / xhigh`.
- **Root cause**: `invocationProfileOverride` treats `--agent` by itself as a
  complete one-Run Preferred Selection override. The canonical Roundfix Skill,
  CLI usage, and user guide always include `--agent`, even though those same
  documents say omitted invocation flags use the category profile. The normal
  documented command therefore bypasses the profile-driven default.
- **Action / suggestion**: make profile-driven commands omit `--agent` unless
  the caller deliberately requests a complete one-Run override. Update CLI
  usage, the canonical skill, and examples together. Preflight must explain
  that an agent-only override selected the legacy tuple and either reject it
  with an exact remediation or define a non-duplicating runtime-only semantic.

## 3. Doctor does not prove the effective Agent Selection Profiles

- **Symptom / evidence**: `roundfix doctor` reports
  `model: ok (gpt-5.5)` while the effective Vortex profiles contain
  `gpt-5.6-sol / high` and `gpt-5.5 / xhigh`; the subsequent operational
  preflight fails the first profile tuple.
- **Root cause**: Doctor probes the legacy Codex runtime default instead of the
  effective required profiles and their configured fallbacks.
- **Action / suggestion**: Doctor readiness must use the same effective-profile
  resolution and disposable-session proof boundary as operational preflight,
  or explicitly report that profile readiness was not checked. Route this into
  `docs/specs/0036-doctor-skill-readiness` before the CLI claims the repository
  is ready.

## What worked — keep

- Preflight stopped before Run persistence, Agent work, worktree creation, or
  file changes.
- The structured profile validation output named the rejected tuple, affected
  categories, ACP error code, and model-managed recovery option.
