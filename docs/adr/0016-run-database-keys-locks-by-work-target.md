# Run database keys active-run locks by work target

Implementing ADR 0012, the Run Database migrates to schema v4: `active_run_locks` is keyed by `(target_kind, target_key)` — `pr` with `<head_repository>#<pr_head_branch>` for review Runs, `spec` with `<git_root>#<spec_slug>` for spec Runs — and `runs` gains an `implement` Kind plus a nullable `spec_slug` column, with the PR-shaped columns (`head_repository`, `head_branch`, `pr_number`, `head_sha`) required only for review Kinds. The single-working-tree stopgap is a Preflight Validation query over Active Runs sharing `git_root`, not a second lock table, so it disappears with worktree-per-task instead of leaving schema residue. The alternative — a separate `spec_runs` table — was rejected because Attach, `stop`, and the Run Event Journal treat all Runs uniformly by run id.
