# ADR-0058: Baseline upgrades fail closed on unaccounted managed-rule removal

Status: Accepted

A real 0.9.0 upgrade replaced previously managed Normative Clauses wholesale while the new catalog passed its own coverage contract, because coverage was validated only inside the selected current catalog. Every Context-Driven Baseline transition must map each prior Normative Clause to a current rule, Repository-Specific Normative Rules, a recognized typed repository document, or an explicit rejection with a recorded reason; preview and apply block while any clause is unaccounted, and the Change Plan presents the accounting. Byte preservation outside markers protects repository content, not the normative strength of what earlier setup versions placed inside markers — only clause-level retention accounting does.
