## What is ready to start

**Spec 0055 — owner identity without fork.** `_techspec.md` and a five-Task
graph are committed. The design replaces `processStartIdentity`'s `ps -o lstart=`
subprocess with direct kernel reads: `/proc/<pid>/stat` field 22 on Linux
(counted from the **last** `)`, because the comm field can contain spaces and
parentheses) and `KERN_PROC_PID` via `golang.org/x/sys/unix` on macOS, which is
already a direct dependency so no new module is needed. The token gains a
platform prefix so a token recorded by the old `ps` implementation classifies
as *unreadable* rather than as a proven mismatch — that is what makes the
migration fall out of the feature instead of needing a schema step.

This Spec has a concrete side benefit: it fixes the
`fork/exec /bin/ps: operation not permitted` denial that currently shows up as
an environment-blocked row in every QA run in this repository.

## The loop order to follow

Corrected in PR #52 after Spec 0053 spent two full QA cycles proving the
original wrong:

> implement the Task Graph → open the Pull Request → `roundfix watch` until
> Clean → request QA once → merge only on `pass`

with two preconditions the clause now states explicitly:

- The order above applies to Specs whose acceptance observes Pull Request
  review surfaces. A Spec whose matrix touches no review surface may request QA
  as soon as the graph closes. (CodeRabbit caught this: the first version made
  the order unconditional and needlessly serialized every Spec.)
- **Rebuild the binary before requesting QA.** Three of Spec 0053's five QA
  cycles ran against a Daemon built before the Spec existed, so the gate
  reported defects the running artifact did not contain and the reports were
  unactionable. `make install`, then check `roundfix --version` names the
  current commit.

## Traps this session hit — do not rediscover them

1. **`roundfix archive` fails silently here.** The `archive-spec` Skill
   prescribes `chore(specs): archive <slug>`, and `cog.toml` sets `scopes = []`,
   so the hook rejects it. The failure is invisible if the commit runs through a
   pipe. Use an unscoped subject: `chore: archive <slug>`. This is unrouted and
   deserves a Spec or a Skill fix.
2. **Never run a gate through a pipe.** `git commit … | tail -1` reported "ok"
   while the hook rejected the commit, and `&&` proceeded to a push that
   reported success. This is the documented HARD RULE in
   `docs/agents/specific-repository.md`, violated hours after it was written.
   Capture `$?` or redirect to a file.
3. **`make baseline-digests` cannot bootstrap a Baseline module edit.** Every
   step loads the catalog, catalog validation rejects a stale
   `formatter.goldenDigest`, and only those steps refresh it — so the failure
   tells you to run the command that cannot run. Recompute the pin with
   `portableFileDigest` over the profile's `fixturePaths` first. Recorded in
   `docs/findings/2026-07-30-baseline-digest-regeneration-cannot-bootstrap.md`.
4. **The parity corpus under `internal/baseline/testdata/parity-corpus/` is
   frozen evidence, not a derived artifact**, despite sharing a
   `DERIVED_DIGEST_PATHS` entry with derived files. Its regeneration rewrites
   only `fixtures/asset-sync.json`. A guide whose module grew past the frozen
   date belongs in the named exclusion set in `plan_test.go`, not in a rewritten
   fixture.
5. **Failed QA runs leave Run Branches nothing can release.** Supersession needs
   a newer report on the target branch, and a report reaches the target only on
   `pass`. Four failing cycles left four branches that `reconcile` calls
   `unintegrated` and Branch Integrity Preflight refuses to work around, with a
   printed fast-forward that no longer applies. They had to be deleted with git
   directly. Recorded in
   `docs/findings/2026-07-30-failed-qa-runs-accumulate-unreleasable-run-branches.md`.
