# A green check is not a review

When CodeRabbit declines to review because the account hit its rate limit, it
publishes a check named `Review rate limited` whose conclusion is **success**,
deliberately, so the block does not prevent a merge. The authoritative signal is
the comment it posts, not the green check.

Roundfix reads the check. `structuredSkipReason` recognises only a check whose
output title is `review skipped`, so `Review rate limited` falls through to the
settled path, `settledEvidenceState` sees zero unresolved threads, and the
evidence resolves `verified`. `acceptedVerifiedEvidenceForHead` accepts it and
`watch --until-clean` proceeds to push and merge.

The gate fails open:

```text
CodeRabbit does not review
  → check "Review rate limited" is green
  → Roundfix records evidence: verified
  → the loop pushes and merges unreviewed code
```

This already happened. **Pull Request #107 — 125 files, +5,621 lines, an entire
new `internal/speccheck` package and a new CLI command — merged with no review
at all**, because this repository's own Supervisor read the green check as
verification. An audit of the same session found three more merges with no
review; those were archive Pull Requests carrying `+4/-1` of real content, so
the exposure is small, but the label was wrong there too.

ADR-0054 already states that Review Source evidence determines review outcomes,
and the glossary already carries the right state: `skipped` is the Review Source
"explicitly declining that head". A refusal is a decline. It was never mapped.

The deeper defect is not the missing string. It is that a green check reaches
`verified` **by falling through** rather than by proving a review happened. A
list of known refusal titles would fix today's shape and leave tomorrow's open,
so this Spec inverts the default: `verified` requires positive evidence that a
review ran, and everything else is `pending`.

Two adjacent defects spend review rounds and are deliberately **not** in scope
here, because an urgent correctness fix should not carry policy. They are
recorded for the Spec that follows:
[gate and review rounds need a convergence rule](../../findings/2026-08-03-gate-and-review-rounds-need-a-convergence-rule.md)
and
[an accepted gap has no terminal state](../../findings/2026-08-04-an-accepted-gap-has-no-terminal-state-so-the-loop-cannot-close.md).

## Goals

- A Review Source that declines to review a head never produces `verified`
  evidence for it, and the loop stops rather than merging.
- `verified` requires positive evidence that a review ran, so a signal Roundfix
  cannot classify can never approve a merge.
- An operator can tell, from the Run's own record, whether a head was reviewed,
  refused, or unclassified.

## Core Features

1. A Review Source refusal — rate limit, path-filter skip, quota, or any other
   explicit decline — resolves as `skipped` evidence naming the refusal, never
   as `verified`, and is recognised by class rather than by one vendor string.
2. `verified` is reachable only through positive evidence that a review ran.
   Any other signal, including an unrecognised check with a success conclusion,
   resolves `pending`. Unknown is not success.
3. Refusal recognition reads the authoritative signal the vendor documents, not
   only the check conclusion, because the conclusion is green by design.
4. `watch --until-clean` treats a refused or unclassified head as not reviewed:
   it does not push, does not merge, and names what it observed.
5. Evidence for one head never verifies another: a refusal or a review recorded
   against an earlier commit does not settle the current one.
6. The classification and its reason are recorded in the Run Event Stream, so an
   operator can tell a refused review from an absent one without reading GitHub.

## Non-Goals / Out of Scope

- Changing the Review Source, its plan, its configuration, or its rate limits.
  Volume control outside this repository's code is a maintainer decision.
- Implementing a review provider, a fallback reviewer, or a second opinion.
- Changing how Review Issues are fetched, fingerprinted, or resolved once a
  review has actually happened.
- Changing QA verdict semantics, owned by ADR-0080.
- Retrying a refused review, and every policy that implies: backoff, attempt
  limits, capacity detection, retrigger deduplication, and timeouts. Deferred
  deliberately — an urgent correctness fix must not carry policy.
- The convergence rule between a fix round and the review it triggers, and the
  `accepted` terminal status for a correct finding deliberately not fixed. Both
  spend review rounds and both belong to the Spec that follows this one.

## Success Metrics

- Replayed against Pull Request #107's exact check payload, the evidence
  resolves `skipped` and `watch --until-clean` refuses to merge, where today it
  resolves `verified` and proceeds.
- A rate-limit refusal and a path-filter skip both resolve `skipped`, proving
  recognition is by class rather than by one string.
- An unrecognised check name with a success conclusion resolves `pending`, and
  no merge follows.
- A refusal recorded against an earlier commit does not verify the current head.
- Every recorded payload that resolves `verified` today still does, so a real
  review never stops counting.

## Decisions

- A refusal is a decline, and the glossary's `skipped` already means exactly
  that. This Spec maps a missing case rather than inventing a state.
- Unknown resolves to `pending`, never to `verified`. A gate that cannot
  classify a signal must not treat it as success.
- The default is inverted rather than the refusal list extended. A list of
  known refusal titles fixes today's shape and leaves tomorrow's open; the
  boundary has to hold for signals nobody has seen yet.
- The retrigger is deferred on purpose. It needs backoff, attempt limits and
  capacity detection, and bundling policy into an urgent correctness fix is how
  urgent fixes stop being urgent.
- This Spec evolves the review boundary and never regresses it: every head that
  reaches `verified` today through a real review still does, and every refusal
  the loop makes today it still makes.
