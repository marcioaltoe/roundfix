# Task 01: The owner of a Skill Activation requires every skill of its bundle, and one function reads the required skills

## Overview

This Task delivers the whole fix of `_techspec.md` → Build Order 1 in one change, because each part breaks the tree without the next: the `typescript` module requires `solid`, catalog validation refuses a Skill Activation whose bundle names a skill its owner does not require, and restore, the update preview, `skills check` and Doctor read the required skills through one `Catalog` method. The derived records are regenerated by the repository's own commands, the Setup Manifest of this repository gets its Managed Refresh, and the glossary entry of **Skill Activation** states the rule. It is verifiable on its own through three new tests over the embedded catalog, a mutated copy of it and a repository profile without `frontend`, and through the existing restore, Doctor, update and `skills check` suites.

## Requirements

1. MUST add `func (catalog *Catalog) RequiredSkills(moduleIDs []string) ([]string, error)` and the type `UnknownModuleError` with its `Error` method to `internal/baseline/catalog.go`, as `_techspec.md` → Interfaces and API Contract 2 state: the sorted union of the given modules' `requiredSkills`, each name once, repeats in the input allowed, an empty list for no modules, and `*UnknownModuleError` naming the module and no list for a module the catalog does not hold.
2. MUST make `loadRestoreProfile` and `loadSkillSnapshotProfile` in `internal/baseline/skills_restore.go` and `resolveExternalSkillRequirement` in `internal/cli/doctor.go` take the required skills only from `Catalog.RequiredSkills` (invariant 4), so that neither file reads a module's `requiredSkills` by hand any more. Each caller keeps the message it prints today: restore reports `restore.assets-invalid` with "Embedded Baseline Profile %q references a missing module.", and Doctor reports "resolve external skill requirement: Setup Manifest names unknown module %q" and still removes the Roundfix-owned names after the call. The branch of `loadRestoreProfile` that reported an invalid module document goes away. No output line, message, code or exit of restore, the update, `skills check` or Doctor changes for a built-in profile.
3. MUST add to `validateSkillActivations` in `internal/baseline/catalog_validate.go` the rule of `_techspec.md` → API Contract 1 and ADR-0448: for an activation whose owner and bundle both exist, each skill of the bundle that neither the owner nor a module the owner reaches through `dependsOn` requires (cycles tolerated) is reported as `catalog.skill.activation.skill.unrequired`, with `Path` the activation identifier and `Info` the skill name, one diagnostic per skill, in activation order and then bundle order. An activation with an unknown owner or bundle reports only the existing `catalog.skill.activation.owner.unknown` or `catalog.skill.activation.bundle.unknown`. A module the owner does not depend on never satisfies the rule.
4. MUST add `"solid"` to the `requiredSkills` of `internal/baseline/assets/modules/typescript.json`, right after `"onioncry"`, and change no other field by hand (API Contract 3). Then run, in this order, the commands `_authorization.md` → Sanctioned regeneration declares: `go test ./internal/baseline -run '^TestEveryBaselineModuleVersionIsRecorded$' -record-module-versions -count=1`, `make baseline-digests`, and `go run -buildvcs=false ./cmd/roundfix baseline update --repo . --no-skills --no-history --yes --format text`. The module record command writes the module's version line, "the next version", never a number written by hand; no version line, digest, golden or manifest field is hand-edited. When another Spec changed a Baseline module first, these commands regenerate on the tree this Task runs on.
5. MUST NOT change `internal/baseline/assets/skill-activations.json`, the `frontend` module or any other Baseline module, template, profile, Source Baseline or Setup Snapshot under `internal/baseline/assets/`, any guide under `docs/agents/` other than the Managed Refresh of `docs/agents/setup-context.json`, any owned or Vendored Skill, any user-guide page, `docs/references/behavior-surfaces.json`, `docs/references/coverage-record.json`, any entry of `docs/references/skill-coverage.json` other than the one requirement 11 names, the Makefile, the CI workflows, `go.mod`, `go.sum`, `.roundfixrc.yml` or `skills-lock.json` (`_authorization.md` → Limits).
6. MUST add `TestAnActivationOwnerRequiresEverySkillOfItsBundle` in a new `internal/baseline/catalog_activation_requirement_test.go`, built on `cloneEmbeddedAssets`, `LoadCatalog` and `catalogDiagnosticByCode`, with these subtests, each named as written:
   - `the_embedded_catalog_loads`: `LoadEmbeddedCatalog` returns no error;
   - `a_sibling_module_does_not_satisfy_the_owner`: removes `solid` from the copied `typescript` module and expects exactly one `catalog.skill.activation.skill.unrequired` diagnostic, with path `trigger.production-code` and info `solid`, although the copied `frontend` module still requires `solid`;
   - `a_dependency_satisfies_the_owner`: removes `systematic-debugging` from the copied `core` module and expects the diagnostic with path `trigger.debugging` and info `systematic-debugging`, proving that before the removal the owner was satisfied through `core`;

   A mutated copy that changes a module keeps the copy's module version record consistent, or asserts only the diagnostics named here, so that the test fails on the rule and not on an unrelated digest.
7. MUST add, in the same new file, `TestTheRequiredSkillsCoverTheRenderedDispatch`, with these subtests, each named as written:
   - `every_module_with_its_dependencies`: for every module of the embedded catalog taken with every module it reaches through `dependsOn`, renders the guide with `renderSkillDispatch` and asserts each skill name it reads is in `Catalog.RequiredSkills` of the same modules;

   The test reads the skill names from the rendered text an Agent reads, as `_techspec.md` → Testing Approach describes: each backticked token after the colon of a line that begins with two spaces and a list marker followed by a backticked `bundle.` identifier, and the token of each line that is exactly a list marker and one backticked name followed by a colon. It never calls `profileNamedSkills`, so it stays an independent witness.

MUST add `TestARepositoryProfileWithoutFrontendRequiresSolid` to `internal/baseline/skills_snapshot_profile_test.go`, on a new helper `typescriptBackendProfileFixture` in that file: `InitCustomProfile` in a temporary repository from `standard-typescript-monorepo`, then the profile file's `modules` cut to `core`, `context-workflow`, `typescript`, `bun`, `autonomous-work`, `spec-workflow`, `secondbrain` and `repository-extension`. No other glossary entry changes.

MUST keep these existing tests unchanged and passing: `TestSkillSnapshotProfileKeepsEveryBuiltInProfile`, `TestSkillSnapshotProfileResolvesARepositoryProfile`, `TestEveryModuleRequiresEverySkillItDispatches`, the Doctor tests that inject `resolveExternal`, including the unknown-module case, and `TestBaselineUpdateSurfaceTranscriptThisRepositoryIsCurrent`, which passes only after the Managed Refresh.
