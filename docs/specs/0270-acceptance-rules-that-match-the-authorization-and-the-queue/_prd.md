# Acceptance rules that match the authorization and the queue

Two acceptance rules disagree with the authority and the queue a Spec runs
under, and each cost a cycle on 2026-10-13. Spec 0258's authorization said that
no QA row opens a network connection, so its QA recorded four outside-evidence
rows as `blocked (environment: network prohibited by Spec authorization)`. The
shared QA policy exempts only `blocked (environment: network denied: <host>)`,
so the Delivery Queue parked a partial with no finding and the operator needed
the QA Archive Override
([the first adopted Backlog Entry](references/2026-10-13-outside-evidence-blocked-by-the-spec-authorization-does-not-qualify.md)).
Spec 0264's QA held a file byte-identical to its bytes at the commit where the
plan was measured. Four Specs merged first and changed that file, and the QA
failed a row although the Spec's own diff left it unchanged
([the second adopted Backlog Entry](references/2026-10-13-a-byte-invariant-pinned-to-a-past-commit-fails-after-other-merges.md)).
Spec 0260 had failed its QA for the same reason a day earlier. This is a bug
fix with no new product surface: the minimal PRD carries the contract the
downstream skills parse. The maintainer decided on 2026-10-13 that an
outside-evidence row blocked because the Spec's own authorization forbids
network access counts toward a qualifying partial without the override, in one
canonical wording the QA skill writes, with settlement and archive sharing the
policy.

## Prerequisites

None that the queue must enforce. The operator delivers cycle AG in the order
B, A, C, D, E, F, so this Spec (E) is rebased after Specs 0266, 0267, 0268 and
0269 merge. Those Specs may also change the owned skill version record, the
corpus golden, `docs/references/behavior-surfaces.json` or Baseline derived
files. After the rebase the Tasks rerun their record and regeneration commands
rather than merging generated bytes by hand. No Verification of this Spec reads
another Spec's artifacts, and no design depends on another AG Spec's code.

## Goals

- A QA partial whose only unmet outside-evidence rows were kept offline by the
  Spec's own authorization settles, archives and passes `qa-report accept`
  without the QA Archive Override, and the Delivery Queue does not park it.
- The QA skill writes that row in one exact wording, and every guide and skill
  that lists the exempt rows names it.
- A QA requirement that holds a file byte-identical names the Delivery Base,
  and `roundfix spec check --strict` refuses one that pins a commit.

## User Stories

1. As the operator, I want a partial with no finding, blocked only because the
   Spec's own authorization keeps a source offline, to settle and archive
   without an override, so that a correct Spec is not parked.
2. As a QA agent, I want one exact wording for an outside-evidence row the
   authorization forbids me to look up, so that the report I write qualifies
   when it should and a paraphrase does not.
3. As a Spec author, I want `spec check` to tell me when a QA requirement pins
   bytes to a commit, so that my plan does not fail after other Specs merge
   first.
4. As an adopter, I want the Baseline guides and the user guide to state both
   rules, so that my repository's QA follows them without reading the code.

## Core Features

1. **Network-Prohibited Row.** The shared QA policy treats a Results row whose
   status is exactly `blocked (environment: network prohibited by Spec authorization)`
   and whose provenance names the outside-evidence row like a Network-Denied
   Row. It never decides a qualifying partial, needs no Unreachable Acceptance
   declaration, and is not an environment row that needs the override. Any
   other status or provenance still refuses (ADR-0276).
2. **One wording in the QA skill.** `qa-gate` writes that status only when the
   Spec's own `_authorization.md` forbids network access, names the
   authorization text in the report, and still checks offline any source it
   can. `qa-gate`, `archive-spec` and `roundfix` extend the QA settlement
   table under a new heading, and the roundfix archive and settle references
   describe the shared policy (ADR-0276).
3. **Pinned Byte Invariant.** `roundfix spec check` reports
   `SC-QA-BYTES-PINNED`, a gap, for each requirement of a pending QA Task that
   names a byte-identity phrase and a commit-shaped hexadecimal token
   together. `write-tasks` says to compare with the Delivery Base (ADR-0276).
4. **Guides and glossary.** The two Baseline clauses that list the exempt
   outside-evidence row gain the new row, the user guide pages that list it
   and the spec check codes follow, and the glossary gains the two terms and
   the Delivery Base sentence.

## Non-Goals / Out of Scope

- Reading `_authorization.md` to confirm that it forbids the network, or
  adding a network field to authorization records.
- Changing the text of the `### QA settlement` section of any skill.
- Removing the authoring rule that an outside-evidence row never rests on a
  lookup the authorization forbids.
- Rewriting archived Specs, Archive Records or reports, including those of
  Specs 0258 and 0264.
- Checking byte invariants in non-QA Tasks, Verification commands or other
  artifacts, or judging whether a named commit is old.
- Another Spec's folder, the Makefile, CI workflows or any dependency.

## Adopter notes

The release notes tell adopters:

- A QA report may record an outside-evidence row as
  `blocked (environment: network prohibited by Spec authorization)` when the
  Spec's authorization forbids network access. Such a row, with the
  outside-evidence row named in its provenance, now qualifies a partial like a
  network-denied row. The Baseline update brings the sentence into
  `docs/agents/spec-routing.md` and `docs/agents/autonomous-work.md`.
- `roundfix spec check --strict` now reports `SC-QA-BYTES-PINNED` on every
  active Spec. Before an active Spec's next Run, rewrite each QA requirement
  it names to compare with the delivery base, the merge base of the audited
  head with the default branch, and move the measured commit out of the
  requirement.

## Decisions

- The new exempt row has its own exact status and joins the one policy in
  `internal/spec`; see ADR-0276.
- The byte-invariant check is a structural gap on pending QA requirements of
  every active Spec; see ADR-0276.
- The QA settlement table keeps its bytes; the extension has its own heading.

  wording returned nothing above the score floor.

  quoted above. Both define a change as the difference from the merge base,
  which supports comparing a byte invariant with the Delivery Base. A search
  for a published source on authorization-prohibited evidence found nothing
  applicable; that rule rests on the maintainer's decision and on the 0258
  report.
- Repository history: a scan of the QA Tasks of the 235 archived Specs at
  their source revisions found five QA requirements in Specs 0193, 0247, 0248
