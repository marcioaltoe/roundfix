-# The Delivery Queue gate runs the changed Go packages in a Linux Lane
-
-The Daemon's repository Verification runs on the maintainer's macOS machine,
-so a defect that exists only on Linux reaches GitHub Actions first. On
-2026-10-17 Spec 0276's fresh item binary copy failed only in CI on Linux with
-`fork/exec <copy>: text file busy` (pull request #568). The test that proves
-the fix, `internal/cli/deliver_item_binary_fork_linux_test.go`, carries
-`//go:build linux`, so no Run on the maintainer's machine ever compiles it. The
-operator proved the fix by hand in a `golang:1.26` container: a copy of the
-tree, a fresh `git init`, and `go test` of the package, passing with the fix and
-failing with it reverted.
-
-## Decision
-
-**The Delivery Queue's repository gate runs a Linux Lane when Project Config
-opts in.** With `delivery.linux_lane: true`, after the repository Verification
-passes, the gate runs `go test -count=1` over the candidate's changed Go
-packages in a `golang:<go.mod go version>` container, once per gate, before the
-candidate is pushed. The changed packages come from the candidate's diff
-against its merge base with the refreshed default branch: each changed path
-maps to the nearest directory at the candidate head, from its own directory
-upward, that holds a `.go` file, and a change to `go.mod` or `go.sum` selects
-`./...`.
-
-The container is bounded:
-
-- The image is used only when it is already present locally: the lane checks
-  `docker image inspect` and runs with `--pull never`. It never pulls.
-- `--network none`, `--rm`, and `--user 65534:65534`. Module sources come from
-  the host module cache, mounted read-only, with `GOFLAGS=-mod=readonly`,
-  `GOPROXY=off` and `GOTOOLCHAIN=local`.
-- The tree arrives as `git archive` of the candidate head on standard input and
-  is unpacked inside the container, so nothing is written into the checkout.
-- The container receives only the variables `go test` needs: `HOME`, `GOCACHE`,
-  `GOMODCACHE`, `GOFLAGS`, `GOPROXY`, `GOTOOLCHAIN` and `GOSUMDB`. The docker
-  CLI itself keeps the Queue Owner's environment, so its context and socket
-  resolve as the operator's do.
-- A 20-minute cap and any cancellation remove the container with
-  `docker rm -f`.
-
-When the lane cannot run, it skips with a named reason on the Queue Owner's
-console log and the gate continues: no `go.mod`, no `go` version in it, no
-changed Go package, `go` or `docker` not on `PATH`, `docker info` failing, the
-image absent, or `docker run` exiting `125`. Docker documents that exit code
-`125` "indicates that the error is with Docker daemon itself"
-(https://docs.docker.com/engine/containers/run/), so it is the machine's
-failure, not the candidate's. Any other non-zero exit, and the cap, fail the
-gate and park the item `gate-failed` with the log path.
-
-## Considered Options
-
-- Running the lane at every Task settlement was rejected by cost. Measured on
-  2026-10-18 on the maintainer's machine, compiling the `internal/cli` and
-  `internal/worktree` test binaries for Linux from an empty build cache took
-  12.9 s, and `go test` of those two packages on the host took 156.9 s. Most
-  Specs change `internal/cli`, so a Spec of four Tasks with retries would add
-  ten minutes or more, against one run of about three minutes per candidate.
-- A repository contract test that shells out to `docker` was rejected. A new
-  Repository Contract Test needs a Makefile list entry, which the cycle's grant
-  excludes, and a test that skips on a machine without Docker would make a
-  Verification depend on the host.
-- Pulling a missing image was rejected. A pull is a network fetch inside a gate
-  the operator did not ask for; the operator pulls the image once.
-- Mounting the checkout into the container was rejected. A Run Worktree's `.git`
-  is a file pointing outside the mount, tests need a repository, and a writable
-  mount would let the container write into the checkout.
-- Turning the lane on for every Go repository was rejected. It would start
-  containers on adopters' machines without their choice.
-
-## Consequences
-
-- A candidate whose changed packages fail on Linux parks before any Pull
-  Request exists, and its log is under
-  `<artifact dir>/delivery/<slug>/linux-lane.log`.
-- On a machine without the image, every gate logs one skip line. The image
-  `golang:1.26` was not present on the maintainer's machine on 2026-10-18.
-- The lane tests only the changed packages, so a Linux-only defect in an
-  unchanged package that a change breaks indirectly still reaches CI.
-- The Delivery Queue reads `delivery.linux_lane` from the fetched default
-  branch, so enabling it takes effect after the change that enables it merges.

-# The Linux Lane runs like CI
-
-The first Linux Lane run that executed, on Spec 0280's candidate on
-2026-10-18, parked the item `gate-failed` on two environment gaps while every
-changed package passed. `TestGuidanceCompositionJourney/rust-cli` failed
-because the `golang:1.26` image has no `rustfmt`, and
-`TestCLITestHelpersEndWithTheirTestBinary` timed out after 594 s because a
-helper orphaned inside the container was never reaped. The maintainer turned
-the lane off the same day. On 2026-10-19 the maintainer chose "--init +
-imagem configurável + skip com motivo (Recomendado)".
-
-## Decision
-
-**The lane runs under an init.** `docker run` gains `--init`, so
-`docker-init`, which Docker documents as backed by tini, is PID 1 and reaps
-every orphan. Without it, PID 1 is `go test`, which waits only for its own
-children, and an orphan that has exited stays a zombie that `kill(pid, 0)`
-still finds.
-
-**The image is configurable.** `delivery.linux_lane_image` names the image.
-It is read from the same fetched default-branch Project Config as
-`delivery.linux_lane`, with User Config beneath it. Empty, the default, keeps
-`golang:<go.mod go version>`. A value must be a container image reference
-(`name[:tag][@digest]`, the grammar of the distribution reference library), so
-it can never start with `-` or carry a space. The lane still never pulls: a
-configured image that is not present locally is skipped like the default one.
-
-**A test that needs an External Test Tool skips naming it.** A tool outside
-the repository's Base Test Tools (`go`, `gofmt`, `git`, `make` and the POSIX
-utilities the tests run) is resolved through `testfixture.RequireTool`, which
-skips the test with `requires <tool>, which is not on PATH` when the tool is
-absent, on any machine and in any container. A repository rule in
-`internal/testfixture` refuses a test that resolves such a tool by a literal
-name in any other way.
-
-**A container failure is told apart from a change failure.** The lane script
-checks for `tar`, `git` and `go`, unpacks the candidate and records it before
-`go test` starts, and any failure there exits `3` with a
-`roundfix-linux-lane: container: <cause>` line. Measured on 2026-10-19 in
-`golang:1.26`, `go test` exited `1` for a failing test, a build failure and a
-panic, and the go command keeps `2` for its own usage errors, so these
-outcomes do not overlap:
-
-- **Lane Container Failure**: exit `3`, `126` or `127`, an exit of `128` or
-  more (the container process ended by a signal), or the 20-minute cap. The
-  item parks `linux-lane-container: <cause>; see <lane log>` in the
-  `environment` Park Class.
-- **Lane Change Failure**: any other non-zero exit. The item parks
-  `gate-failed: Linux Lane change failure: go test exited <n>; see <lane log>`
-  in the `finding` Park Class.
-
-The lane log ends with the outcome's line. The skips ADR-0288 defined, an
-absent image and `docker run` exiting `125` among them, stay skips.
-
-**The lane runs on demand.** `roundfix deliver lane [--all] [<revision>]` runs
-the same lane against a revision of the current checkout, `HEAD` by default,
-without a queue or a Spec and whatever `delivery.linux_lane` says. It reads
-the image from the checkout's Project Config, selects the changed packages as

-# The Linux Lane reads the repository history read-only
-
-On 2026-10-19 the on-demand Linux Lane run on `main` failed two tests that
-read historical commits by object name, because the lane records the
-candidate in a fresh repository that holds no history, while CI checks out
-with `fetch-depth: 0`. The lane now mounts the repository's object store
-read-only and registers it as an alternate of the container repository, so a
-historical object is reachable as in CI; a store it cannot mount whole skips
-the lane with its reason.
-
-## Decision
-
-**The object store is mounted read-only.** The lane resolves, on the host,
-the object store Git reads in the lane's working directory, `git rev-parse

-worktree this is the common directory's `objects`. `docker run` gains `-v
-<objects>:/repo-objects:ro` after the module cache mount. Only the object
-store is mounted: never the working tree, never refs, and never writable.
-
-**The container repository borrows from it.** The lane script checks that
-`/repo-objects` is a readable directory, exiting `3` with `cannot read the
-repository history at /repo-objects` otherwise, and writes `/repo-objects`
-into `.git/objects/info/alternates` right after `git init`. The candidate is
-still recorded as one fresh commit; objects that commit adds are written into
-the container's own repository.
-

-
-- a store path holding a colon, outside a Windows volume name, cannot be
-  expressed in `-v`, and skips with `the object store <objects> cannot be

-- a store path that is not a directory skips with `the object store <objects>
-  cannot be mounted: it is not a directory`, so Docker never creates a host
-  directory for a missing source;
-- a store whose `info/alternates` holds an entry (a line that is neither blank
-  nor a `#` comment) skips with `the object store <objects> borrows objects
-  through info/alternates, which the Linux Lane does not mount`.
-
-Refs are not made available. The 2026-10-19 run failed only the two tests
-that read objects by name, and every other package passed without history.
-

-

-  alternate object path` from every Git call and still failed the test.
-  Mounting each store at its own host path made the probe pass, but a host
-  path then becomes a container path that can shadow `/tmp`, `/go` or the
-  image's tools, a relative entry resolves against `/repo-objects` instead of
-  its host store, and a Windows path is not a container path. Roundfix's own
-  worktrees never create alternates; a clone made with `--shared` or
-  `--reference` does, and `git repack -a` followed by removing
-  `objects/info/alternates` makes it self-contained.
-- Running without history when the store cannot be mounted was rejected: the
-  history tests would fail as a Lane Change Failure, which is the defect this
-  record fixes.
-- Mounting the checkout or its `.git` was rejected for the reasons ADR-0288
-  gives: a worktree's `.git` is a file pointing outside the mount, and refs,
-  the index and hooks are not the candidate's to read or change.

-- A test reads any object the repository holds, including other branches',

-# The Linux Lane names a failed go list apart from go test
-
-The lane script selects the candidate's packages with `go list` before it
-runs `go test`, but a failed `go list` ends the script with its own exit code,
-so the lane reports `go test exited <n>` for a test run that never started.
-Quaestor reported it on 2026-10-21 from a review of the Roundfix `deliver`
-reference. The lane script now marks a failed `go list` with its exit code and
-a reserved exit, and the outcome names `go list`; its Park Class follows what
-can make it fail.
-
-## Decision
-
-**A failed `go list` has its own exit and line.** In the lane script, a
-non-zero exit of the package-selection `go list` prints
-`roundfix-linux-lane: go list: exited <n>` and exits `4`. No other step of the
-script exits `4`, and `go test`, which the script runs last with `exec`,
-exits `1` for failing tests, build failures and panics and `2` for its usage
-errors (ADR-0294's measurement), so the exit code decides that `go list`
-failed and the line carries its code.
-
-**Its Park Class follows the cause.** Measured on 2026-10-22 with the lane's
-environment (`GOFLAGS=-mod=readonly`, `GOPROXY=off`, `GOTOOLCHAIN=local`,
-`GOSUMDB=off`, an empty module cache), `go list -e` exited `1` for a `go.mod`
-that does not parse, for a `go` directive above the running toolchain and for
-a `go.work` that names a missing module, and exited `0` for a requirement
-absent from the module cache, an import of an unknown module and a Go syntax
-error, which `go test` then reports. The Go documentation of `go list` says
-that with `-e` "the list command never prints errors to standard error and
-instead processes the erroneous packages with the usual printing". A
-non-zero `go list -e` exit is therefore a property of the candidate's module
-files against the image's toolchain:
-
-- **Lane Change Failure** for an exit `<n>` from `1` to `127`: the cause is
-  `go list exited <n>`, the item parks `gate-failed: Linux Lane change
-  failure: go list exited <n>; see <lane log>` in the `finding` Park Class,
-  and `roundfix deliver lane` exits `1`.
-- **Lane Container Failure** for `<n>` of `128` or more, a `go list` ended by
-  a signal, as ADR-0294 classifies a container process ended by one: the cause
-  is `go list exited <n>: the process ended by signal <n-128>`, the item parks
-  `linux-lane-container` in the `environment` Park Class, and `roundfix
-  deliver lane` exits `3`.
-- An exit `4` without a well-formed line, which only a lane script that lost
-  its line produces, is a Lane Change Failure with the cause `the lane script
-  exited 4 without reporting the go list exit code`.
-
-The last output line that starts with `roundfix-linux-lane: go list: exited `
-and ends in decimal digits names `<n>`; a line that only contains the prefix is
-ignored, as for the setup marker.
-
-**Every other outcome keeps its bytes.** Exit `3`, `126`, `127`, `128` or
-more, the cap, exit `125` and every other non-zero exit keep ADR-0294's

-

-
-- Exiting with `go list`'s own code and only printing a line was rejected: the
-  exit code would no longer tell which step failed, and a test's output after
-  `go test` started could carry a line that looks like the marker.
-- Reusing exit `3` with a second marker was rejected: ADR-0294 makes exit `3`
-  the script's container setup, a Lane Container Failure, and the class must
-  not depend on which line a test printed.

-  rejected: every measured failure came from the candidate's `go.mod`,

-  a contract of the go command, and the classification stays structural.
-
-## Consequences
-
-- An exit `4` that the lane classified as `go test exited 4` before is now a
-  `go list` failure; `go test` never exits `4`, so no `go test` outcome
-  changes.
-- A module the read-only cache lacks still fails as `go test exited 1`, as
-  before, because `go list -e` does not fail for it.
-- Lane logs written before keep their bytes; only new runs carry the line.
-

+# Roundfix verifies on macOS, and the Delivery Queue has no Linux Lane
+
+Supersedes ADR-0288, ADR-0294, ADR-0297, ADR-0303 and ADR-0316 (2026-11-24); all are retired, and Git keeps their text. Their creation dates are respectively 2026-10-18, 2026-10-19, 2026-10-20, 2026-10-20, 2026-10-22.

+
+The maintainer retired Linux verification because Roundfix is used on macOS and the container gate had repeatedly blocked delivery. Continuous integration retains verification before merge.
+
+## Decision
+
+The Delivery Queue repository gate takes one Machine Verification Capacity unit, computes the Verification Core Budget once and supplies it to the repository Verification, releases the unit afterwards, and passes when that Verification passes. A failure parks the item as before. The gate neither reads default-branch configuration for a lane nor resolves Docker, writes a lane log, adds a warning, or adds a pull request paragraph; the engine advances to publishing and preserves existing warnings.
+
+`roundfix deliver lane` is no longer a command: without help it is refused as an unknown command on standard error with exit 2, and with help it prints deliver usage and exits 0. Deliver usage lists plan, start, status, resume, retry and stop.
+
+The keys `delivery.linux_lane` and `delivery.linux_lane_image` are deprecated and ignored, whatever their value. They are removed before validation, each produces its deprecation warning once per load in that order, and a key present in both User and Project Config warns once. The warning is `config: <key> is deprecated and ignored; the Linux Lane was retired, so remove it`. A delivery mapping with only those keys is empty; a configuration read at a commit removes them silently. Other unknown delivery keys remain errors. Doctor no longer runs or reports the lane check or its diagnostic codes; it prints none of `DR-LANE-IMAGE-UNKNOWN`, `DR-LANE-DOCKER-MISSING`, `DR-LANE-DOCKER-UNREACHABLE` and `DR-LANE-IMAGE-MISSING`. Its `verification-cores` line is followed by `codex`, and its other checks retain their order and text.
+
+A stored `linux-lane-container:` blocker keeps its environment Park Class and directs the operator to `roundfix deliver retry <slug>` because the lane was retired. A stored `gate-failed: Linux Lane change failure:` blocker remains a finding with the normal gate-failed action. The retry counts against the item retry limit. Status prints a stored `linux-lane-skipped:` warning unchanged; no new code reads, writes or removes that segment. Low-disk warning updates preserve the other segments and place the low-disk segment last. Existing lane logs are neither read nor deleted.
+
+The CI Verification gate runs its existing steps on `macos-26`. Release verification and the Full Contract Run execute in a `macos-26` job with read-only contents permission, full-history checkout and no persisted credentials; the unchanged publication job needs that job to succeed. The verification job uses the existing Go setup and the existing Verify gate and Verify every contract steps for both tag pushes and manual dispatches. The publication job retains its runner, permissions, environment and step order, including checkout, Go and Node setup, runtime guard, tag validation, preflight, cross-compilation, package comparison, publication and GitHub Release. +## Considered options
+
+A light Linux build-and-vet job was rejected because the maintainer chose to retire Linux verification. No CI tests was rejected because the maintainer wanted a check before merge. Running the whole release on macOS was rejected to preserve the proven publication job and its permissions. Three release jobs validating the tag first were rejected in favor of the bounded two-job change; the trade-off is that a bad tag is refused after verification. The moving `macos-latest` label was rejected so an image change is reviewed; a larger runner was rejected without a measurement. Classifying a stored blocker as `unclassified` was rejected because its generic action would tell the operator to repair a retired gate.
+
+## Consequences
+
+macOS runs the tests; Linux and Windows builds and tests are compiled but not executed. Existing parked items remain actionable through Delivery Retry, and existing warning text remains readable.
