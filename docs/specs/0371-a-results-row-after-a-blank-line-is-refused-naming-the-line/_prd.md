# A Results row after a blank line is refused, naming the line

A QA Report whose `## Results` table holds a blank line between its rows loses every row after that line without a word: Roundfix 0.137.7 reads a table only down to its first blank line, so Pantheon's report, whose QA Agent wrote its rows after a blank line below the rows the Daemon seeded, was refused with `rows_blocked_environment is 1; expected 0`, and the mechanical stage asked to set the blocked counts to the rows it had read. Both named the wrong cause. After this Spec one reader decides which lines are Results rows, and every reader takes them from it. A table line that no table header leads is never skipped: `roundfix qa-report accept`, the Settle Command, `roundfix archive` and the Daemon's QA settlement refuse the report with its path, the row's line and the blank line to remove, the mechanical stage reports the same line, and the Daemon gives the gate one repair turn. The Daemon's prompt and the qa-gate skill tell the gate to continue the seeded table with no blank line and the same three columns.

## Goals

- No row under `## Results` of a QA Report is ignored in silence: each reader
  counts it, or refuses naming the report path and the row's exact line.
- The refusal names the real cause and its repair, the blank line to remove,
  instead of a blocked count.
- Every reader of Results rows reads them through one function, so the
  eligibility decision and the mechanical stage can no longer disagree about
  which rows a report holds.
- The gate is told to continue the seeded table, and a gate that still breaks
  it repairs the report in one returned turn instead of losing the Run.

## User Stories

1. As a maintainer whose QA gate wrote rows after a blank line, I want the
   refusal to name the blank line to remove, so that I fix the report instead
   of overriding QA.
2. As the QA Agent completing a seeded report, I want the prompt and the skill
   to say where my rows go, so that I do not start a second, headerless table.
3. As an adopter whose archived and current reports carry a second `Status`
   table or one under a deeper heading, I want them read exactly as before, so
   that this fix refuses nothing it used to count.

## Core Features

1. `spec.ReadQAResults`, the one reader of the Results section: its tables,
   the rows of every table with a `Status` column, and the first table line no
   header leads, with the refusal text naming path, line and repair.
2. The eligibility decision refuses such a report first, so `qa-report
   accept`, the Settle Command, `roundfix archive` and the Daemon's settlement
   name the real cause; the environment-row count needing the QA Archive
   Override and the Borrowed Evidence exemption read the shared rows.
3. The mechanical stage reads the same rows, reports the break as one
   report-shape finding at the row's line, and reconciles no count against a
   table it could not read whole.
4. The Daemon's prompt for the seeded report says where rows go; one repair
   turn returns a report with a row outside every table; the Daemon's count of
   the rows it seeds reads the same reader.
5. Documentation: the qa-gate skill, the qa-report, settle and implement
   guides, the context-driven development guide, the Roundfix settle and
   implement references, and `CONTEXT.md`.

## User Experience

On the reduced Pantheon shape, `roundfix qa-report accept` exits `1` with
`roundfix: QA Report eligibility refused: QA Report <path>: Results row at line 16 is outside the Results table that starts at line 12; remove the blank line at <path>:15 so the row continues the table`;
after the blank line is removed the same report is accepted. In a Run, the
gate first gets one repair turn naming the same line; a report still broken
settles the QA Task `failed` with that text. A report without a break sees no
new output.

  (https://github.github.io/gfm/, read through Exa on 2026-11-10): "The table
  is broken at the first empty line, or beginning of another block-level
  structure". A row after a blank line is therefore not a row of the table
  above it in any GFM renderer.
