# Task 02: Every Baseline plan makes CLAUDE.md the link to AGENTS.md when nothing is lost, and the guide says so

## Overview

Adoption writes `CLAUDE.md` as a symbolic link to `AGENTS.md`, and a managed refresh does so when the file holds nothing of its own. Otherwise the plan warns and leaves the file. The file transaction replaces a regular file or a link at that one path and restores it on rollback. The `agent-instructions.md` guide template states the rule, the derived Baseline files are regenerated by their commands, and this repository's managed guide is refreshed with the sanctioned `baseline update`. ADR-0100 records the amendment.

## Requirements

1. MUST implement `_techspec.md` → invariants 5 to 8 and API Contracts 1 and 2 in `internal/baseline`:
   - `assemblePostimages` in `plan.go` reads the shape with `ReadClaudeInstructionLink`, through the plan's Git runner;
   - it adds the link postimage `{Path: "CLAUDE.md", Kind: "symlink", Mode: 0, Content: "AGENTS.md"}` with no content identity, and one managed entry `root.claude-instruction-link` of kind `link`, as invariant 5 decides;
   - in a managed refresh that replaces a regular file it also writes the root backup `CLAUDE.<digest>.md` through the backup path adoption uses, with its `backup:CLAUDE.md` entry, and `expectedRootBackups` in `apply.go` accepts it;
   - otherwise it adds the warning of invariant 6, with the code and message of API Contract 2 word for word, to the plan's warnings;
   - `validateManagedRefreshPreservation` accepts the link postimage at `CLAUDE.md` only when the reader, run on the preimage, finds the file convertible, and keeps refusing every other change outside Managed Regions;
   - `preimageMatchesPostimage` in `apply.go` matches a link postimage against a link preimage with the same target.

A rollback removes the link only when it is still the planned one, then restores the regular bytes and mode, or the previous link's target. Every other path keeps refusing a link postimage over an existing preimage.
