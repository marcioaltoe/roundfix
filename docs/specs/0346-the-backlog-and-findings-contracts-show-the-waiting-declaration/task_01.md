# Task 01: The Backlog and Findings contracts show the Waiting Declaration commented

## Overview

The Baseline's copyable Backlog and Findings Operational Contracts gain the
two commented keys of a Waiting Declaration and one sentence each; the
`context-workflow` module records its next version, the derived Baseline
files and this repository's managed guide are regenerated by their
commands, and the user guide, the glossary and the coverage records follow.
This answers the adopted Backlog Entry of 2026-11-03, "The Backlog and
Findings contracts name the Waiting Declaration"
([references](references/2026-11-03-the-backlog-and-findings-contracts-name-the-waiting-declaration.md)),
whose Shape section asks for exactly this.

## Requirements

1. MUST change the `guidance` of
   `clause.context.backlog-01-operational-contract` and
   `clause.context.findings-01-frontmatter`
   (`internal/baseline/assets/modules/context-workflow.json`) exactly as
   `_techspec.md` → API Contracts 1 and 2 give, keeping every other byte of
   both clauses, and raise the `version` of `rule.context.docs-layout` by one
   over the value the tree holds. Both clauses keep their `id`,
   `enforcement` and the absence of `replaces`; nothing else in the module is
   edited by hand.
2. MUST add `internal/baseline/waiting_declaration_clause_test.go` with
   `TestTheOperationalContractsShowTheWaitingDeclarationCommented` and
   `TestAnAdopterKeepsTheWaitingContractClauses`, each calling `t.Parallel()`
   first, as `_techspec.md` → Interfaces and Testing Approach describe:
   - per clause, the sentence occurs once and the copyable frontmatter (the
     lines between the first fenced `---` pair) ends with the two commented
     lines;
   - per clause, that frontmatter decodes with `gopkg.in/yaml.v3` without a
     `waiting_on` or `since` key, and with both keys once the two lines are
     replaced by `waiting_on: ERP vendor support answer` and
     `since: 2026-10-25`;
   - the Standard TypeScript formatter golden and this repository's
     `docs/agents/docs-layout.md` each carry each commented line twice, on
     its own line, and each sentence once on whitespace-normalized text;
   - a transition from Source Baseline
     `baseline.standard-typescript-monorepo-0.0.1` over the Standard
     TypeScript profile records each clause once, disposition `retained`,
     enforcement `mandatory`, targets equal to its own identity.
   No existing test changes its bytes.
3. MUST then run, in this order, and hand-edit none of their outputs:
   - `go test ./internal/baseline -run '^TestEveryBaselineModuleVersionIsRecorded$' -record-module-versions -count=1`,
     which writes the module's next version and records it in
     `internal/baseline/module-versions.json`;
   - `make baseline-digests`, which rewrites the derived files this Task
     declares (the Standard TypeScript docs layout golden, the Standard
     TypeScript profile, the three catalog files and the four plan
     characterization goldens);
   - `go run -buildvcs=false ./cmd/roundfix baseline update --repo . --no-skills --no-history --yes --format text`,
     the Managed Refresh of this repository, which rewrites
     `docs/agents/docs-layout.md` and `docs/agents/setup-context.json`, then
     the same command again, which must report `File changes: 0`. Run both
     with `HOME` set to a temporary directory that is removed afterwards and
     `GOMODCACHE` and `GOCACHE` kept at their `go env` values.
   A file the commands change that this Task does not declare is a
   stop-and-report condition.
4. MUST update `docs/user-guide/context-driven-development.md`: the fenced
   block between `baseline-findings-template:start` and `:end` gains the two
   commented lines after `updated_at: YYYY-MM-DD`, so it equals the
   generated Findings fence, and after the paragraph that follows the block
   (the one ending "keep `created_at` unchanged.") add one paragraph that
   starts "The two commented keys are a Waiting Declaration." and says that
   a `pending` or `partial` Finding, or an `open` Backlog Entry, that waits
   on someone or something outside the repository may uncomment them, with a
   link to the Waiting Items section of the follow-up command guide.
5. MUST revise the **Waiting Declaration** entry of `CONTEXT.md` through
   `domain-modeling`: keep its definition and append, before its ADR link,
   "; the copyable Operational Contract blocks the Baseline writes for
   backlog and findings show the pair as commented keys". Write no new
   capitalized phrase: the glossary phrase check rejects an undefined
   capitalized run such as "Findings Operational Contracts". No other glossary entry changes.
6. MUST record the Coverage Review of the surface
   `guide docs/user-guide/context-driven-development.md` in
   `docs/references/skill-coverage.json`: replace that surface's `review`
   value with one starting `2026-11-04 — Spec 0346 task_01` that says the
   guide's Findings template gains the two commented keys and one paragraph
   and that its covering skills need no text change, as the PRD's `## Skills`
   entry states. No other surface changes.
7. MUST re-record the Behavior Surface Record with
   `go test -count=1 -tags docscontract ./internal/docscontract -run '^TestTheSkillCoverageMapIsCurrent$' -record-skill-coverage`
   as the Task's LAST step, after the last edit of the user guide and of
   `CONTEXT.md`.
8. MUST NOT change the Source Baseline corpus, manifest, accounting or
   index, `internal/baseline/assets/retention/**`, any other module, profile
