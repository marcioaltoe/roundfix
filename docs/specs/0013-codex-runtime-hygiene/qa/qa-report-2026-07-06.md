# QA Report — Codex Runtime Hygiene

## Summary

QA exercised the completed spec against the built `roundfix` binary on a Darwin
host, plus the focused Go tests for the shared health checks, Doctor command,
codex hygiene inspector, and codex-acp spawn path. The static gate passed and
the real Doctor flow detected this host's Gatekeeper-rejected codex with the
required reinstall next action. The verdict is `fail` because Doctor ignores a
configured `CODEX_PATH` during its codex hygiene check, while the PRD and the
new docs say the check covers a configured codex path before `PATH`.

## Failures and blocked items

### Failure: Doctor ignores configured `CODEX_PATH`

Expected: Doctor's codex hygiene check covers the configured codex path before
the `PATH` entry, matching the PRD's "PATH and any configured codex path"
contract and the docs added in task 05.

Actual: this command:

```bash
rtk /usr/bin/env CODEX_PATH=/tmp/roundfix-qa-nonexistent-codex ./bin/roundfix doctor
```

exited 1 but still inspected `/Users/marcio/.local/bin/codex`, the `PATH`
codex:

```text
codex: failed (/Users/marcio/.local/bin/codex is not accepted by Gatekeeper; next: reinstall codex with the official curl installer into ~/.local/bin, then set CODEX_PATH to that binary)
```

Code inspection matches the observed behavior:
`internal/cli/health.go` constructs `codex.Inspector{}` without passing a
configured path, while `internal/agent/codex_spawn.go` handles `CODEX_PATH`
only for the codex-acp spawn path.

Impact: a developer can follow Doctor's remediation and set `CODEX_PATH` to a
clean codex, but Doctor can still report on the old `PATH` codex. That leaves
the diagnosis inconsistent with the stated repair path.

Blocked items: none.
