# Task 02: The queue merges an archived item's derived-record conflict and refuses it without the sanction

## Overview

This Task reproduces, through the queue's own conflict recovery, the park of
Spec 0329's item on 2026-10-27, recorded in the adopted Backlog Entry
[the queue cannot regenerate the coverage record of an archived Spec](references/2026-10-27-the-queue-cannot-regenerate-the-coverage-record-of-an-archived-spec.md).
The fixture is an archived item whose Pull Request conflicts with the default
branch only in the coverage record. `ResolveConflict` runs the real
`.roundfixrc.yml` regeneration under the real suite guard. With task_01's
fix it commits the derived merge. When the item's Archive Record does not
list the command, the guard still refuses the write and the item is left
exactly as it was. The Task then re-records the coverage record, because it
adds two top-level tests.

## Requirements

1. MUST create `internal/cli/deliver_derived_archived_item_test.go` with a
   fixture helper as `_techspec.md` → API Contract 4 states.
   - Copy the repository in-process (`os.ReadFile` and `os.WriteFile`, never
     a child process), so the Go test cache records every copied input. The
     root is found by walking up to `.roundfixrc.yml`.
   - Skip `.git`, `.gocache`, `bin`, `docs/` and `.agents/`, then copy
     `docs/references/coverage-record.json` alone. The fixture reads none of
     the documentation trees that the repository keeps for docscontract files,
     and no record or authorization other than the fixture's own can
     sanction a write.
   - Build the history:
     - base: a commit that adds `docs/specs/0001-the-archived-item/_prd.md`,
       pushed to a local bare `origin`, with `refs/remotes/origin/HEAD` set;
     - item branch: a commit that replaces one coverage record entry with
       `TestItemSideEntry`, then an archive commit that removes
       `docs/specs/0001-the-archived-item/` and adds
       `docs/history/specs/0001-the-archived-item.md`
       (`schema: roundfix/archive-record/v1`);
     - default branch: a commit that replaces the same entry with
       `TestDefaultSideEntry`, pushed.
   - Build the workflow like the existing real-Git conflict fixtures
     (`preflight.ExecGitRunner`, `roundconfig.Builtin()`, with the artifact
     directory and home under `t.TempDir()`). Do not set `HOME`, `GOCACHE`
     or `GOMODCACHE` for the nested `go`.
2. MUST add `TestAnArchivedItemsDerivedRecordConflictIsMergedAndRegenerated`.
   The record's `regeneration` lists the coverage command with the output
   `docs/references/coverage-record.json`. Assert API Contract 5:
   - a new `Head`, no `SourcePaths`, and `Regenerated` equal to the
     `.roundfixrc.yml` coverage command;
   - a committed record that contains the replaced original entry and
     neither `TestItemSideEntry` nor `TestDefaultSideEntry`, with no conflict
     marker;
   - parents equal to the item head and `origin/main`;
   - the `Roundfix-Delivery: derived-merge` trailer;
   - a clean worktree.
3. MUST add `TestAnArchivedItemWithoutTheSanctionKeepsItsDerivedRecordConflict`.
   The record's `regeneration` lists only `make baseline-digests`, so a
   declaration exists but does not sanction the coverage record. Assert API
   Contract 6:
   - an error containing `regenerate derived paths`;
   - HEAD at the item head, a clean worktree, and no `MERGE_HEAD`;
   - one `derived-regeneration-*.log` under the artifact directory's
     `delivery/<slug>/` that contains
     `suiteguard: modified: docs/references/coverage-record.json`.
4. Both tests MUST call `t.Parallel()` first, start no process except through
   `ResolveConflict` and `git`, and reach no network.
5. MUST NOT change `internal/cli/deliver_workflow.go`, the existing conflict
   tests, `internal/suiteguard/`, `internal/suiteguardcontract/` or
   `.roundfixrc.yml`.
6. MUST, as the last step, re-record the coverage record with
   `go test ./internal/spec -run '^TestCoverageEquivalence$' -update-coverage-record -count=1`,
   recording `docs/references/coverage-record.json`, which then lists both
   new tests. With task_01 in place this command exits 0 under this Spec's
   own `_authorization.md`. Never edit the record by hand.

## Acceptance Criteria

- [ ] An archived item whose Pull Request conflicts only in the coverage record is merged and regenerated by the queue's conflict recovery with no operator step.
- [ ] Without its record's sanction, the recovery fails with `regenerate derived paths`, the guard's refusal is in the regeneration log, and the item head and worktree are unchanged.
- [ ] The coverage record lists both new tests and was written by its record command.

## Result

Added the archived-item conflict fixture and both parallel queue tests in
`internal/cli/deliver_derived_archived_item_test.go`. The fixture copies source
inputs in-process, skips `.git`, `.gocache`, `bin`, `docs` and `.agents`, and
copies only the coverage record from `docs`. It builds the base, item edit,
archive and default-branch edit as real commits against a local bare origin.
The coverage command comes from the copied `.roundfixrc.yml`; the fixture's
Archive Record is its only sanction. Workflow home and artifacts stay under
`t.TempDir()`, and nested Go inherits HOME and both Go caches.

Focused evidence for the acceptance criteria:

- Sanctioned recovery: `TestAnArchivedItemsDerivedRecordConflictIsMergedAndRegenerated`
  passed. It asserts a new HEAD, no source paths, the exact configured
  regeneration command, the committed original coverage entry with neither
  fake entry nor conflict markers, both ordered merge parents, the
  `Roundfix-Delivery: derived-merge` trailer and a clean worktree.
- Unsanctioned recovery:
  `TestAnArchivedItemWithoutTheSanctionKeepsItsDerivedRecordConflict` passed.
  Its record lists only `make baseline-digests`. It asserts the
  `regenerate derived paths` error, unchanged item HEAD, a clean worktree,
  no `MERGE_HEAD`, and exactly one regeneration log containing
  `suiteguard: modified: docs/references/coverage-record.json`.

  exited 0. Inspection of the generated diff shows exactly the two new test
  names added to `docs/references/coverage-record.json`; the record was not
  edited by hand.
