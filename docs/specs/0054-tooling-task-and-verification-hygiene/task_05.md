# Task 05: Document the choreography and the standing regeneration policy

## Overview

Turn the two rules this Spec settles into discoverable repository guidance:
the commit choreography a protected-tooling change must follow, and the
standing policy that sanctioned regeneration is fallout of an authorized
edit rather than a separate authorization. Align the Roundfix Skill with the
shipped behavior and propagate the deterministic digest fallout.

## Requirements

1. MUST document the commit choreography in the repository-authored agent
   guidance: prerequisite fixes first, the authorization record second, the
   Task commit third, everything else after — and state that folding a
   prerequisite fix or an authorization into the Task commit fails the gate.
2. MUST record the standing policy that derived pins regenerated by the
   sanctioned command are deterministic fallout of an expressly authorized
   Skill or module edit and need no separate express authorization, while a
   hand-edited pin value remains an unauthorized mutation.
3. MUST document the sanctioned regeneration command and the deterministic
   build-cache behavior where the repository's Verification is described.
4. MUST NOT edit any setup-owned managed block; repository-authored carriers
   own this text.
5. MUST align the Roundfix Skill pair with the shipped behavior when it
   describes Verification, commits, or regeneration, keeping both copies
   byte-identical, and MUST propagate the deterministic digest fallout using
   the sanctioned regeneration command from Task 02.
6. MUST change only the paths this Spec expressly authorizes plus its own
   Task file and repository-authored documentation.

## Subtasks

- [ ] Write the choreography and the standing policy into the

- [ ] Document the regeneration command and cache behavior beside the

- [ ] Align the Skill pair and regenerate the derived pins with the

## Result

### Implementation

- Added the protected-tooling commit choreography to the repository-authored
  agent guide: prerequisite fixes first, the express authorization record
  second, the authorized Task commit third, and everything else afterward.
  The guide states that folding a prerequisite fix or authorization into the
  Task commit fails the tooling-authority gate.
- Recorded the ADR-0081 standing policy for expressly authorized
  Roundfix-owned Skill and Baseline module edits. Derived pins rewritten by
  `make baseline-digests` are deterministic fallout that needs no separate
  express authorization; hand-edited pins remain unauthorized.
- Documented the sanctioned regeneration command beside repository
  Verification and documented that the ignored repository-local `.gocache`
  is only the default when the environment supplies no explicit `GOCACHE`.
- Aligned both Roundfix Skill copies with the shipped repository-green
  precondition, shared executable-file commit filter, and sanctioned
  regeneration policy.
- Ran the sanctioned regeneration command after the Skill edit. It changed
  exactly the five derived-pin paths expressly authorized by the Spec.
