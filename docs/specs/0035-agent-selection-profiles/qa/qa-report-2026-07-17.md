## Findings

### QA-F001: Macro profile flow escapes fake ACP boundary and fails on local Codex hygiene

- **Severity:** Blocker
- **Evidence:** `rtk make verify` and `rtk go test ./internal/cli -run 'TestAgentSelectionProfilesMacro' -count=1` both fail in `TestAgentSelectionProfilesMacro`.
- **Observed failure:** `profiles validate` exits `2` because ACP launch resolves `/Users/marcio/.local/bin/codex`, then reports `invalid or missing code signature; next: reinstall...`.
- **Expected behavior:** The macro harness should use fake pinned ACP adapters through the production process boundary and complete configure/show/validate, mixed backend/frontend+QA work, notification-first cross-runtime fallback, persistence, stream, and invalid Task Type assertions.
- **Impact:** PRD success metrics and task_10 acceptance criteria are not fully proven; the full repository gate and focused race gate fail.
- **Likely cause:** The macro helper creates fake `acpx`, `codex-acp`, `claude-code-acp`, and `opencode` binaries, but does not isolate the `codex` executable or `CODEX_PATH`; the codex launch hygiene path therefore falls through to the workstation runtime.
- **Recovery action:** Isolate Codex launch in the macro fixture with a fake `codex` executable or explicit `CODEX_PATH` that passes the production hygiene boundary, then rerun `rtk make verify` and the task_10 macro/race gates.
