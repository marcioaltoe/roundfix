# The Baseline corrects its archive destination, profile gaps and guide warnings — Technical Spec

## Executive Summary

Three independent corrections land in existing seams of `internal/baseline`
and `internal/cli`. The archive clause of the `spec-workflow` module gets its
current destination and is regenerated by the Baseline's own commands. A new
helper, `ProfileDecisionGaps`, reads the embedded catalog to find decisions a
template the profile renders requires and the profile does not reach;
`buildPlanWithCatalog` returns a `decision` action outcome for them before
it normalizes decisions, and `baseline profile validate` fails on them. The
carrier classification gains one kind, a repository-authored guide, that the
warning filter drops. The trade-off the gap rule accepts is a static reading
of the catalog: it counts a template only when no decision can replace it, so
a gap behind a conditional template still fails at render as today, in
exchange for no false refusal of a profile that renders correctly (proved
over every built-in profile).

## Implementation Design

### Interfaces

```go
// internal/baseline/profile_decision_gap.go
type ProfileDecisionGap struct {
	Decision  string // catalog decision ID, e.g. verification.incremental
	Template  string // template whose token it binds
	Artifact  string // managed artifact rendered with that template
	Suggested string // rendered suggestion or default; "" when the catalog has none
}

func ProfileDecisionGaps(profile ResolvedProfile, catalog *Catalog) []ProfileDecisionGap
func ProfileDecisionGapMessage(profile ResolvedProfile, gaps []ProfileDecisionGap) string
func ProfileDecisionGapRepair(profile ResolvedProfile, gaps []ProfileDecisionGap, command string) string

// internal/baseline/classification.go
const carrierRepositoryAuthoredGuide carrierClassificationKind = "repository-authored-guide"
func hasMarkerLine(content []byte) bool
```

### Data Models

No persisted model changes. The Setup Manifest, plan JSON, update JSON and
profile JSON keep their schemas; the refusal travels in existing `message`
and `nextAction` fields.

### API Contracts

1. API Contract: the archive clause. In the guidance of
   `clause.spec.keep-artifacts-in-spec-folder`, the text
   "so copy every file a later reader needs to `docs/references/`, an
   accepted ADR, the glossary, an agent guide or the Secondbrain inbox before
   or at archive." becomes "so copy every file a later reader needs to
   `docs/references/`, an accepted ADR, the glossary or an agent guide before
   or at archive, or send its knowledge in an ai-memory message to the
   project that owns the Secondbrain for its ingestion." Every other byte of
   the clause stays; `id`, `enforcement` and the absence of `replaces` stay.
2. API Contract: the gap rule. `ProfileDecisionGaps` returns, sorted by
   decision then template, one gap per decision D and binding (artifact A,
   template T) where all hold:
   - D is a catalog decision not marked `optional`, and one of its effects
     binds a token of T on A (`renderBindings`);
   - A is declared by a module in `profile.Modules` with template T, and no
     catalog decision's `selectTemplates` names another template for A;
   - D is not reachable: the reachable set starts with `profile.Decisions`
     and adds, until nothing changes, every decision a member's effect lists
     in `requireDecisions` and every `requiredDecisions` entry of a module a
     member's effect lists in `activateModules`, whatever the effect's `when`.
   `Suggested` is the decision's `suggestion`, else its `default`, rendered
   by `renderDecisionValue`. A built-in profile has no gap.
3. API Contract: the gap message and repair. `ProfileDecisionGapMessage`
   joins with "; " one phrase per gap:
   `profile <id> does not list decision <decision>, which template <template> requires`.
   `ProfileDecisionGapRepair` returns
   `add "<d1>", "<d2>" to "decisions" in <path>, then <command> --decision '<d1>=<value>' --decision '<d2>=<value>'`,
   listing each distinct decision once in sorted order, where `<path>` is
   `profile.Path` as the command prints it and `<value>` is `Suggested`, or
   the literal `<value>` when it is empty.
4. API Contract: `baseline plan` and `baseline update`. After the profile
   resolves (by ID or draft) and before `normalizePlanDecisions`,
   `buildPlanWithCatalog` returns
   `actionOutcome("decision", ProfileDecisionGapMessage(...), ProfileDecisionGapRepair(..., "rerun with"), warnings)`
   when gaps exist. Both commands then exit 3, print
   `Category: decision`, and write nothing; JSON carries state
   `action_required`, category `decision`, the message and `nextAction`.
5. API Contract: `baseline profile validate`. For each resolved profile with
   gaps, the command fails as other invalid profiles do (exit 2, category
   `preflight` in JSON) with the message
   `custom.profile.decision.template-required: <ProfileDecisionGapMessage>; <ProfileDecisionGapRepair with "run roundfix baseline update">`.
   A profile without gaps keeps today's bytes.
6. API Contract: the repository-authored guide. `classifyMarkedCarrier`
   first checks a carrier with no managed block: when its path starts with
   `docs/agents/`, its base name is neither `AGENTS.md` nor `CLAUDE.md`,
   `hasMarkerLine` is false, the path is not a value of `knownPaths`, and
   neither the Setup Manifest nor the current plan has an artifact at the
   path, it returns `carrierRepositoryAuthoredGuide`. Otherwise its logic is
   unchanged. `hasMarkerLine` is true when a line, after at most three
   spaces, starts with `<!--`, optional whitespace and
   `setup-context-driven:begin` or `setup-context-driven:end`.
   `warningsForCarrierClassifications` drops the
   `baseline.inventory.nested-carrier-conflict` warning for the new kind as
   it does for current and stale managed artifacts.

### Surface Transcripts

The repository is a temporary Git repository holding only a Makefile with
`verify` and `verify-incremental` targets and
`.roundfix/baseline/profiles/sqllib.json`, made by
`roundfix baseline profile init --id sqllib --from go-cli-tui` with

1. Surface Transcript: `baseline profile validate` names the gap.

   ```transcript
   $ roundfix baseline profile validate sqllib
   stdout:
   stderr:
   roundfix: baseline profile.validate failed: custom.profile.decision.template-required: profile sqllib does not list decision verification.incremental, which template template.guide.agent-instructions requires; add "verification.incremental" to "decisions" in .roundfix/baseline/profiles/sqllib.json, then run roundfix baseline update --decision 'verification.incremental=make verify-incremental'
   Run 'roundfix baseline profile --help' for usage.
   exit: 2
   ```

2. Surface Transcript: `baseline plan` refuses before rendering.

   ```transcript
   $ roundfix baseline plan --profile sqllib --repo . --format text --decision preservation.mode=greenfield
   stdout:
   Baseline plan: action required
   Category: decision
   Result: profile sqllib does not list decision verification.incremental, which template template.guide.agent-instructions requires
   Next action: add "verification.incremental" to "decisions" in .roundfix/baseline/profiles/sqllib.json, then rerun with --decision 'verification.incremental=make verify-incremental'
   stderr:
   exit: 3
   ```

## ADR Alternatives

- ADR-0372: the design takes the decided options and none of the rejected
  ones: it never writes the profile, it names templates rather than modules,
  it does not narrow the text match, and it keeps the warning for a guide at
  a managed path.
- ADR-0330: rejected keeping the Secondbrain inbox beside ai-memory; the
  clause now names only ai-memory for cross-project knowledge.
- ADR-0338: rejected leaving a handed-in message pending; the design sends
  no message and changes no follow-up behavior.
- ADR-0353: rejected validating a waiting declaration outside the command
  that reads it; the design touches neither the declaration nor its reader.

## Risks & Considerations

- Rebase order: Spec 0360 delivers first and Spec 0361 after. A derived
  Baseline file or version record in conflict is regenerated by its command,
  never merged by hand.
- A repository profile that renders today and has a gap behind a template
  alternative keeps today's render error; the rule is static by design.
- The refusal precedes the existing missing-decisions outcome in `baseline
  plan`, so a plan over a gap profile no longer lists other missing
  decisions until the gap is fixed; the test pins the order.
- Plan characterization goldens may record carrier warnings; step 3 reruns
  `make baseline-digests` when a golden moves and declares them.

## Decisions

- One helper serves the plan, the update and the validate command; the
  update reaches it through `BuildPlan`, so its exit and JSON shape come from
  the existing outcome mapping. See ADR-0372.
- The template rule, not the module rule, names the gap, because the
  template is what fails to render.
- The repository-authored guide branch runs only for a carrier with no
  managed block; every other carrier keeps its classification bytes.
- Four implementation Tasks and the QA gate, in series, because tasks 01 to
  03 all move the Baseline package's derived records.
