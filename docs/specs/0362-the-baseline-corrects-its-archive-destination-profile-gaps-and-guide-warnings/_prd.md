# The Baseline corrects its archive destination, profile gaps and guide warnings

Two adopters reported three Baseline defects on 2026-11-06 after `roundfix baseline update` 0.136.0. The docs layout guide's archive clause still sends a file a later reader needs to the Secondbrain inbox, which ADR-0330 retired. A repository-owned Baseline Profile that does not list `verification.incremental` makes `baseline update` fail with an opaque render error while `baseline profile validate` calls the profile valid. Every guide a repository writes under `docs/agents/` raises `baseline.inventory.nested-carrier-conflict`, which the reporter traced to the marker name quoted in prose. After this Spec the clause names an ai-memory message to the project that owns the Secondbrain, the three profile commands name the missing decision, the line to add and the `--decision` flag, and a guide the Baseline does not own stops warning.

## Goals

- An adopter's docs layout guide sends knowledge a later reader needs to a
  destination that exists: a repository file or an ai-memory message to the
  project that owns the Secondbrain.
- A repository profile that lacks a decision a template it renders requires
  is refused before anything renders, by `baseline profile validate`,
  `baseline plan` and `baseline update`, with the decision, the template, the
  quoted entry to add and the `--decision` flag; nothing is written.
- After the profile lists the decision, `baseline update` follows the
  promise of the setup skill: it exits 3 and names the missing decision.
- A guide under `docs/agents/` that the Baseline does not manage and that
  carries no marker line raises no nested-carrier warning, whether or not its
  prose names the marker; every other nested carrier keeps its warning.

## User Stories

1. As an agent archiving a Spec in an adopter repository, I want the docs
   layout guide to name a destination that still exists, so that knowledge
   leaving with the Spec folder is not sent to a retired inbox.
2. As a maintainer of a repository with its own Baseline Profile, I want
   `roundfix baseline profile validate`, `baseline plan` and `baseline update`
   to tell me which decision my profile lacks, the line to add and the
   `--decision` flag, so that I can repair it without reading the catalog.
3. As a maintainer who writes a repository guide under `docs/agents/`, I
   want the Baseline to leave it without a conflict warning, so that a real
   conflict stands out.

## Core Features

1. The archive clause. `clause.spec.keep-artifacts-in-spec-folder` ends
   with the current destination; the `spec-workflow` module records its next
   version, and the derived Baseline files and this repository's docs layout
   guide are regenerated by their commands.
2. The profile decision gap. One helper in the Baseline package finds every
   decision a template the profile renders requires and the profile does not
   reach. `baseline plan` and `baseline update` stop with category `decision`
   and exit 3; `baseline profile validate` fails with
   `custom.profile.decision.template-required` and exit 2.
3. The repository-authored guide. The carrier classification recognizes a
   guide under `docs/agents/` that carries no marker line at a path no
   catalog artifact or Setup Manifest entry manages, and drops its
   `nested-carrier-conflict` warning.
4. Documentation. The baseline command guide, the Roundfix skill's baseline
   reference and the setup skill describe the refusal and the warning rule;
   both owned skills record their next versions.

## User Experience

A maintainer whose profile lacks `verification.incremental` runs
`roundfix baseline update` and reads
`Result: profile sql-library does not list decision verification.incremental, which template template.guide.agent-instructions requires`
and `Next action: add "verification.incremental" to "decisions" in .roundfix/baseline/profiles/sql-library.json, then rerun with --decision 'verification.incremental=make verify-incremental'`,
with exit 3 and no write. `roundfix baseline profile validate sql-library`
exits 2 with the same facts and the full `roundfix baseline update` command.
An adopter's next `baseline update` shows `update docs/agents/docs-layout.md`
as a Managed Refresh.

## Acceptance evidence

The outside-evidence row rests on a source this Spec did not write: the
CommonMark specification 0.31.2, section 4.6 HTML blocks
(https://spec.commonmark.org/0.31.2/, read through Exa on 2026-11-06): "The
block begins with a line that meets a start condition (after up to three
optional spaces of indentation)." A comment that starts a line is an HTML
block; the same characters inside a code span are text, which is why a
marker line, not the marker name, is the evidence a guide is managed.

  Secondbrain", as `docs/agents/secondbrain.md` does: every adopter renders
  it, and adopters other than the maintainer's may have no project named
  `default/marcioaltoe-secondbrain`. In the maintainer's repositories that

  fails with the same render error; it runs before decisions are normalized,
  so the refusal comes first.
- The detector's change follows the characterization: since the marker name
  is not the trigger, a guide the repository wrote under `docs/agents/`,
  without a marker line and at a path the Baseline does not manage, stops
  warning, and the marker name in prose no longer makes such a guide
  unclassifiable. This is the outcome the reporter asked for ("parece falso
  positivo").
- ADR-0372 records the three corrections. No older ADR is amended: the
  archive decision of 2026-10-06 still names the Secondbrain inbox in a
  sentence ADR-0330 overtook, and the nested-carrier rule of 2026-07-24 keeps
  its meaning, because a guide the Baseline does not own is no detected
  conflict. Amending either record would make every ADR that cites it an
  obligation of this Spec (39 and 48 records, measured with the strict
  check's citation rule on 2026-11-06).
