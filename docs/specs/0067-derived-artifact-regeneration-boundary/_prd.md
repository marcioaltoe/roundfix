# Derived artifact regeneration boundary

`internal/baseline/testdata` is listed in `DERIVED_DIGEST_PATHS`, so the
natural reading is that `make baseline-digests` owns everything under it. It
does not, and the gap has now produced the same failure three times.

The frozen parity corpus lives there but is regenerated by nothing — acting on
the natural reading and repointing its blob and twelve fixtures was wrong, and
the edits had to be reverted. The diagnostic characterization corpus added by
Spec 0062 lives there too and is regenerated only by its own dedicated flag: a
single owned-skill edit changed a recorded digest detail, `make verify` failed,
and `make baseline-digests` succeeded in one invocation while being unable to
fix what it had broken. Specs 0034 and 0035 met the same collision earlier and
handled it with an unexplained exclusion list in a test. Evidence:
[the frozen parity corpus reads as a derived artifact](../../findings/2026-07-30-baseline-digest-regeneration-cannot-bootstrap.md)
and
[the characterization corpus is outside its regeneration command](../../findings/2026-08-01-characterization-corpus-is-outside-the-regeneration-command.md).

Spec 0062 fixed the regeneration cycle. This Spec fixes the boundary the cycle
sat on: which artifacts under a derived path the regeneration command owns, and
which it does not.

## Project Constraints

- Identifier strategy: not applicable — no project-owned Internal Identifier is
  created; artifact paths, digest fields, and diagnostic codes keep their
  existing contracts. Source: `docs/agents/domain.md`.
- Authentication and HTTP: not applicable — the governing clause prohibits
  reading, printing, committing, or generating secrets and forbids inventing
  authentication, authorization, transport, or deployment policy; all behavior
  is local artifact regeneration and validation. Source:
  `docs/agents/agent-instructions.md`.
- Active ADR obligations: applicable — ADR-0081 keeps sanctioned digest
  regeneration a fallout of the authorized edit; ADR-0085 keeps a regeneration
  run ungated by the pins it rewrites while every other load stays strict, and
  any new regeneration step must preserve both. ADR-0080 owns QA verdict
  semantics and ADR-0091 owns the authored QA gate as a typed Task node,
  under which this Spec's own graph is authored. ADR-0093 surfaces as a
  relation candidate because it cites ADR-0080; it does not apply — it
  governs the Spec Consistency Check's detection boundary. Source:
  `docs/agents/domain.md`.
- Tooling authority: applicable — express maintainer authorization: on 2026-08-02 the maintainer
  authorized tooling adjustment for the queued Specs, recorded at
  `docs/workflow/authorizations/2026-08-02-queued-spec-tooling.md`; bounded
  files: `Makefile`. Deterministic digest fallout is sanctioned by ADR-0081. Source:
  `docs/agents/agent-instructions.md`.

## Goals

- Every artifact under a derived path has exactly one stated regeneration
  owner, readable at the path rather than inferred from a helper.
- One sanctioned command regenerates everything it claims to own, so an
  ordinary edit never leaves a maintainer holding a broken gate the command
  cannot fix.
- An artifact deliberately frozen is marked as frozen where a reader and a test
  both find it.

## Core Features

1. Every path under the derived scan is classified as regenerated by the
   sanctioned command, regenerated by a named dedicated step, or frozen, and
   the classification is recorded at the path.
2. The sanctioned regeneration command covers every artifact it claims,
   including the diagnostic characterization corpus, so a single invocation
   leaves the tree consistent after an ordinary owned-skill or module edit.
3. A frozen artifact is marked at its own path, replacing inference from a
   helper's implementation and the unexplained exclusion lists Specs 0034 and
   0035 added.
4. A failure whose remediation the sanctioned command cannot perform states
   that fact and names what the human must do, rather than printing a command
   that will not help.
5. A test proves the classification is exhaustive: an artifact under a derived
   path with no stated owner fails, so the next artifact added cannot silently
   inherit the ambiguity.

## Non-Goals / Out of Scope

- Changing what any derived artifact contains, or how any digest is computed.
- Re-litigating the regeneration cycle or the strict-load boundary, which
  ADR-0085 and Spec 0062 own.
- Making frozen artifacts regenerable — frozen is the intended state, and this
  Spec makes it legible rather than changing it.

## Success Metrics

- Editing an owned skill and running the sanctioned regeneration command once
  leaves `make verify` green, reproducing the 2026-08-01 failure as a
  regression fixture.
- Every path under the derived scan resolves to exactly one stated owner, and
  adding an unclassified artifact fails the exhaustiveness test.
- The frozen parity corpus is identifiable as frozen from its own path, without
  reading a test helper.

## Decisions

- Ownership is declared at the path, not inferred from which step happens to
  rewrite a file. Inference is what produced three instances of this defect.
- Frozen stays frozen; legibility is the deliverable, not regenerability.
- This Spec evolves the regeneration contract and never regresses it: every
  artifact regenerated today is still regenerated the same way, and no digest
  value changes as a result of this Spec.
