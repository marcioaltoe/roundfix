Glossary entry: **Spec Queue Table**:
The table the status view of the Follow-up Command shows of a repository's Spec queue, one row each and in this order: each Delivery Queue item that is not merged, each planned Spec that is not queued, each Spec being authored and each open Backlog Entry. A row holds a row number, the Spec's number, a status, a start, an end and a one-line note; a start or an end is an actual time, a Queue Forecast, a named condition with two durations, or the reason no forecast is shown. A Spec is being authored when the checkout holds no PRD for it and either its folder or a phase entry of an Authoring Phase written in the last seven days of the Phase Record, recorded in the checkout or in a working tree with the same `origin` remote. A renamed Spec keeps its Spec Number, so an entry for a slug without a folder there does not count when another slug of the same number has a folder, an Archive Record, a Delivery Queue item or a later counted entry ([ADR-0409](docs/adr/0409-a-queue-forecast-is-a-likely-time-and-a-limit-from-the-repository-own-deliveries-or-a-named-condition.md), [ADR-0410](docs/adr/0410-the-status-view-lists-specs-being-authored-and-open-backlog-entries.md), [ADR-0434](docs/adr/0434-a-renamed-spec-keeps-its-spec-number-and-is-one-row-of-the-spec-queue.md)).
