# The Secondbrain search and the duplicate check go through the Indexus, with no second path

## Context

On 2026-11-20 the maintainer decided: "Agora, os testes devem ser com o
objetivo inicial de ser superiores ao que o qmd/secondbrain entrega no que os
projetos/jarvis usam. Se for, já podemos usar somente o indexus e eliminar o
qmd no mini e macbook." He authorized preparing the change in a Pull Request
while the test runs. The earlier command required a local installation and
index, could be slow, and the consultation attempted during authoring stopped
at a locked database. Keeping it in the guide after its removal would direct
Agents to a command the machines no longer have.

## Decision

The Secondbrain search after reading `wiki/index.md` and the advisory duplicate
check use the `pesquisar_acervos` tool of the `indexus` MCP server. No Baseline
clause, generated guide or owned skill names a second search tool. The search
opens a returned page with `abrir_conteudo`, using its returned `caminho`; the
duplicate check verifies that each returned page opens and names a strong
verified match so the knowledge owner extends what exists. A relevance label
or a rank alone never decides.

When the tool is absent, does not answer, or answers without a wiki page, the
Agent records that limitation and continues with the evidence it has. It
substitutes no other search tool and claims no consultation that did not
happen.

Both clauses keep their identities and mandatory force. The duplicate-check
clause keeps its replacement of the earlier research-capture clause, so an
adopter's update accounts every clause it held. Roundfix's code never calls
the Indexus and adds neither a Baseline decision nor a Doctor check for it:
the session provides the tool and its reach.

This decision takes effect with the release that carries it. The change waits
in an open Pull Request until the project that owns the Secondbrain reports
that the Indexus is superior in the uses the maintainer named. That project
removes the earlier command from the machines after the release, not as part
of this repository's change.

## Considered Options

- Indexus first with the earlier command as a reserve: rejected by the
  maintainer's choice of one path; a reserve would preserve the installation
  and an instruction that its removal breaks.
- A Baseline decision declaring whether the Indexus is available: rejected
  because availability belongs to the session, not the repository.
- New clause identities: rejected because rewording keeps identity and force;
  new identities would require new Source Baseline accounting.
- Describing the search capability without naming the tool: rejected because
  an Agent needs the tool's name to perform the consultation.
- Naming one harness's joined tool identifier: rejected because that
  identifier differs by harness; server and tool names are stable separately.

This decision amends the consultation rule of
[ADR-0330](0330-the-secondbrain-is-read-only-and-ai-memory-carries-handoffs-and-messages.md).
The Secondbrain remains read-only, and ai-memory continues to carry handoffs
and cross-project messages.

# The Secondbrain is read-only and ai-memory carries handoffs and messages

Supersedes ADR-0095 (2026-10-24); it is retired, and Git keeps its text.

ADR-0095 made the Secondbrain's `inbox/<destination>/` the single door for
every fleeting observation: any session committed a file there, and only the
destination project triaged it. Since 2026-10-19 the maintainer's sessions
also run ai-memory, whose MCP server gives each project an inbox of directed,
claim-once messages (`memory_message_send`, `memory_message_list`,
`memory_message_pop`) and single-use session handoffs (`memory_handoff_*`).
Two doors for one job split the fleet's mail: on 2026-10-24 the maintainer
wrote "Lembrando que solicitei em algum momento para matar o inbox de
secondbrain e usar somente as mensagens do ai-memory". The same day the
upstream skills repository replaced its `handoff` skill with six `ai-memory-*`
skills in every preset (pull request #131, commit
`65d5f365cace27c4b468db1723213723b10c870b`).

## Decision

**The Secondbrain stays the business knowledge base, and it is read-only.**
The Baseline keeps its consultation rules: read `wiki/index.md` first, then
`qmd`, cite every file used, keep secrets out, and ask its owner to ingest a
durable change. A session never writes a Secondbrain file, `inbox/` included.
Substantive external research reaches the Secondbrain as a digest message to
the project that owns it, which ingests it by its own contract.

**Amended by [ADR-0449](0449-the-secondbrain-search-and-the-duplicate-check-go-through-the-indexus-with-no-second-path.md) (2026-11-20).** The consultation rule after the wiki index uses the Indexus tool `pesquisar_acervos`, the advisory duplicate check uses the same tool, and no second search tool is named.

**ai-memory carries session handoffs and cross-project messages.** The core
module requires and dispatches `ai-memory-handoff` and `ai-memory-messaging`
in place of `handoff`, and its new rule says: an observation another project
owns becomes one self-contained message to that project's inbox; a project
reads its messages oldest first and consumes one only after recording its
content in a Spec, a Backlog Entry or a Finding, or naming it when it only
informs. Each retired inbox clause is replaced by one of these clauses with
the same force, so an adopter's next refresh accounts every clause it held.

**Amended by [ADR-0383](0383-a-message-expects-a-reply-only-when-it-declares-the-work-it-blocks.md) (2026-11-10).** A message is one-way unless the sending project's own work depends on the answer: the sender then says so in the subject and first lines and names the blocked work, and otherwise neither waits for a reply nor watches whether the other project acted. The receiving project triages such a message first and the others oldest first, handles it next after the work already running, and answers only it. Recording before consuming, and the rest of this decision, still hold.

**Amended by [ADR-0390](0390-one-blocking-message-per-sender-takes-precedence-and-every-direct-question-is-answered.md) (2026-11-11).** The receiving project triages first only the oldest blocking message of each sender, and it answers each direct question a message asks, not only a blocking one; it still sends no acknowledgment, adoption notice or completion notice to a message that declared no blocked work.

**Amended by [ADR-0396](0396-a-message-that-asks-to-be-told-when-its-work-is-done-receives-one-completion-notice.md) (2026-11-12).** The receiving project sends one completion notice to a message that asks to be told when its work is done, once that work is delivered; it still sends no acknowledgment or adoption notice to a message that declared no blocked work.

**ai-memory is optional and detected at run time.** It is not a Baseline
decision: a repository renders the same guidance with or without it. A
session uses ai-memory only when it exposes the MCP tools; otherwise it tells
the user what is missing and puts the handoff or message text in its
response. Roundfix's own code never talks to ai-memory: the follow-up command
keeps reading messages only from a file the caller hands in, and drops its
`secondbrain-inbox` source. Its two keys, `secondbrain.root` and
`secondbrain.inbox_namespace`, become deprecated keys that are ignored with
one warning, so an existing User Config keeps loading.

**The upstream setups follow the commit that carries the ai-memory skills.**
Every upstream Setup Snapshot moves to `65d5f36` through the asset sync,
the only writer of a Setup Snapshot; the snapshots drop `handoff` with
upstream and gain the six `ai-memory-*` skills; `go` and `rust` also gain
`find-skills` and lose `council` and `the-fool`, which Roundfix had already
retired. The `gws-*` and
`brand-guidelines` skills upstream removed were never in a Roundfix snapshot,
because the Baseline imports no `content` or `devops` preset.

## Considered Options

- Keeping both doors, the Secondbrain inbox for captures and ai-memory for
  handoffs, was the 2026-10-19 arrangement; the maintainer retired it on
  2026-10-24 because the same observation could land in either.
- Making ai-memory a Baseline decision, with clauses that apply only when a
  repository answers yes, was rejected: whether the MCP server is reachable is
  a property of the session, not of the repository, and the fallback (say
  what is missing, put the text in the response) is the same everywhere.
- Having the follow-up command read ai-memory through its HTTP API was
  rejected: the CLI would need a credential and a network call, and the skill
  already hands messages in as a file.
- Removing the two configuration keys outright was rejected: strict
  validation would then refuse every User Config that still names them,
  including the maintainer's.
