# Secondbrain

- **mandatory**: Consult both the local Secondbrain and Exa MCP before proposing solutions or recommendations, making product, design, or architecture decisions, and authoring an Idea, PRD, or TechSpec. Both sources are required; one does not replace the other.

- **mandatory**: Read `wiki/index.md` first. Then search with the `pesquisar_acervos` tool of the `indexus` MCP server, which returns one group per acervo the session's key reaches; `abrir_conteudo` opens a returned page by its `caminho` as returned, which for a `wiki` result is relative to `wiki/`. An answer without a `wiki` result is a limitation to record. When the tool is not in the session or does not answer, the Secondbrain search is unavailable: substitute no other search tool. Inspect `projects/<project>/mirror/` only when the index and the search point there, and open only the files required for the task; treat mirrors as references, not workspaces.

- **mandatory**: Use Secondbrain for prior decisions, related project experience, and existing research.

- **mandatory**: Use Exa MCP to find and read relevant external sources that support or challenge the proposal. Prefer primary sources, assess their applicability, and distinguish published evidence from inference. This requirement complements the mandatory authoritative documentation workflow for external APIs and libraries.

- **mandatory**: If either source is unavailable or yields no relevant result, record the attempted consultation and its limitation explicitly, then continue with the available evidence. Do not claim validation from an unavailable, unread, or irrelevant source. Another research tool does not satisfy the Exa MCP requirement.

- **prohibited**: Do not create, edit, rename, move, or delete any Secondbrain file, `inbox/` included. Do not edit `raw/` or `projects/*/mirror/`, and never copy code or generated artifacts from a mirror without a local source check.

- **mandatory**: Send substantive external research and relevant findings or articles from Exa MCP as a sourced digest in one message to the project that owns the Secondbrain, for its own ingestion and later reuse as reference material, including relevant articles found outside a dedicated research session. Include each source's title and URL, a concise summary of the content read, the projects or topics it informs, and why it matters; distinguish published evidence from inference. Run the advisory duplicate check first with the Indexus tool `pesquisar_acervos`, verify that each returned page opens, and name a strong verified match in the message so the owner extends existing knowledge instead of duplicating it; a relevance label or a rank alone never decides.

- **prohibited**: Never read, copy, or expose `.env` files, tokens, credentials, cookies, private keys, API keys, session material, or unsafe personal and client data. Stop at likely secret-bearing sources and request a safe source.

- **mandatory**: Cite every Secondbrain file used in the final response or handoff by path. Do not claim Secondbrain context when no Secondbrain file was read.

- **mandatory**: Record the Secondbrain file paths and external source URLs used, and explain how they informed, changed, or challenged the decision in the relevant technical artifact. If no artifact is being authored, include this record in the response.

- **mandatory**: Guidance delivered inside `setup-context-driven` markers is owned by the Baseline, not by the repository holding it. Proposing a change to it is a message to the Baseline's owner; editing it locally produces a change the next Baseline update silently overwrites. Verify ownership by looking for the markers before editing any agent guide, because the same file usually carries repository-authored prose outside them that is yours to change.

- **mandatory**: When Secondbrain knowledge must be added or corrected, ask Hermes to ingest or update it instead of writing from this repository.

- **mandatory**: This repository publishes to the Secondbrain only what `.secondbrain-export` lists, and that file has two parts. The first is the Standard Export List, between the lines `# roundfix:standard-export:begin` and `# roundfix:standard-export:end`: the README, the glossary files, `docs/user-guide/`, `docs/references/`, `docs/design/`, `docs/lessons/` and each ADR whose header says `knowledge: true`, one path per line. The Baseline owns those lines: `roundfix baseline update` rewrites them, and the only line added by hand is the path of an ADR, in order, when the ADR is written with that mark. Never publish process: `AGENTS.md`, `CLAUDE.md`, `docs/agents/`, the Spec folders, `docs/backlog/`, `docs/findings/`, `docs/handoffs/` and `docs/history/` stay out of both parts.

- **mandatory**: The second part is the repository's own lines, everything outside those two markers, which no Baseline operation changes. There the repository may add a file or a folder of knowledge that the standard list lacks, or drop a standard item with an exclusion line: `!` followed by the item as the list writes it, or `!docs/adr/*` for every ADR. Give each such line its reason in a comment line directly above it; one comment stands for the lines that follow it without a blank line. `roundfix doctor` reports a line without a reason, a process path, and a standard list that differs from what the update would write.

- **mandatory**: Mark every ADR you write with whether the Secondbrain wants it: add `knowledge: true` or `knowledge: false` to its header, on the line after `status`. It is `true` when the decision states a rule of the business or of the product that someone outside this repository's development can use, and `false` when it is about how this repository is built, tested, organized or delivered, or about a tool it uses. An ADR without the mark is not published. The ADRs a repository already has are marked once, by the same test, by the Agent of the session that applies the Baseline update that brings this rule: in one commit that a person reviews in a Pull Request, followed by a second update so the list names them.
