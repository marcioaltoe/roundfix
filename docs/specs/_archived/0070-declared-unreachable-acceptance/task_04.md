# Task 04: Teach the gate to match and to scope its blocking

## Overview

Two behaviours live in the `qa-gate` skill and nowhere else. First, matching a
blocked row against the Spec's declarations and typing it as
declared-unreachable — distinctly from environment and from finding. Second,
scoping a static-gate failure to the rows it actually implicates.

The second is what cost this repository two full cycles in one day: on Spec
0072 a single governance finding marked fifteen of twenty-four rows blocked,
and on Spec 0064 one load-sensitive assertion marked thirteen of fifteen —
including every functional journey those Specs existed to prove.

This is the authorized tooling Task. Its bounded files are exactly
`.agents/skills/qa-gate/**` and the `skills/qa-gate/**` mirror.

## Requirements

1. MUST record a blocked row that matches one of the Spec's declared
   unreachable acceptances as `blocked (declared: <criterion>)` and count it in
   `rows_blocked_declared`.
2. MUST keep the three causes separate and countable: no cause is folded into
   another to make a report look cleaner, and no verdict becomes more permissive
   than the evidence it summarizes.
3. MUST report a row declared unreachable that the gate could in fact reach as a
   finding — a wrongly declared row — rather than accepting the declaration.
   Declaration is the author's claim, not proof.
4. MUST NOT let the gate declare unreachability on its own. It matches only what
   the Spec declared before the run.
5. MUST scope a static-gate failure to the rows that depend on what failed. Rows
   it does not implicate still run and report, and a row it does block records
   by name the failure it waits on.
6. MUST keep a blocked row with no matching declaration blocking exactly as it
   does today.
7. MUST change exactly `.agents/skills/qa-gate/**` and its `skills/qa-gate/**`
   mirror, regenerated by `make skills-sync`. This is the complete bounded file
   list from the Tooling authority row; any other path is out of scope — stop
   rather than widen it.
8. MUST run `make baseline-digests` after the skill edit, then re-record the two
   characterization corpora that command does not reach:

   ```bash
   go test ./internal/baseline -count=1 \
     -run TestBaselinePlanCharacterization -update-baseline-plan-characterization
   go test ./internal/baseline -count=1 \
     -run TestCatalogDiagnosticCharacterization -update-catalog-diagnostics
   ```

   Editing the skill moves the qa-gate tree digest, which moves the setup
   snapshots and the catalog digest, which makes both corpora stale. Neither
   test is in `BASELINE_DIGEST_STEPS`, so the sanctioned command reports "no
   changes" and the gate still fails — recorded in
   `docs/findings/2026-08-01-characterization-corpus-is-outside-the-regeneration-command.md`,
   which Spec 0067 owns. The flag names are given verbatim because they do not
   match their test names and have been guessed wrong before.
9. Every file those commands rewrite under `DERIVED_DIGEST_PATHS` is
   deterministic fallout of the authorized edit, sanctioned by ADR-0081, and
   needs no separate grant. Never hand-edit one.

## Result

Updated the QA gate contract with a third blocked cause,
`blocked (declared: <criterion>)`, and the independent
`rows_blocked_declared` count. The gate now loads declarations before the run,
matches only a proved blocked cause to the declaration's criterion and reason,
keeps unmatched rows under their existing environment or finding cause, and
never creates a declaration itself. A declared row that the gate can reach
runs normally but produces a wrongly-declared-row finding that prevents
`pass`.

Static-gate failures now block only matrix rows whose entry point, observable,
or evidence depends on the named failed check. Unimplicated rows continue, and
even a genuinely matrix-wide failure must record the dependency on each row.
The verdict rules remain evidence-conservative: declared-blocked rows produce
`partial`, wrongly declared rows produce `fail`, and `pass` requires zero
declared-blocked and finding-blocked rows.

Acceptance evidence:

- Declared cause and count: the canonical skill defines
  `blocked (declared: <criterion>)` beside the environment and finding forms,
  adds `rows_blocked_declared` to report frontmatter and coverage, and requires
  all three exact counts in every closed report.
- Wrong declaration: the real-flow rules require the gate to run any declared
  row it can reach, record a wrongly-declared-row finding, and prevent `pass`
  even when the journey's product behavior passes.
- No gate-authored declaration: scope resolution says declarations must come
  from the PRD's pre-run `## Unreachable Acceptance` section and prohibits
  inferring one from a failed attempt.
- Implicated-row scoping: the code-caused static-gate rule traces each failed
  check to dependent rows, names that check in every finding-blocked status,
  and continues rows whose evidence remains valid.
- Verdict conservatism: `fail` includes wrongly declared rows; `partial`
  includes declared-blocked rows; `pass` excludes declared-blocked,
  finding-blocked, skipped, and wrongly declared rows. Environment-blocked
  semantics remain unchanged.
- Mirror identity: after `rtk make skills-sync`,
  `rtk cmp -s .agents/skills/qa-gate/SKILL.md skills/qa-gate/SKILL.md` exited
  0.
- Bounded paths: post-regeneration `rtk git status --short` and
  `rtk git diff --name-only HEAD` showed only the two authorized skill files,
  this Task file, and twelve command-generated files under
  `internal/baseline/assets/setups/` or `internal/baseline/testdata/`, both in
  `DERIVED_DIGEST_PATHS`.
- Full repository gate: `make verify` remains for Daemon-owned Verification
  and was not run in this Agent turn, so this criterion has no Agent-side
  terminal evidence.
