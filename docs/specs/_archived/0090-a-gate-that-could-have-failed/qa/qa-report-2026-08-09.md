## Findings

### F-001 — Project Constraints cite the wrong accepted ADR

- Impact: Trust-Damage.
- Actor and journey: maintainer auditing Q01 before crediting implementation
  evidence.
- Expected: the PRD and TechSpec must cite the accepted decision that makes
  `make verify` authoritative, or cite the operative repository guide without
  assigning that meaning to another ADR.
- Actual: both artifacts state that ADR-0083 makes `make verify` authoritative,
  while accepted ADR-0083 is “Adopted sources move to their owning Spec” and
  contains no Verification-gate decision. The gate requirement is present in
  `docs/agents/agent-instructions.md` and `docs/agents/specific-repository.md`,
  so the product rule exists but its claimed ADR provenance is false.
- Reproduction: read `_prd.md` and `_techspec.md` → Project Constraints, then
  read `docs/adr/0083-adopted-sources-move-to-their-owning-spec.md`; search
  `docs/adr` and `docs/agents` for `authoritative gate|make verify`.
- Affected rows: Q01. Task 01 and Task 06 Results independently recorded the
  same out-of-scope citation defect before this gate.

### F-002 — The pre-work probe breaks existing Clean Implement journeys

- Impact: Blocks-Completion.
- Actor and journey: maintainer running the authoritative gate; Supervisor
  relying on established Implement CLI integration journeys.
- Expected: the feature's changed universal Verification semantics ship with
  every producer/consumer fixture adjusted to carry a gate that fails before
  work and passes after it, so the existing Clean journeys remain meaningful.
- Actual: `make verify` exits 2. The full log has 51 failed CLI test/subtest
  headings; representative fixtures now stop before their intended Agent path
  because `true`, `echo docs-check`, `echo backend-check`, or a bootstrap-created
  file already passes the new probe. The focused end-to-end reproduction exits
  1 and leaves task_01 failed before task_02 can run.
- Root cause evidence: Task 03 inserted the probe as a universal dispatch
  behavior, but its bounded scope covered daemon tests only. Existing
  `internal/cli/implement_test.go` Task fixtures remained work-independent.
- Affected rows: Q03 and Q04. Q09 independently demonstrates that a correctly
  authored positive-control fixture still reaches the ordinary path.

### F-003 — Coverage-equivalence evidence was left stale

  renamed, and removed test identities introduced by Tasks 01–06.

### F-004 — The declared Vocabulary Contract was not published

### F-005 — Negative-control health stops at parsing
