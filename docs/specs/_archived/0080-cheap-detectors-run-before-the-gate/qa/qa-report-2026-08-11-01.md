- Impact: Blocks-Completion.
- Actor and journey: adopting-repository maintainer running either verification
  tier; QA gate agent receiving changed-path and previous-report context.
- Expected: the public QA TaskCycle reaches its Agent prompt after a clean
  mechanical stage, and both verification targets exit 0.
- Actual: the prompt integration test's shared fixture is an ordinary temp
  directory. The real mechanical stage runs first, `git rev-parse HEAD` exits
  128, the test never observes the prompt, and both targets exit 2.
- Reproduction: run
  `qa/evidence/2026-08-11-spec-0080-rerun-01/R03-daemon-head-reproduction.sh`;
  the focused test exits 1 in under one second.
- Root cause: Task 03 added the real Git-dependent mechanical stage before the
  QA Agent Session without adapting or isolating
  `TestQAGatePromptUsesTaskContextBuilderAndPreviousReportIdentity`, whose
  `newTaskCycleFixture` root has no Git repository. Task 09 repaired seeded
  report selection but did not touch this fixture.
- Affected rows: R03. R02 independently fails on F-004 before F-003 can
  supply integration evidence.
- Required before rerun: make the integration fixture supply the real Git
  precondition or its deliberate mechanical-stage boundary, without bypassing
  production head resolution; then rerun the focused reproduction, both
  verification tiers, R02, and one adjacent blocking-stage canary.
