## Findings

### F-001 — A governed rename bypasses final-push authority

- Impact: Trust-Damage.
- Actor and step: an operator runs `roundfix implement` with auto-push enabled;
  the Task renames governed `Makefile` to ordinary `notes.txt`, commits, then
  reaches the final-push decision under an authorization record that grants
  `implement` and `commit` but omits `push`.
- Expected: final push refuses with `authorization operation "push" is not
  permitted`, as required for a Run that changed a Governed Path.
- Actual: the CLI exited 0, printed `pushed origin/feat/qa-governed_push`, and
  the independent bare-remote reread matched the new local head.
- Reproduction: run `run-public-flow.sh governed_push <rebuilt-binary>
  <evidence-output-root>` from this report's evidence directory.
- Evidence: [public stdout](evidence/2026-09-14-run-e15c7ee8/results/governed_push/stdout.txt),
  [public stderr](evidence/2026-09-14-run-e15c7ee8/results/governed_push/stderr.txt),
  [committed paths](evidence/2026-09-14-run-e15c7ee8/results/governed_push/changed.txt),
  [remote head](evidence/2026-09-14-run-e15c7ee8/results/governed_push/remote-head.txt),
  and [changed-path comparison](evidence/2026-09-14-run-e15c7ee8/prior-changed-comparison.txt).
- Diagnosis: after integration, `PriorChangedFiles` runs `git diff --name-only
  <initial>..HEAD`; Git rename detection returned only `notes.txt`. The final
  push therefore classified no governed path, although the committed
  `--no-renames` reread shows `D Makefile` and `A notes.txt`.
- Affected row: R-09.
