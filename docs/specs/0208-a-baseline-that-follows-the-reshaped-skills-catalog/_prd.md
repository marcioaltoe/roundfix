# A Baseline that follows the reshaped skills catalog

On 2026-10-01 the upstream skills catalog `marcioaltoe/skills` (pull request
#103, commit `b3c45a4`) renamed its setup lists `go-tui` to `go`, `rust-cli` to
`rust` and `typescript-bun` to `typescript`, merged `go-cli` into `go`, and
removed the `review` and `triage` skills and thirteen other skills that Baseline
snapshots still list. Run with `--check` against that commit,
`roundfix baseline assets sync` exits `2` with "Canonical setup source file is
missing." for all four snapshots. The `core` module still requires and
dispatches `review`, and the `typescript` module still requires and dispatches
`triage`. No module requires `typesafe-ai`, so managed repositories never
install it, and only the `typescript` module requires
`crafting-effective-readmes`.

This refactor gives the Baseline the new setup names and drops the removed
skills. It moves what external triage still needs from the `triage` skill into
clauses of the `external-triage` module, and requires both skills in `core`.
It brings this repository to the state an adopter reaches after its next
update. The maintainer asked for it before the next release ("esse ajuste deve
ser feito antes do próximo release"). See ADR-0206. The adopted Finding is
`docs/history/findings/2026-10-01-the-skills-catalog-reshaped-the-baseline-inputs.md`.

## Goals

1. The asset sync against upstream `b3c45a4` reports every snapshot current,
   and a second refresh changes nothing.
2. No module, trigger, activation bundle or snapshot names `review`, `triage`
   or any other skill the catalog removed.
3. External triage keeps, as clauses with force, the functions the `triage`
   skill carried.
4. Every managed repository requires `typesafe-ai` and
   `crafting-effective-readmes`.
5. This repository holds every required skill, and no `review` lock entry or
   tree.

## User Stories

1. As a maintainer, I refresh the Baseline from the upstream catalog and the
   sync accepts it.
2. As an adopter, my next update renders guides that name only skills the
   catalog ships.
3. As an Agent triaging an external forge, I read with force how to classify,
   label, ask, disclose, record and route.
4. As an Agent in any managed repository, I find the TypeSafe and README
   skills installed and dispatched.

## Core Features

1. Core Feature: the three snapshots take their upstream names, the profiles
   take them, and `go-cli` retires (task_01).
2. Core Feature: `review` and `triage` leave `core`, `typescript`, the
   dispatch guides and the snapshots (task_01).
3. Core Feature: the `external-triage` module gains eight clauses with force.
   Its old rule's Source Baseline entry is `replaced` (task_02).
4. Core Feature: `core` requires `typesafe-ai` and
   `crafting-effective-readmes` with triggers (task_03).
5. Core Feature: this repository takes its own update. It restores the two
   skills (task_03), then reconciles away the `review` lock entry and deletes
   the tree (task_04).

## Non-Goals / Out of Scope

- Editing any upstream skill or `~/dev/skills`.
- Renaming a built-in profile identifier.
- Re-pointing the frozen parity fixtures, which record the Python run's setup
  names. Only the sanctioned `asset-sync.json` fixture follows the snapshots.
- Changing `triage.external` from a boolean into a label map.
- Deleting an adopter's installed `review` or `triage` tree.
- The new upstream `content` and `devops` setups, which no built-in profile
  uses.

## Success Metrics

1. Success Metric: `roundfix baseline assets sync --check` against upstream
   `b3c45a4` exits `0`, and the embedded snapshots are exactly `go`, `rust` and
   `typescript`, each listing the Roundfix-owned skill.
2. Success Metric: no catalog module, trigger, bundle or snapshot names
   `review`, `triage`, `resolving-merge-conflicts`, `lesson-learned` or the
   thirteen removed skills of the Finding's section 3. A planted name is
   reported.
3. Success Metric: the Standard TypeScript Monorepo `external-triage.md`
   golden renders the eight clauses with their force. A Source Baseline
   adopter's refresh reports `rule.external-triage` as `replaced`, and the
   same refresh without the declaration is refused.
4. Success Metric: every built-in profile's dispatch guide names
   `trigger.core.typesafe-ai` and `trigger.core.crafting-effective-readmes`,
   and no `typescript` trigger names the README skill.
5. Success Metric: in this repository, Doctor reports `skills: ok (43
   required: 14 Roundfix-owned, 29 external)`, and no lock entry or tree names
   `review`. A second `roundfix baseline update --repo .` reports `current`.

## Declared breaks

- **Break — setup identifiers.** The Setup Manifest of every adopter records
  the new setup name on its next update. A repository-owned profile that names
  `go-tui`, `rust-cli`, `typescript-bun` or `go-cli` as its setup no longer
  loads until it names the new one.
- **Break — guides.** Every adopter's `skill-dispatch.md` loses
  `trigger.core.review` and gains the two `core` triggers. A Standard
  TypeScript Monorepo adopter loses the two `typescript` triggers. An adopter
  with `triage.external` enabled receives eight clauses in place of one rule.
- **Break — required skills.** Every adopter requires `typesafe-ai` and
  `crafting-effective-readmes`. Doctor's `skills:` line fails until the next
  update restores them.
- **Break — parity fixture.** `asset-sync.json` records three setups instead
  of four. The other frozen fixtures still name the setups the Python run
  used.

## Decisions

- **Keep the profile identifiers.** Only setup names moved upstream. See
  ADR-0206.
- **Drop, never rename, a removed skill.** See ADR-0206.
- **Triage functions become clauses.** The label mapping stays
  repository-owned. A `wontfix` decision becomes a declined Backlog Entry. See
  ADR-0206.
- **README skill in `core`.** One trigger serves every stack. See ADR-0206.
- **Dogfood the adopter path.** This repository uses `baseline update` and
  `baseline skills reconcile`, and deletes its own tree.
