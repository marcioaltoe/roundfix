# A profile proof whose session answered passes when only its close fails

Under heavy host load an Exact Agent Selection Proof can finish every setup
step and then fail because closing its disposable Agent Session takes longer
than a fixed 5-second cleanup deadline. The close error fails the proof, the
CLI reads its wrapped deadline as a setup timeout, repeats the whole proof
three times, and parks a pre-PR review or a Delivery Queue item with `profile
proof setup timed out on 3 attempts of 2m0s each`, a message that names a
setup that never timed out. After this Spec the proof's verdict rests on its
setup alone, the close gets the attempt's Proof Setup Deadline, a session
Roundfix could not close is recorded as an Unclosed Proof Session and closed
by a later proof, and a setup timeout names the step that was slow.

## Goals

- A tuple whose disposable session answered every setup step is proven, even
  when acpx is too slow to close the session.
- A session that never answered still fails its proof, with its own
  classification.
- No disposable session Roundfix failed to close is forgotten: it is recorded
  and closed by a later proof.
- A setup timeout names the step that reached the deadline.

## Core Features

1. The verdict is the setup's. A failed or timed-out close after a passing
   setup leaves the proof passed and prints one warning naming the session,
   the deadline and the cause; a failed setup returns its own error.
2. The close deadline is the attempt's Proof Setup Deadline, for the profile
   proof and the Fallback Chain candidate probe.
3. Unclosed Proof Session. A failed close writes a record under
   `~/.roundfix/unclosed-proof-sessions/`; the first proof of each Agent
   runner closes the recorded sessions, deletes each record acpx closes or
   reports absent, and stops at the first failure.
4. A named step. A setup step that reaches its deadline is reported as
   `profile proof step "<step>"`, and a deadline found only in a close error
   is never retried or reported as a setup timeout.
5. Reports. `profiles validate` prints the warning under its proof in text
   and carries it as `warning` in `roundfix/profiles-validate/v1` JSON.
   Baseline semantic analysis still falls back to manual classification when
   a proof left its session open.

## User Experience

An operator whose machine is overloaded sees the queue pass Preflight where
it used to park, with a line on stderr such as `disposable Agent Session
"roundfix-preflight-…" was not closed within 2m0s after its profile proof:
…; recorded in ~/.roundfix/unclosed-proof-sessions/roundfix-preflight-….json
for the next profile proof to close`. The next command that proves a profile
closes it first. When a setup really times out three times, the refusal ends
with the step, for example `profile proof step "apply session selection":
context deadline exceeded`.

Declared behavior changes: a proof that used to fail with
`session_cleanup_failed` after a passing setup now passes with a warning;
`profiles configure` and Setup can therefore write a profile they used to
refuse; a failed setup's error no longer carries the close error; a proof
attempt may wait up to its setup deadline for the close instead of 5
seconds; `profiles validate` JSON gains the optional `warning` field.

## Non-Goals / Out of Scope

- Changing the three attempts, their backoff or the setup deadline's key,
  default and bounds (ADR-0298).
- Proving fewer tuples or activating a Fallback Chain before Run creation.
- The cleanup of sealed prompts, Run, QA and review sessions, and Process
  Residue reporting.
- Closing open `roundfix-preflight-*` sessions that earlier releases left
  without a record.
- Reporting the host load average in the refusal (ADR-0344, Considered
  Options).
- A Doctor check or a GC step for Unclosed Proof Session records.

## Success Metrics

1. Success Metric: with a fake acpx whose `sessions close` blocks past the
   close deadline after a passing setup, the proof returns no error, its
   result names the unclosed session, one warning is printed and one record
   exists.
2. Success Metric: with a fake acpx whose setup is rejected and whose close
   fails, the proof's error is the setup's rejection and holds no close
   error, and a record exists.
3. Success Metric: a later proof of a new runner closes a recorded session
   before it opens its own and deletes the record; a failed close keeps it
   and stops the reaping.
4. Success Metric: the CLI never retries a proof whose only deadline is in a
   close error, and a setup timed out on 3 attempts names its step.
5. Success Metric: `profiles validate` reports the warning in text and JSON.
6. Success Metric: after release, Vortex or this repository's Delivery Queue
   under load runs a pre-PR review without a profile-proof park caused by a
   close timeout.

## Validation

Characterized on 2026-10-27 at `5e9475bf`.

- A scratch test (removed afterwards) drove `ProveExactSelection` with the
  fake acpx harness, a passing setup and `sessions close` blocked, with a
  300 ms cleanup deadline: it returned `close disposable Agent Session
  "roundfix-preflight-…": close acpx Agent Session "…": context deadline
  exceeded; recovery: rerun Agent Selection readiness after the Session can
  be closed`, an `*AgentSessionCleanupError` for which
  `errors.Is(err, context.DeadlineExceeded)` is true.
  `profileProofSetupTimedOut` (`internal/cli/profiles_validate.go`) accepts
  exactly that, so `proveProfileSelectionWithRetry` repeats the proof and
  wraps the third result in `profileProofTimeoutError`, the incident's
  message.
- `ProveExactSelection` (`internal/agent/selection_assignment.go`) and
  `probeFallbackCandidate` (`internal/agent/fallback.go`) close under
  `disposableCleanupTimeout()`, `acpxPreflightCleanupTimeout` = 5 s
  (`internal/agent/acpx_runner.go`), and return the close error, joined with
  a setup error when both fail.
- Setup steps return a bare `context.DeadlineExceeded` (for example
  `startSessionSelectionWithEnsure` and `applyDisposableEffort`), so a
  setup timeout does not say which step was slow.
- No code closes a disposable session later: `rg -n 'roundfix-preflight|acpxPreflightSessionPrefix' internal -g '!*_test.go'`
  finds only the name generator; `ListRoundfixSessions` serves Run session
  cleanup by Run id.
- This machine's acpx store on 2026-10-27 held 157 open and 3,669 closed
  `roundfix-preflight-*` records (152 of the open ones with their adapter
  exited), 27 of the open ones created that day: sessions earlier proofs
  never closed. A read-only census script in the operator's scratch
  directory counted them.
- `acpx --cwd /nonexistent/dir/x codex sessions close roundfix-preflight-doesnotexist`
  printed `No named session … for cwd /nonexistent/dir/x and agent codex`
  and exited `1`: a close addresses the record by name and working directory
  string, so a record whose item worktree is gone can still be closed.
- Baseline semantic analysis (`internal/baselineacp/analyzer.go`,
  `cleanupUnproven`) stops on an `AgentSessionCleanupError` from a proof; a
  proof that passes with an unclosed session would bypass that stop unless
  the analyzer checks it.
- Secondbrain, read only: `wiki/index.md`; `qmd query "roundfix profile proof
  disposable session close timeout load" --all --files --min-score 0.3`
  returned only mirrors of this repository's profiles guide, glossary and
  ADR-0140.
- Exa: the acpx sessions guide passages quoted under Acceptance evidence.
