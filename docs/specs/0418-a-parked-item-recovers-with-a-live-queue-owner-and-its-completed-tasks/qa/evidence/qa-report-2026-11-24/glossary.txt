Line 975: **Delivery Retry**:
The explicit act that returns one parked Delivery Queue item to the stage supported by its recorded evidence and ends with a Queue Owner proven alive, or fails and parks the item again as it was. It may perform Task Carry-Forward from every Run of the item's Spec, newest first, and is never automatic. It refuses a Spec whose Archive Record is `cancelled` ([ADR-0262](docs/adr/0262-a-cancelled-spec-leaves-an-archive-record-and-returns-its-sources.md)). An item parked before it has an Item Branch returns to `queued`, and its owner creates the branch as on a first start ([ADR-0398](docs/adr/0398-a-parked-item-always-has-a-way-back-through-a-delivery-retry.md)) ([ADR-0450](docs/adr/0450-a-delivery-retry-ends-with-a-live-queue-owner-and-status-reports-a-queue-nobody-advances.md)).
_Avoid_: Resume Command, automatic retry, replay

Line 896: **QA-Only Failed Run**:
A terminal Implement Run whose outcome is Failed, whose Run Branch exists and holds a loadable committed Task Graph with a QA gate's Task not completed and every other Task completed. A Delivery Retry accepts its completed Tasks under the Task Carry-Forward proofs and never carries the QA gate's Task ([ADR-0450](docs/adr/0450-a-delivery-retry-ends-with-a-live-queue-owner-and-status-reports-a-queue-nobody-advances.md)).
_Avoid_: Failed Run with unfinished implementation, QA row carry-forward

Line 939: **Queue Owner**:
The `roundfix deliver` process that holds one Delivery Queue and advances its items in order, one item at a time through every stage except the pre-PR review, which it runs for up to its Review Capacity of items at once. It waits on each Prerequisite Spec and starts a queued item only when no earlier item is between its Implement Run and its merge; a Delivery Retry hands a parked item to the live Queue Owner or starts a new one, and a live owner finds a retried item within 30 seconds ([ADR-0365](docs/adr/0365-the-pre-pr-review-gets-its-own-capacity-and-status-shows-each-items-turn.md)). When an item can still advance, `roundfix deliver status` reports a recorded Queue Owner proven not running by its PID and start-time identity; status never reclaims it, so the item can still advance after `roundfix deliver resume` ([ADR-0279](docs/adr/0279-status-reports-a-queue-owner-proven-gone-and-a-dismissal-survives-a-fix-that-leaves-its-anchor.md)). A Queue Owner that stops while an item can still advance keeps that record, so the report names it ([ADR-0395](docs/adr/0395-a-queue-item-stops-only-for-its-own-work.md)). Status also reports a queue with no recorded owner while an item can still advance, and the Active Run and Tasks in progress of each item at `running` ([ADR-0450](docs/adr/0450-a-delivery-retry-ends-with-a-live-queue-owner-and-status-reports-a-queue-nobody-advances.md)).
_Avoid_: Scheduler, daemon, deliver loop

Line 900: **Task Carry-Forward**:
The explicit act that hands a settled Task from a terminal Spec Run's Run Branch back to the user's checkout, so work that already ran and passed its Verification is never executed again to reach the same result. It accepts a Run whose outcome is Stopped, Unresolved or Budget Exceeded ([ADR-0158](docs/adr/0158-a-budget-expired-run-settles-budget-exceeded-and-stays-recoverable.md)) and refuses every other terminal outcome through the Reconcile Command and the Implement Command's Preflight; a Delivery Retry also accepts a QA-Only Failed Run. It carries a Task only on proof — a passing Verification verdict, exactly one settlement commit, declared inputs unmoved since settlement except planning amendments that preserve its Binding Text ([ADR-0284](docs/adr/0284-carry-forward-binds-a-task-to-the-planning-text-it-references.md)), a clean checkout, and a repository-local Spec Root — refuses the whole set rather than carrying part of it, and stamps each carried Task with the Run and commit that established it. Reached through the Reconcile Command's `--carry-forward` switch or through a Delivery Retry; it is never automatic. A Task already completed on the target is nothing to carry, so the act does not repeat itself. The implementation spelling `CarryForward` refers to this same term ([ADR-0450](docs/adr/0450-a-delivery-retry-ends-with-a-live-queue-owner-and-status-reports-a-queue-nobody-advances.md)).
_Avoid_: replay, resume, automatic carry, QA row carry-forward
