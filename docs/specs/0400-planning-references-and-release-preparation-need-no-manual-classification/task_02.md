# Task 02: The release guides describe both rules and keep the repository's own publication trigger

## Overview

The release plan's usage text, the Roundfix skill's release reference and
`SKILL.md`, the release runbook, the usage page and the glossary describe
`docs/references/` as planning evidence and the **Release-Preparation
Commit**. The release reference stops telling every adopter to preserve a
tag-triggered workflow: it keeps the trigger the repository already uses,
a pushed tag or the merge of the version change, and asks that
`release_paths` list every file the preparation commit changes. The skill
mirror, the owned-skill version record and the Behavior Surface Record are
regenerated by their sanctioned commands, and a test pins the new release
reference text in both copies.

## Requirements

1. MUST add to the `release plan` usage text in `internal/cli/cli.go`, as
   its own paragraph right after the paragraph that says when
   `approval_required` is answered, exactly the text of `_techspec.md` →
   API Contract 4.
2. MUST change `.agents/skills/roundfix/references/release.md`, section
   `## Release planning`, as `_techspec.md` → API Contract 5 says:
   - the paragraph that begins "Backlog Entries under `docs/backlog/`"
     names outside evidence under `docs/references/` as planning evidence
     beside the five directories, and then says that a Release-Preparation
     Commit, a commit with no automatic impact whose every changed path is
     a `release_paths` entry of a Spec the range delivers with a Release
     Ceiling, is maintenance-only too, and that JSON marks it
     `releasePreparation: true`; it keeps the sentence on a `refactor:`
     delivery;
   - the paragraph on the record adds: list in `release_paths` every file
     the release-preparation commit changes, including a lockfile or a
     generated file the release regenerates, because a preparation commit
     that changes any other path is a commit to classify by hand;
   - the last paragraph of the section tells the session to follow the
     repository release runbook and keep the publication trigger the
     repository already uses, and describes both: a workflow that publishes
     when a version tag is pushed, where the tag is validated and artifact
     versions agree before it is pushed; and a workflow that publishes when
     the release Pull Request that changes the version merges to the
     default branch, which writes the tag and the release itself, so no tag
     is created by hand. It keeps "publish packages and release assets only
     through the repository's release workflow" and "leave the Upgrade
     Command asset contract unchanged", and drops the sentence "Preserve
     the existing tag-triggered workflow".
   It MUST leave the section `## Completion notices` byte-identical.
3. MUST change the sentence "Backlog Entries are planning evidence." in
   `.agents/skills/roundfix/SKILL.md` to name `docs/references/` and the
   Release-Preparation Commit in one or two sentences, and change nothing
   else there by hand.
4. MUST give `docs/user-guide/release-runbook.md` and
   `docs/user-guide/usage.md` the same planning-evidence paragraph as the
   release reference, and the runbook the same `release_paths` sentence.
   The runbook keeps its tag-triggered publication steps, which describe
   Roundfix's own workflow, and the words "tag-triggered" and
   "publication workflow" that `internal/docscontract` pins.
5. MUST add to `CONTEXT.md`, through `domain-modeling`, the glossary entry
   **Release-Preparation Commit** beside **Release Ceiling**, in the form
   of its neighbours: a commit with no automatic release impact whose every
   changed path is a `release_paths` entry of a Spec the range delivers
   with a Release Ceiling, such as the commit that writes the changelog and
   the version files; the Release Plan counts it as maintenance-only
   (ADR-0412); with an `_Avoid_` line. MUST change no other glossary entry.
6. MUST add `skills/roundfix_release_reference_test.go` with
   `TestTheReleaseReferenceKeepsTheRepositoryPublicationTrigger`, calling
   `t.Parallel()` first, one subtest per copy that `roundfixLayoutSources`
   returns, asserting with `roundfixWhitespace` that the `Release planning`
   section names `docs/references/`, `Release-Preparation Commit`,
   `releasePreparation: true`, the merge of the version change and a pushed
   tag, and no longer contains "Preserve the existing tag-triggered
   workflow".
7. MUST regenerate, never hand-edit, with the commands of
   `_authorization.md` → Sanctioned regeneration, in this order:
   `make skills-sync`; the `-record-skill-versions` step
   (`go test ./skills -run '^TestEveryOwnedSkillVersionIsRecorded$' -record-skill-versions`),
   which raises the Roundfix skill's version in both `SKILL.md` copies and
   the version record; and the `-record-skill-coverage` step
   (`go test -count=1 -tags docscontract ./internal/docscontract -run '^TestTheSkillCoverageMapIsCurrent$' -record-skill-coverage`),
   which records the `command release plan`, release runbook and usage
   page surfaces in `docs/references/behavior-surfaces.json`.
8. MUST change no file outside the ones this Task declares; the only
   Governed Paths it changes are the three in `_authorization.md` `paths`.
