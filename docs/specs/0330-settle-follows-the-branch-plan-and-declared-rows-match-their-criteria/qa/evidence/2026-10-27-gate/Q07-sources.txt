# A declaration covering two criteria is refused, and settle reads the Run Worktree's plan

## Symptom

A QA Report whose two declared-blocked rows both fall under one
`## Unreachable Acceptance` declaration is refused by
`roundfix qa-report accept` with `rows_blocked_declared is 2, but Spec
declares 1 unreachable acceptance`, because acceptance compares counts
instead of the criteria each declaration names. After the author splits the
declaration on the branch, `roundfix settle --task <qa task>` still reads the
old PRD from the kept Run Worktree, and refuses again, until the author moves
that worktree to the new commit by hand.

## Where

`internal/spec/qa.go` `QAReportEligibility` (the count comparison that
`roundfix qa-report accept`, `roundfix settle`, Daemon settlement and
`roundfix archive` share); `internal/spec/spec.go`
`parseUnreachableDeclarations` (one `criterion:` per declaration);
`internal/cli/settle.go` `preflightSettle` and `resolveSettleSurface` (the
Spec is loaded from the settle surface only).

## Expected

One declaration covers each criterion it names, and acceptance matches each
declared-blocked row to a declaration naming its criterion; `write-prd` and
`qa-gate` say that each criterion becomes its own QA row. Settle reads the
plan the branch carries when the branch is ahead of the Run Worktree.
