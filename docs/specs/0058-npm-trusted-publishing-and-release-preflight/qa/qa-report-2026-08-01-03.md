## Findings

### QA-005 — Retained npm token is injected into the entire publish step

- Impact: Trust-Damage.
- Actor and step: release maintainer, `Publish to npm` before the bounded
  fallback branch is selected.
- Expected: Task 04 Requirement 1 forbids unconditional token exposure to the
  publish stage, Requirement 4 confines the token secret reference to the
  fallback branch, and its first acceptance criterion requires the secret to
  appear only inside that branch.
- Actual: the current workflow maps `${{ secrets.NPM_TOKEN }}` to step-level
  environment variable `NPM_TOKEN`, making the retained credential available
  to every command in `Publish to npm`. The generated shell references
  `$NPM_TOKEN` only in the fallback command, never prints the sentinel, and
  does not pass it to the first npm calls, but the step-wide exposure still
  contradicts the declared credential boundary.
- Reproduction: run `rtk ruby
  docs/specs/0058-npm-trusted-publishing-and-release-preflight/qa/evidence/2026-08-01-qa-03/secret_boundary_probe.rb`.
- Evidence: `local-workflow-probes.md`, `secret_boundary_probe.rb`, and
  `.github/workflows/release.yml`.
