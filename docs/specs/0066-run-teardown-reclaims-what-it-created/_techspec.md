# Run teardown reclaims what it created — Technical Spec

## Executive Summary

Two debris kinds, two existing seams, no new command. Process-tree termination
extends `OwnerProcessControl` in `internal/store`, which already proves owner
identity and waits for absence but reaches only the recorded PID. Run Branch
set classification extends `internal/worktree`, whose `supersedingQAReport`
already proves a single branch holds nothing but an obsolete QA report; the
gap is several such branches at once.

The reclamation surface is `reconcile`, not a new command. It is already
dry-run first, already enumerates without a Run ID, already preserves
ambiguity, and already refuses to apply anything it did not itself inspect.
Adding a second candidate kind to a command with that posture is cheaper and
safer than minting a surface that must re-learn all four properties.

The trade-off accepted: process termination can prove absence but cannot always
prove *why* a process is absent. A host that cannot answer is reported as
unproven, never as terminated — ADR-0044 depends on that distinction to reclaim
orphaned locks, and collapsing it would make a silent host look like success.

## System Architecture

```mermaid
flowchart TD
    STOP[Stop / terminal Run] --> PC[store.OwnerProcessControl]
    PC --> TREE[descendants Roundfix started]
    TREE --> PROOF[per-process: proven gone | unproven]
    PROOF --> ADR44[ADR-0044 lock reclamation reads this distinction]
    REC[cli: reconcile] --> WT[worktree: Run Branch set on one target]
    WT --> NEWEST[newest carries current evidence]
    WT --> OLDER[older superseded-only branches releasable]
    REC --> PROC[orphaned process candidates]
    BIP[Branch Integrity Preflight] --> SPLIT[blocking work vs superseded accumulation]
```

## Implementation Design

### Interfaces

```go
// store: termination reaches the tree, and reports per process.
type TerminationOutcome struct {
    PID      int
    Proven   bool   // absence observed
    Reason   string // why it could not be proven, empty when Proven
}

// TerminateTreeAndWait terminates the descendants Roundfix started for this
// Run and returns one outcome per process. It never reports an unprovable
// termination as success.
func (c *OwnerProcessControl) TerminateTreeAndWait(
    ctx context.Context, pid int, recordedIdentity string,
) ([]TerminationOutcome, error)
```

```go
// worktree: classify the Run Branches of one target together.
type BranchSetClassification struct {
    Current    string   // the Run Branch holding current evidence
    Releasable []string // superseded-only branches, proven
    Preserved  []string // anything ambiguous, with a reason each
}

func ClassifyRunBranchSet(
    ctx context.Context, runner gitRunner, gitRoot, targetBranch, specSlug string,
) (BranchSetClassification, error)
```

### Data Models

No persisted state. `TerminationOutcome` is returned, logged through the
existing Run Event Stream, and never written to the Run Database as a new
column.

### API Contracts

`reconcile` gains process candidates beside worktree candidates. Its existing
contract is unchanged: dry-run by default, `--apply` acts, every candidate
carries its proof, ambiguity is preserved, and `--format json` keeps its
schema with the new candidate kind added additively.

Branch Integrity Preflight keeps every refusal it makes today except one: a Run
Branch proven to hold only a superseded QA report no longer blocks a review
Run. That is the Spec's declared break.

## Coverage Map

- Core Feature 1 (termination reaches the tree and reports) →
  `TerminateTreeAndWait` and `TerminationOutcome`.
- Core Feature 2 (unprovable reported distinctly) → `Proven` plus `Reason`, and
  the ADR-0044 distinction preserved.
- Core Feature 3 (Run Branch set classification) → `ClassifyRunBranchSet`.
- Core Feature 4 (Preflight splits blocking from superseded) → the declared
  break in Branch Integrity Preflight.
- Core Feature 5 (dry-run first, proof per candidate, preserve ambiguity) →
  `reconcile`'s existing posture extended to the new candidate kind.
- Core Feature 6 (discoverable without a Run ID) → `reconcile` already
  enumerates without one.
- Goal "nothing reclaimable is reclaimed while it could still be in use" → the
  Active Run guard on every path.

## Testing Approach

The seams exist: `internal/store` re-executes a test binary as a helper
process, and `internal/gittest` builds real repositories. No new seam is needed.

- **A child that outlives its immediate parent**, which is the exact shape
  found running after three days and six hours. The fixture must start a
  grandchild, kill the middle process, and assert the grandchild is gone.
- **The unprovable case**, asserted distinctly from the proven one, because
  ADR-0044 reads that distinction and a silent host must never look like
  success.
- **Four failed-cycle Run Branches on one target**, the Spec 0053 shape:
  assert the newest is `Current`, the three older are `Releasable`, and a
  `watch` proceeds afterwards without any ref being hand-deleted.
- **The Active Run guard**, injected on every reclamation path.
- **Idempotence**: a second reconcile pass after applying is a no-op.

## Build Order

1. **Process-tree termination** — `TerminateTreeAndWait`, per-process outcomes,
   the outliving-grandchild fixture, and the unprovable case.
2. **Run Branch set classification** (depends on: 1 only for ordering) —
   `ClassifyRunBranchSet` and the four-branch fixture.
3. **Preflight split** (depends on: 2) — the declared break, with every other
   refusal asserted unchanged.
4. **Reconcile candidates** (depends on: 1, 2) — the new candidate kind, its
   proof, dry-run and apply, idempotence.
5. **Skill synchronisation** (depends on: 3, 4) — the authorized Skill update
   and its regeneration chain.

## Risks & Considerations

- **Killing more than Roundfix started.** The Non-Goals forbid terminating
  processes Roundfix did not start, and the tree walk must be bounded by
  recorded ownership rather than by process group alone.
- **Collapsing unprovable into terminated.** ADR-0044 depends on the
  difference. This is the assertion most worth writing first.
- **The declared break is a Preflight relaxation.** Every other refusal must be
  asserted unchanged, because relaxing a guard is where a regression hides.
- **`reconcile` grows a second candidate kind.** Its four safety properties —
  dry-run default, proof per candidate, preserve ambiguity, refuse
  uninspected applies — must hold for the new kind without being re-derived.

## Decisions

- Reclamation extends `reconcile` rather than minting a command, because that
  command already has the four safety properties this Spec needs.
- Termination proves absence per process; an unprovable termination is
  reported, never treated as done. See ADR-0044.
- Set classification reuses the existing superseded proof rather than
  introducing a second notion of obsolescence.
