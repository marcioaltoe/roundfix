The repaired paths do not justify a retention shape beyond the existing age

The measurement supports that decision for two separate reasons. Run-start

did increase after machine-wide writer serialization, but its after values are
flat across 0, 1,000, and 10,000 journal events. Reducing retained payload
bytes would therefore repair neither measured residual: the Run-start scan is
already bounded, and the remaining concurrent-write cost is independent of
journal size.

## Retention decision

Keep the current retention shape: complete journals remain available until a
terminal Run crosses the configured age window, then the existing GC boundary
may remove the journal. Add no payload side table, second window, compression,
rewrite, or early payload deletion.

Shedding agent payloads would make retroactive rich rendering and replay from
raw ACP updates unrecoverable during the new shorter window. ADR-0030 removed
the default per-Batch agent logs because the Run Event Journal is already the
durable copy, so there is no redundant source from which to recover that
capability. The repaired measurement shows no size-dependent hot-path cost
that would buy this loss. ADR-0008 therefore needs no amendment, and the
reconcile replay probe's payload-equality key needs no change.

Nothing an operator observes changes in this Task. The machine-checked durable
table set, schema, GC boundary, CLI output, and retention configuration are
unchanged, so `docs/user-guide/run-database-lifecycle.md` remains untouched.

## Limits

- The append harness measures direct `AppendRunEvent` calls, not end-to-end
  JournalWriter batching. It supports the retained-size comparison and exposes
  serialization cost; it does not measure amortized agent-output throughput.
- The largest fixture remains 10,000 events. The result establishes that the
  repaired query no longer follows the measured size curve; it does not
  extrapolate an exact latency for the earlier 1.6-million-event database.
- `SQLITE_BUSY = 0` is the observed result at the unchanged 30-second timeout.
  Task 07 separately exercises six parallel Runs at the pre-raise timeout.
