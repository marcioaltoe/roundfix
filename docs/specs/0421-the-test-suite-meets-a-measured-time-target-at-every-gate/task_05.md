# Task 05: Run the final QA gate

## Overview

This is the authored terminal gate for this Spec. It declares what the matrix covers and settles the Spec on evidence. The Spec gives each gate of this repository a Gate Time Target: a Task settles on the light checks, the Complete Suite Run happens once per Spec at the Delivery Queue's repository gate, a pull request runs the packages its change reaches and every Repository Contract Test once, continuous integration runs only for a pull request in five parallel jobs on `macos-26`, a release runs no test and proves its Release Provenance, and each gate reports its time. Four nested test runs leave the code tests, binaries and corpora are built once, four waiting tests end on their event, ADR-0453 supersedes ADR-0387 and amends six records, and the glossary, the guide and the runbook follow. No product command, flag, key, exit code, Run Database table or Daemon behavior changes.

Every row runs on this repository's own files, temporary Git repositories, temporary copies of the audited head or of the Delivery Base, and the Run Worktree the gate runs in. No row:

- starts an Agent harness, an Agent session, an Author Subagent or an ACP adapter, or asks a person a question;
- starts a real Run, a Daemon or a Delivery Owner outside a test's own temporary home;
- runs the real `gh`, calls ai-memory, the Indexus or any MCP server, or reaches the network, GitHub included;
- reads another repository, or reads or writes the real `~/.roundfix`;
- signals a process it did not start, or ends a process by name;
- sends a message or a request to a provider, the judge or a reviewer;
- reads a credential.

No `go test` it runs carries a `-timeout` other than the `20m` a contract invocation of the `Makefile` carries today; a code-test invocation carries none.

The gate follows the `qa-gate` section "A fresh home keeps the host toolchains". Every `go test` run, every `make` target, the lab protocol and the repository Verification keep the session's own `HOME` and `TMPDIR`. Only a row that runs a built tool from a temporary copy uses a fresh `HOME`, prepared this way: before `HOME` changes it takes `m="$(go env GOMODCACHE)"` and `c="$(go env GOCACHE)"`; it sets `HOME` and `TMPDIR` to fresh temporary directories outside the checkout with `GOMODCACHE="$m"` and `GOCACHE="$c"`, which the command only reads; it puts first on `PATH` a temporary directory holding an executable `gh` that writes nothing and exits 1; it unsets `GH_TOKEN`, `GITHUB_TOKEN`, `TYPESAFE_API_KEY` and every Judge Key Variable; and it removes the temporary directories afterwards. A command that fails only because a fresh `HOME` hid a toolchain is a gate error, never an environment block. A temporary copy of the audited head or of the Delivery Base is made with `git archive` of that commit and committed in a fresh Git repository outside the checkout, because the suite guard refuses a tree outside Git. The QA never writes into the checkout while a test suite runs. It keeps its evidence under names the repository does not ignore, `.txt` for command output, and links only files it kept. Evidence records environment variable names, never their values.
