Roundfix should cut how much of the maintainer's weekly Claude limit long orchestration sessions consume, and adopt in Roundfix itself the per-phase authoring model declaration that Spec 0392 shipped.

Measured on 2026-11-14 (ai_usage.py, ccusage): long Supervisor sessions resend 270k-340k tokens of context per call; 61% of one account's limit went to main sessions and 52% of another's to Fable authoring. Decisions already taken by the maintainer on 2026-11-14: orchestration runs on Opus at medium effort (done in user config); one Supervisor session per Spec; never several Fable authorings in parallel; automatic proactive compaction is refused because it loses important information. Scope wanted for this Spec: (1) each Run writes its Run id and current phase to a fixed, documented place so the operator's usage script can attribute limit consumption per Run and per phase exactly; (2) the Supervisor closes its session at each phase boundary (after the PRD, TechSpec, Tasks, each Spec delivered) with an ai-memory handoff and continues in a fresh session carrying only what the next phase needs; (3) Roundfix declares skills.authoring.claude in its own .roundfixrc.yml so its authoring phases run on the decided models (Fable xhigh for Idea, PRD and TechSpec; Fable high for Tasks; a cheaper researcher subagent).
