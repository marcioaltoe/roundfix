# Task: Every QA Report names its auditor, not only a refusal

Corrective, from QA finding F-001. task_02 recorded the auditing binary in the
precondition-refusal writer, which is one of three producers. The normal report
the Daemon materializes and the template an Agent fills both still record only
the audited commit, so the ordinary report — the one a maintainer actually reads
— cannot attribute its findings to a named auditor. The Spec's own gate had to
add the keys by hand to satisfy its matrix.

## Work

- The Daemon's normal-report materialization records the auditing binary and its
  staleness in the frontmatter it writes, beside the blocked-cause counts.
- The QA gate skill's report template carries both keys beside `build:`, so an
  Agent filling it produces the same shape the Daemon does. One report contract,
  not two that drift.
- Keep `build:` as the audited tree. The two facts stay distinct and separately
  named; collapsing them is the confusion this Spec exists to remove.
- Update the Daemon expectation that encodes the old frontmatter, deliberately:
  the report contract is intentionally changing, and the assertion must state
  the new contract rather than be relaxed around it.
- Change no verdict rule, no row contract, and no blocked-cause count.
