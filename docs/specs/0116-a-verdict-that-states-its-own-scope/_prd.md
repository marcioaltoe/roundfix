# A verdict that states its own scope

A Spec author runs the Spec Consistency Check, reads `No findings.`, and treats
the graph as checked. The check never ran a single authored Verification
command, so a command that passes against the unchanged tree survives it, and
the Daemon's pre-work probe refuses that Task at the starting line one Run
later. A maintainer reads a QA Report and cannot tell which Roundfix produced
it, so a finding raised by a binary older than the tree it audits is
indistinguishable from a real one. Both are the same defect: a verdict that
reports less than the reader takes it to mean, and does not say so where the
reader is looking.

## Project Constraints

- Identifier strategy: applicable — Spec Consistency Check, Verification, QA
  Report, and Verdict are glossary terms this Spec reports on, and a message
  that invents a synonym for one of them is a defect. The closing node checks
  whether the work introduced or changed a term the glossary should carry.
  Source: `docs/agents/domain.md`.
- Authentication and HTTP: not applicable — no network boundary, credential, or
  request is created or read. The work is checker reporting, authoring
  guidance, and report provenance. Source: `docs/agents/specific-repository.md`.
- Active ADR obligations: applicable — ADR-0148 already decides that authoring
  and Run time share one Verification prober precisely so that a checker cannot
  approve what the probe later refuses; this Spec closes the remaining half,
  which is that the shared prober is never reached from the authoring path the
  skills name. ADR-0135 makes an absent diagnostic a reported state rather than
  an empty message, and this Spec applies the same principle to an unrun check.
  ADR-0096 asks the gate to prove machine facts before spending an Agent turn.
  ADR-0117 places a defect's check at the stage that can produce it, which is
  the obligation this Spec is most directly accountable to: a vacuous
  Verification is produced during authoring, so authoring is where it must be
  refused. Source: `docs/agents/domain.md`.
- Tooling authority: applicable — this Spec edits Roundfix-owned authoring
  skills, which are protected tooling. Express maintainer authorization:
  granted 2026-08-26 in session, for the four authoring skills. Bounded files:
  `.agents/skills/write-tasks/SKILL.md`, `.agents/skills/qa-gate/SKILL.md`,
  `.agents/skills/write-prd/SKILL.md`,
  `.agents/skills/write-techspec/SKILL.md`. Their mirrors under `skills/` are
  regenerated by the declared `make skills-sync` and are sanctioned fallout,
  not separate targets. Source: `docs/agents/agent-instructions.md`.

## Goals

1. An author who follows a Roundfix authoring skill reaches the Verification
   prober, rather than the form of the check that skips it.
2. A clean check verdict cannot be read as coverage the check did not perform.
3. A QA Report names the Roundfix that produced it, so a finding can be
   attributed to the binary that raised it.
4. The defect class ADR-0148 exists to remove stops recurring in repositories
   that follow the shipped skills.

## User Stories

1. As a Spec author decomposing a Task Graph, I want the check the skill tells
   me to run to exercise my authored Verification commands, so that a command
   which cannot fail is refused while I am still authoring rather than a Run
   later.
2. As a Spec author reading a clean verdict, I want the check to say what it did
   not do where I read the result, so that I do not end my checking on a partial
   pass.
3. As a maintainer reading a QA Report, I want to know which Roundfix produced
   it, so that I can tell a finding raised by a stale auditor from a finding
   about my code.

## Core Features

1. **The authoring skills name the probing form of the check.** Every
   Roundfix-owned authoring skill that instructs the author to run the Spec
   Consistency Check names the form that runs the authored Verification
   commands. The skill that owns the Verification contract states that a clean
   verdict from the non-probing form does not cover the vacuity class, and stops
   describing the check's speed as a property the author should prefer, because
   that speed is a consequence of the omission.
2. **A skipped probe is reported beside the verdict, not after it.** When the
   check produces no findings and did not run the authored Verification
   commands, the result states that in the same place the verdict is read, and
   in terms that name what was not covered. A reader who stops at the verdict
   line still learns the check was partial.
3. **A QA Report records the Roundfix that produced it.** The report carries the
   identity and version of the binary that ran the gate, distinct from the
   commit of the tree it audited. A reader can attribute every mechanical
   finding in the report to a named auditor.
4. **A stale auditor is visible to the reader of its findings.** When the
   binary producing a QA Report is older than the tree it audits, the report
   says so where its findings are read. What "older" means is a design decision
   for the TechSpec; the requirement is that the reader is not left to discover
   it by reading source.

## User Experience

Not applicable — no browser or interactive surface. The affected surfaces are
the Spec Consistency Check's terminal output, the QA Report artifact, and the
rendered authoring guidance.

## Non-Goals / Out of Scope

- Task collision at integration. Two Tasks a graph declares independent that
  edit the same file and die at integration is owned by Spec
  `0097-a-wave-that-cannot-collide`, which names it in its own problem
  statement. This Spec adopts none of it.
- Changing what the Verification prober classifies, or how the Daemon's
  pre-work probe behaves. ADR-0148 settled the shared prober; this Spec changes
  which callers reach it and what the caller reports, never the classification.
- Changing the QA gate's verdict rules, its row contract, or which checks it
  runs. Only the report's record of its own producer is in scope.
- Refusing to run when the auditing binary is stale. Making the condition
  visible is in scope; deciding to block on it is not.
- The QA Task's authored Verification never being executed, and the Daemon
  holding a green-tree precondition with no postcondition. Both are unresolved
  Roundfix defects recorded as pending Inbox Entries; both need Triage and
  independent measurement in this repository before a Spec commits to them.

## Success Metrics

- The measured authoring sessions stop losing Runs to this class. On
  2026-08-25/26 in this repository, five of eight authored Verification commands
  in Spec 0098 and six of six in Spec 0113 were vacuous or non-hermetic past a
  check that reported `No findings.`, costing three Unresolved Runs. An author
  following the amended skills reaches a refusal during authoring instead.
- A QA Report produced by any Roundfix names that Roundfix, proven by reading
  the artifact rather than the process that made it.
- The 2026-08-14 finding's second observation — that a partial detector is read
  as a gate — no longer holds for the shipped authoring path.

This PRD was itself written into the defect it describes, which is the closest
measurement available. Its author ran the stage-scoped check, read
`No findings.`, and reported the artifact as validated. `SC-ADR-RELATED` was in
that run's skipped list, and the full unscoped sweep raised it: ADR-0117 was
unaccounted for. The stage-scoped run did print its skips, and they were read
past. A check that lists twelve skipped detectors under a clean verdict states
its scope truthfully and still loses the reader, which is why Core Feature 2 is
about where the scope is reported and not only whether it is.

## Decisions

- The fix reaches the author through the skills rather than by changing the
  check's default alone, because the skills are what an author follows and they
  currently name the incomplete form in four places. Changing a default without
  changing the guidance would leave the guidance wrong.
- Stale-auditor visibility is scoped to reporting, not to refusal. A gate that
  refuses on auditor age would have blocked every Run in the measured session,
  including the ones that were correct.
- The two pending Inbox Entries in the same defect family are named in Non-Goals
  rather than absorbed, because their measurements come from other repositories
  and were not reproduced here. Adopting unreproduced evidence would put claims
  in this Spec that its own gate cannot verify.

## Open Questions

- Whether Core Feature 2's report belongs on every clean verdict or only when
  the graph contains authored Verification commands the probe would have run.
  The default until answered is every clean verdict, because an author cannot
  know which case they are in without already knowing what the check skipped.
