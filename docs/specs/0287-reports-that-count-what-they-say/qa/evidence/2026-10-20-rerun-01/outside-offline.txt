# An Archive Record summary ends at the colon that introduces its list

## Symptom

The Archive Record of Spec 0282 ends mid-sentence: "Two environment gaps
failed it:". The record's summary is the PRD's title paragraph, and that
paragraph introduces a list of the two gaps that the summary leaves out. On
2026-10-20, 38 of the 256 Archive Records under `docs/history/specs/` ended
with a colon.

## Where

`internal/spec/archive_record.go`, `archiveParagraph`: it collects the lines
of one paragraph and stops at the first blank line or heading. Every summary
goes through it:

- `BuildArchiveRecord` reads the PRD's title paragraph, or the QA Report's
  `## Outcome` paragraph when one exists;
- `legacyArchiveParagraph` strips block quote markers and calls it for a
  Legacy Archive Folder;
- `internal/spec/cancel.go` reads a cancelled Spec's summary with it;
- `ParseArchiveRecord` reads a written record back with it.

## Expected

A summary paragraph that ends with a colon carries what it introduces, so the
record reads as a whole. Records already written stay byte-identical.

## Evidence

`docs/history/specs/0282-the-linux-lane-runs-like-ci.md` and the PRD at its
`source_revision` `b026a989f1fb3fc600aa71dd5c060b27eb022fdc`; the count of
records ending with a colon on 2026-10-20; no Finding.

# The storage report misses the default Artifact Roots

## Symptom

On 2026-10-20 `roundfix storage report` on the maintainer's machine listed one
Artifact Root, `.`, as `missing` with 508 Run rows and 0 bytes, `Measured
bytes: 0`, and 0 artifact bytes for every repository and every Run state. This
repository's `.roundfixrc.yml` sets `defaults.artifact_dir: ""`, so every Run
wrote its artifacts under the default root of its repository,
`~/.roundfix/artifacts/<repository id>/`. That tree held 37 repository
directories and about 605 MiB (`du -sk` reported 619,428 KiB), with 336
`runs/<run-id>` directories.

## Where

- `internal/store/journal.go`, `storageRunRecords` and
  `storageFilesystemGroups`: each Run's recorded `artifact_dir` is cleaned with
  `filepath.Clean`, so an empty value becomes `.`, and `storageDirectoryBytes`
  and `storageRunArtifactBytes` treat `.` as absent. A relative value is
  measured against the process's working directory.
- `internal/cli/gc.go`, `printStorageReport` (`:349` onward), prints the group.
- The recorded value is empty for every Implement Run: `runImplement` resolves
  the directory with `ValidateArtifactDirectory` and writes there, but
  `store.CreateRunRequest` carries no `ArtifactDir`. Review Runs record the
  configured value.
- `internal/store/journal.go`, `DiscoverArtifactRoots` (`:1583`), gives `roundfix
  gc sanitize` the same recorded value: its dry run on 2026-10-20 printed
  `Artifact Root: ` classified `unsafe`, "preserved because recorded Artifact
  Root "" is not a clean absolute path".
- Run Retention already resolves an empty recorded root
  (`internal/cli/run_retention.go`, `runRetentionArtifact`): the repository
  key's default root, or the recorded checkout's default root.

## Expected

The storage report measures each Run's artifacts where the Run wrote them: an
empty recorded root resolves to its repository's default root, a relative one
resolves against the Run's Git root, and an absolute one stays as recorded. The
report stays read-only and creates no directory.

## Evidence

`roundfix storage report` and `roundfix gc sanitize` (dry run) on the
maintainer's Roundfix Home, 2026-10-20, read-only; no Finding.

# The Linux Lane counts package patterns as packages

## Symptom

`roundfix deliver lane --all` printed `Linux Lane passed 1 package(s)` on
`main` although 43 packages ran in the container: 40 reported `ok` and 3
reported no test files. The number on the pass line is the number of package
arguments the host handed to the container, and `--all` hands it the single
pattern `./...`. The Delivery Queue gate prints the same line, so a gate that
tested a whole module reads as one package.

## Where

`internal/cli/deliver_linux_lane.go`, `runLinuxLane`: the lane log line
(`:239`) and the console line (`:243`) both print `len(result.Packages)`.
`result.Packages` is the pattern list, `./...` in `--all` mode or after a
`go.mod` or `go.sum` change, and the nearest package directories otherwise.
The packages that actually run are chosen inside the container by the lane
script: `go list -e -f '{{if or .GoFiles .TestGoFiles .XTestGoFiles}}{{.ImportPath}}{{end}}'`
expands the patterns, and `go test` runs the result. The user guide
(`docs/user-guide/commands/deliver.md`) documents the defect as intended: "`<n>`
counts selected package arguments". The gate and `roundfix deliver lane` share
`runLinuxLane`, so both print the wrong number.

## Expected

The pass line counts the packages `go list` selected in the container, the
packages `go test` ran, in the gate and in `roundfix deliver lane` alike. When
the count is unknown, the line says so instead of printing a number.

## Evidence

The operator's on-demand lane run on `main`, reported in the cycle AK operator
briefing of 2026-10-20 (43 packages ran, the line said 1); no Finding.
