# A push whose tests pass runs every contract under a measured budget — Technical Spec

## Executive Summary

The suite-time verdict moves out of the step that times the suite. With
`SUITE_BUDGET_VERDICT` naming a file, `make test-budget` writes its verdict
line there and returns 0 on an overrun; a new target, `make
suite-budget-check`, prints the recorded line and fails when it says the
budget was exceeded, when nothing was recorded and when the line cannot be
read. The push path of `.github/workflows/ci-verify.yml` records the verdict
under `${{ runner.temp }}` in `Verify`, keeps `Verify docs` and `Verify every
contract` where they are, and adds a last step, `Check the suite-time budget`,
that runs whenever `Verify` passed. The budget becomes one number,
`SUITE_BUDGET_SECONDS ?= 420` in the `Makefile`, and the workflow stops
overriding it. The trade-off accepted is a coarser detector: on the fast
runner a suite must slow by about 1.95 times to fail, because one absolute
number must also pass the slow runner, whose suites measured up to 343 s
(ADR-0387).

## Implementation Design

### Interfaces

```make
SUITE_BUDGET_SECONDS ?= 420
# SUITE_BUDGET_VERDICT: optional path; set by the caller, no default.
test-budget: gocache-bound           # records the verdict when SUITE_BUDGET_VERDICT is set
suite-budget-check:                  # judges the recorded verdict
```

```yaml
- name: Verify
  id: verify
  env: { SUITE_BUDGET_VERDICT: "${{ runner.temp }}/suite-budget-verdict", ... }
- name: Check the suite-time budget   # last step
  if: ${{ !cancelled() && github.event_name == 'push' && steps.verify.outcome == 'success' }}
  run: make suite-budget-check
```

### Data Models

The verdict file holds exactly one line, the line `test-budget` prints:
`suite-time budget: <n>s of <budget>s` or `suite-time budget exceeded: the
suite took <n>s against a budget of <budget>s`. It lives in the runner's
temporary directory, which GitHub empties at the start and end of each job,
and nothing else reads it.

### API Contracts

1. API Contract: recorded verdict. `make test-budget` with
   `SUITE_BUDGET_VERDICT` set: removes that file first; runs the suite as
   today; a failing suite exits with its status and leaves no file; otherwise
   prints the verdict line, writes it to the file, prints `suite-time verdict
   recorded in <file>; make suite-budget-check judges it`, and exits 0 even on
   an overrun. Without the variable its output and exit status are today's.
2. API Contract: verdict check. `make suite-budget-check` with no variable
   or no file prints `suite-time budget: no verdict recorded at '<file>'; run
   make test-budget with SUITE_BUDGET_VERDICT set first` and exits non-zero;
   with a line starting `suite-time budget exceeded:` prints it and `the
   budget is SUITE_BUDGET_SECONDS in the Makefile; raise it deliberately or
   find the regression` and exits non-zero; with a line starting
   `suite-time budget: ` prints it and exits 0; with anything else prints
   `suite-time budget: unreadable verdict at '<file>'` and exits non-zero.
3. API Contract: push wiring. Exactly one step sets `VERIFY_TEST_TARGET:
   test-budget`, the `Verify` step with `id: verify`; no step sets
   `SUITE_BUDGET_SECONDS`; `Check the suite-time budget` is the job's last
   step, after `Verify every contract`, with the condition and verdict path of
   the Interfaces sketch.

## ADR Alternatives

- ADR-0387: new; it rejects a calibrated budget, running the docs and contract
  steps before the timed suite, a separate job and parsing the `Verify` log,
  and this design takes none of them.
- ADR-0259: amended; its sequential-test rule and the race-detector and
  splitting rejections stand, and only its last consequence, the 240 s CI
  budget until CI measures the converted suite, is replaced by the measured
  420 s.
- ADR-0253: kept; the Full Contract Run still runs on every push and before
  every release, and the change restores it on pushes whose suite was slow;
  none of its rejected options (contracts in `make verify-docs`, a hand-kept
  list, an environment switch widening `make verify-docs`) is taken.
- ADR-0089: not applicable; the injected environment rule is unchanged.
- ADR-0252: not applicable; Contract Relevance and the selective gate are
  unchanged.
- ADR-0271: not applicable; no test bounds anything by real time, and the
  new test makes the verdict deterministic with budgets of -1 and 420.

## Testing Approach

New file `internal/verifyselect/suite_budget_test.go`, every test and subtest
calling `t.Parallel()` first, each subtest in its own `t.TempDir()` with a
`go` stub script and the environment reduced to `PATH`, `TMPDIR` and `HOME`
(the stub answers the `gocache-bound` run as `TestVerifyContractsRunsEveryContract`
does):

- `TestTheSuiteTimeBudgetIsRecordedThenJudged`, subtests
  `an overrun is recorded without failing` (variable from the environment,
  budget -1), `without a verdict file an overrun fails at once`,
  `a failing suite records no verdict` (stale file present, stub fails
  `test`), `the default budget is 420 seconds`, `the check fails an exceeded
  verdict`, `the check passes a verdict within the budget`, `the check fails
  without a verdict` and `the check fails an unreadable verdict`.
- `TestTheCIPushJudgesTheSuiteTimeBudgetLast`: API Contract 3 over the parsed
  workflow.

On the authoring base both tests fail; only `without a verdict file an
overrun fails at once` passes there, which shows that path is kept.
`TestMainAndReleaseRunEveryContract` and
`TestTheCIPullRequestSkipsOnlyTheRepeatedDocumentationContracts` pass
unchanged; no existing test changes.

Sabotage proofs, each run on the prototype: deferral removed (`exit 1` after
recording) fails `an overrun is recorded without failing`; the check passing
an exceeded line fails `the check fails an exceeded verdict`; no removal of a
stale file fails `a failing suite records no verdict`; default 360 fails `the
default budget is 420 seconds`; a missing verdict passing fails `the check
fails without a verdict`; an unreadable verdict passing fails `the check
fails an unreadable verdict`; `SUITE_BUDGET_SECONDS: "240"` put back in the
workflow, or the check's condition reduced to
`github.event_name == 'push'`, fails `TestTheCIPushJudgesTheSuiteTimeBudgetLast`.

## Risks & Considerations

- The verdict path must be the same in both steps; API Contract 3 pins both.
- A push whose suite is over budget now spends the docs and contract steps
  (about six minutes measured) before failing; the evidence they produce is
  the point.
- The real workflow run is proved only after the merge; that is the PRD's one
  Unreachable Acceptance entry.

## Decisions

- Record the verdict in `make test-budget` and judge it in a new
  `make suite-budget-check`; no log parsing, no step outputs.
- One budget, 420 s, in the `Makefile`; the workflow sets none.
- ADR-0387, amending ADR-0259.
- One implementation Task and the QA gate.
