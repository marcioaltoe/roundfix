Run this mode in the repository the session works in, never in a Daemon-assigned Run.

1. Check: run `roundfix update check --refresh --format json`. When the installed Roundfix does not know the command, run `roundfix upgrade` and then the check again. Report the installed and latest versions, each newer release with its titles, the Baseline line, and every `recommendations.categories[]` row with its `category`, `state`, configured and recommended profiles, its `deviation` and `repin` when present, and its `adopt` command. When the report carries `userSkills`, show each copy with its `remove` and `refresh` commands, say which copies hide a declared header (`hidesDeclaredHeader`), and ask once which commands to run, recommending the removals, before going on: both write outside the repository, a refresh through any link the copy's `resolved` names, and a removal deletes the copy; run only the ones the user approves. Before the mode's report, when the report carries `recommendations.categories`, ask once, in one question, with the recommended option first: adopt every reported category by running `roundfix profiles check --apply --scope <scope> --yes` for each scope; re-pin each category whose state is `pinned_to_older_snapshot` by setting `profiles.<category>.deviation.from` to the report's `snapshot` in the configuration file named by its `source`, then adopt every remaining reported category with the same command; or keep the configuration. Run only what the user chooses, re-pin before adopting, and never edit a configuration or run `--apply` without that answer. When the mode runs at session start because `update.mode` is `auto`, report the `recommendations` categories and run no profile fix. When `state` is `unknown` or `development` and `baseline.state` is not `plan_ready`, report that nothing can be applied now and stop.
2. Upgrade: when `state` is `update_available`, run `roundfix upgrade`. When it fails, report its manual fallback and stop without applying a Baseline plan. After `roundfix upgrade` succeeds, run `roundfix update check --format json` again with the installed binary and use that report, including its `recommendations`, for the remaining steps.
3. Preview: run `roundfix baseline update --repo <root> --format json` with the binary now installed and show its state, each file change, each history unit with its paths, each skill it refreshes, restores or deletes, and its `planDigest`. When the state is `current`, report the versions and stop. When it needs a new decision or an adoption, ask the user as the stop-and-ask clause of `docs/agents/agent-instructions.md` says, and never pass `--adopt-suggested` unasked.
4. Apply: apply exactly the previewed plan with `roundfix baseline update --repo <root> --confirm-plan <planDigest> --format json`. Ask first, in one question with the recommended option first, when the plan deletes files, that is when `history.units` or `skills.retired` is not empty: apply the whole plan, apply it without history (preview again with `--no-history` and confirm that digest), or stop. Ask first, too, when `git status --porcelain` shows uncommitted changes. When the mode runs at session start because `update.mode` is `auto`, apply no Baseline plan over uncommitted changes; report it for a later `--update`.
5. Report the versions before and after, the applied Plan Digest and the changed files. When the check's `authoringModels.state` is `unapplied` after these steps, name its `next` command. When it is `undeclared`, show its `recommendation` and leave `.roundfixrc.yml` to the user; never write it. This mode never commits, pushes or opens a pull request; committing follows the repository's own rules.
