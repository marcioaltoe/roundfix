# Task 01: The Baseline text sends every repository rule to the specific-repository guide, with an example

## Overview

Three existing Normative Clauses keep their identities and their
`mandatory` force and gain the placement rule: a repository's own rules and
variations go only in `docs/agents/specific-repository.md`. The guide
templates of `agent-instructions.md` and `skill-dispatch.md`, the root
pointer and the starter of a new `docs/agents/specific-repository.md` say
the same, and the starter shows how a rule is written there. The derived
Baseline files are regenerated by their commands, and this repository's
managed guides are refreshed with the sanctioned `baseline update`, after
which a second refresh reports `current`.

## Requirements

1. MUST change, in `internal/baseline/assets/modules/core.json`, only the
   `guidance` of these two clauses, to these texts word for word:
   - `clause.core.keep-root-compact`: "Keep root agent instructions as short
     mandatory pointers. Setup owns only marked baseline content; preserve
     repository-authored bytes outside setup markers and keep
     project-specific architecture and policy in repository-owned documents.
     Write each rule or variation of this repository only in
     `docs/agents/specific-repository.md`, never in a root instruction file
     or in a Baseline guide, inside or outside its setup markers. Write it
     there under a heading of its own, as a bullet that states its force,
     such as `- **mandatory**: <rule>`, with the date of the decision that
     set it when it has one."
   - `clause.core.activate-matching-skills`: its current text followed by
     " Write a stricter trigger, the model or effort a skill runs with, or
     any other dispatch rule of this repository in
     `docs/agents/specific-repository.md`, never in this guide."
2. MUST change, in `internal/baseline/assets/modules/context-workflow.json`,
   only the sentence "Preserve repository-authored extensions outside setup
   markers." of `clause.context.docs-one-job-per-directory`, which becomes
   "Preserve repository-authored bytes outside setup markers, and add a
   repository rule only to `docs/agents/specific-repository.md`."
3. MUST keep, for each of the three clauses, its id, its `mandatory`
   `enforcement`, its rule and its absence of `replaces`, and MUST add or
   remove no clause and no rule. MUST raise by one the `version` of
   `rule.core.compact-root`, `rule.core.skill-dispatch` and
   `rule.context.docs-layout`.
4. MUST change the four templates to these texts:
   - `templates/guides/agent-instructions.md`: its two sentences about
     repository authors become "Repository authors write every
     project-specific rule or variation, stricter or not, only in
     `docs/agents/specific-repository.md`, never in this guide or in a root
     instruction file."; every token line after them stays.
   - `templates/guides/skill-dispatch.md`: its intro becomes "This
     setup-owned guide is generated from the active modules. Activate every
     matching skill before governed work; write a stricter trigger of this
     repository in `docs/agents/specific-repository.md`, never in this
     guide."
   - `templates/root/repository-extension.md`: its bullet becomes "- Read
     {{reference.repository-extension}} for project-specific hard rules,
     and write every rule or variation of this repository there, never in
     this file or in a Baseline guide."
   - `templates/extensions/specific-repository.md`: after its heading, one
     blank line and this paragraph: "Write each rule or variation of this
     repository here, never in a root instruction file or in a Baseline
     guide. Give each rule a heading of its own and state it as a bullet
     with its force, such as `- **mandatory**: run the schema check before
     changing a migration (2026-11-16)`, with the date of the decision that
     set it when it has one."

   MUST raise by one, in `templates/index.json`, the `version` of the four
   changed templates; in `core.json`, the `version` of the guides
   `guide.agent-instructions` and `guide.skill-dispatch`; and in
   `repository-extension.json`, the `version` of the root block
   `root.repository-extension`. Every template keeps its tokens.
5. MUST regenerate, in this order and never by hand: the module record with
   `go test ./internal/baseline -run '^TestEveryBaselineModuleVersionIsRecorded$' -record-module-versions -count=1`
   (it writes the next version of each changed module; the Spec names no
   number); the derived Baseline files with `make baseline-digests`; and, as
   the Task's last step, this repository's managed carriers with
   `go run -buildvcs=false ./cmd/roundfix baseline update --repo . --no-skills --no-history --yes --format text`,
   whose second run reports `current`. The files these commands rewrote in
   the measurement of `_tasks.md` are declared below; any other file they
   rewrite on the tree the Task runs on is recorded by the Daemon.
6. MUST change, in `internal/baseline/vendored_skill_clauses_test.go`, only
   the literal guidance of `clause.core.activate-matching-skills` to the
   text of requirement 1, so its two tests pass on the new catalog.
7. MUST add `internal/baseline/repository_rule_placement_test.go` with
   `TestTheBaselineSendsRepositoryRulesToTheSpecificRepositoryGuide`,
   calling `t.Parallel()` first, with these subtests. Each asserts a whole
   value, never a word alone:
   - `keep_root_compact`, `activate_matching_skills` and
     `docs_one_job_per_directory`: in the embedded catalog, the clause
     carries the exact guidance of requirement 1 or 2, `mandatory` force,
     its rule and no `replaces`; for the third, the old sentence is absent;
   - `agent_instructions_guide`, `skill_dispatch_guide` and
     `docs_layout_guide`: the Standard TypeScript formatter golden of that
     guide holds the clause as exactly one line `- **mandatory**: <guidance>`
     and, for the first two, the template sentence of requirement 4;
   - `root_pointer`: a plan built with the repository extension enabled, as
     `TestRepositoryExtensionMigratesOneLegacyCarrier` builds one, writes
     the pointer bullet of requirement 4 into `AGENTS.md`, with the
     reference rendered;
   - `starter`: on a repository with no rules file, that plan writes
     `docs/agents/specific-repository.md` as the heading, a blank line and
     the paragraph of requirement 4, exactly.
8. MUST NOT change, by hand or by command, any Source Baseline, Setup
   Snapshot, profile other than `standard-typescript-monorepo.json`, the
   formatter golden `AGENTS.md`, `docs/agents/specific-repository.md`,
   `.roundfixrc.yml`, the Makefile, a workflow, `go.mod` or a lint
   configuration. Of the Governed Paths the Task changes only those it
   declares below, all listed in `_authorization.md`.

- [ ] The root pointer and a new `docs/agents/specific-repository.md` say the same, and the starter carries the example.
- [ ] The three clauses keep their identities, force and rules; the vendored-skill clause tests and the whole Baseline suite pass.
- [ ] The derived files and this repository's guides are current: a second managed refresh reports `current`, and the documentation contracts pass.
- [ ] Restoring any old sentence makes a named subtest fail.
