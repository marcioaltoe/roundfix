# A QA Report relies only on evidence its own Run produced

A later Run's terminal QA gate can settle a Spec on evidence an earlier Run of the same Spec left on the item branch. Quaestor's gate for its Spec 0071 failed on a file that ran the console script inside an earlier Run's Run Worktree and on a replay script that pinned a head older than the Task that fixed the text under test, while the real head passed; the item parked and was retried by hand. Roundfix 0.137.1 accepts such a report everywhere. After this Spec, every QA settlement path refuses Borrowed Evidence: a linked evidence file the audited head or the QA Report Import already held byte for byte, an executable the report lists outside its own worktree, or a path inside another Run's Run Worktree. The Daemon gives the gate one repair turn to regenerate it, and the qa-gate skill writes each pass's evidence under its own directory and records the executables it ran.

## Goals

- `roundfix qa-report accept`, the Settle Command for a `qa` Task and the
  Daemon's QA settlement refuse Borrowed Evidence with one text naming each
  item, its line and its reason.
- The Daemon returns the QA turn once with the Run Worktree, the audited head
  and the pass's evidence directory, so the gate regenerates the evidence
  instead of parking the Run.
- The qa-gate skill writes each pass's evidence under a directory no earlier
  pass used, builds and runs executables from its own Run Worktree, and lists
  them in `user_flow_executables`.
- Reports in archived Specs, Carried Rows and reports written before the key
  existed keep their acceptance; the rule reads bytes and paths, so it holds
  for Go, Python `.venv` and Node gates alike.

## User Stories

1. As a maintainer whose Spec is retried after an unresolved Run, I want the
   new QA gate refused when it cites the earlier Run's evidence, so that a
   verdict always describes the head it claims.
2. As an adopter running a Python or Node product, I want my gate's
   `.venv/bin/<tool>` or `node_modules/.bin/<tool>` accepted when it lives in
   my Run Worktree, so that the rule never refuses an honest gate.
3. As the QA Agent, I want the repair prompt to name the Run Worktree, the
   audited head and where to write this pass's evidence, so that one repair
   turn is enough.

## Core Features

1. One shared check in `internal/spec` that finds Borrowed Evidence for a QA
   Report by its four reasons, with Carried Rows exempt and nothing checked
   outside Git.
2. `qa-report accept` and the Settle Command apply it after the evidence-link
   rule, with the shared refusal text.
3. The Daemon applies it after the QA turn with the import and the Run Branch
   it knows, gives one repair turn, refuses at the QA Report commit boundary,
   and tells the gate its Run Worktree, audited head and evidence directory.
4. Documentation: the qa-gate skill, the qa-report, settle and implement
   guides, the Roundfix settle and implement references, and `CONTEXT.md`.

## User Experience

On Quaestor's case, `roundfix qa-report accept` exits `1` with
`roundfix: QA Report eligibility refused: QA Report evidence does not belong to this Run: evidence/2026-11-06-gate/head-exclusive.execution.txt (line <n>, reused); …`.
In a Run, the gate first gets one repair turn that names the Run Worktree,
the audited head and `qa/evidence/<report name>/`; a report still carrying
Borrowed Evidence settles the QA Task `failed` with the same text and no QA
Report commit. An honest report sees no new output.

## Success Metrics

1. Success Metric: on a temporary repository whose earlier commit holds
   `qa/evidence/2026-11-06-gate/head-exclusive.execution.txt` and
   `replay.py.txt`, an uncommitted `pass` report linking both makes
   `qa-report accept` exit `1` naming both as `reused`; at `2e59aebe` the same
   report exits `0` (characterized on 2026-11-09).
2. Success Metric: the same report linking a new untracked file and a tracked
   file whose bytes changed is accepted; a committed report whose evidence its
   own commit added is accepted, and one whose evidence an earlier commit
   added is refused.
3. Success Metric: a link inside a Carried Row's Results line or
   `### <row-id>` block is exempt; the same link in an observed row is
   refused.
4. Success Metric: `user_flow_executables` entries `./bin/tool`,
   `.venv/bin/tool` and `.venv/bin/python` (a link to an interpreter outside
   the worktree) are accepted; `/elsewhere/bin/tool` and `../other/bin/tool`
   are `outside the worktree`; a scalar value is `not a list of paths`; an
   absent key is accepted.
5. Success Metric: an evidence file naming `<another Run Worktree>/.venv/bin/tool`
   is refused with `names another Run Worktree <path>`; a path inside the
   report's own Run Worktree, inside the same Run's Task worktree, or inside
   the user checkout is not.
6. Success Metric: in a Daemon Run, a QA report citing evidence the audited
   head holds gets exactly one repair turn whose prompt names the Run
   Worktree, the audited head and the evidence directory; after a repair that
   regenerates the evidence the QA Task settles `completed` with a QA Report
   commit; without one it settles `failed` with the shared text, publishes
   the `evidence_binding` event with outcomes `repair` and `refused`, and
   creates no QA Report commit.
7. Success Metric: a re-run row citing a file the QA Report Import copied,
   unchanged, is refused as `imported`.
8. Success Metric: every existing evidence-link, prior-pass, carry-forward,
   settle and qa-report test passes unchanged, and `roundfix archive` code is
   untouched.

## Acceptance evidence

The outside-evidence row rests on two sources this Spec did not write.

- The Quaestor report adopted in `references/` (measured 2026-11-06 in
  `gesttione-solutions/quaestor`, commit `8559795`): the evidence directory
  `qa/evidence/2026-11-06-gate/` an earlier Run left on the item branch, a
  file calling `…/run_20261106T154834Z_fa21ea4f4f57f94a/.venv/bin/quaestor`
  and a replay file pinning `HEAD = 4bc81f4`.
- SLSA Build Provenance v1.2 (https://slsa.dev/spec/v1.2/build-provenance,
  read through Exa on 2026-11-09): provenance exists so that "Consumers of
  the provenance can verify that the artifact was built according to
  expectations", and "a build that takes a git repository URI as a parameter
  might record the specific git commit that the URI resolved to as a
  dependency." Evidence that cannot be tied to the commit it claims to
  describe cannot be verified against it.

Taken from those and the reading, with no further interview:

- A mechanical check on every QA settlement path, after the evidence-link
  rule, instead of prose only; one repair turn in a Run, as ADR-0351 gives
  links. See ADR-0376.
- "Reused" is decided by bytes against the audited head, not by a commit
  written inside the evidence, so no adopter evidence format is parsed.
- `user_flow_executables` is optional and compared lexically, so reports
  written before it and Python virtual environments keep working.
- Only another Run's Run Worktree is named; the user checkout is not.
- Carried Rows stay exempt; `roundfix archive` is unchanged.
- The release is the operator's patch right after the merge; no Task
  releases.
