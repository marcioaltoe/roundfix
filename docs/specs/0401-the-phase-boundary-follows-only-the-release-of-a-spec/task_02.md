# Task 02: The autonomous-work clause states the boundary after a Spec's delivery and release

## Overview

The `autonomous-work` Baseline clause that tells a supervising session when
to end says that a Spec's phase boundary comes after its delivery and
release, or its merge when it releases nothing, and that an authoring phase
is not one. The clause keeps its identity and force. The derived Baseline
files are regenerated by their commands, and this repository's managed
`docs/agents/autonomous-work.md` is refreshed with the sanctioned
`baseline update`, after which a second refresh reports `current`.

## Requirements

1. MUST change, in `internal/baseline/assets/modules/autonomous-work.json`,
   only the `guidance` of `clause.autonomous.loop-07-outlive-the-turn`, to
   the text of `_techspec.md` → API Contract 3, word for word.
2. MUST keep the clause's id, its `mandatory` `enforcement`, its rule and
   its absence of `replaces`, and MUST add or remove no clause and no rule
   (`_techspec.md` → invariant 5).
3. MUST regenerate, in this order and never by hand: the module record with
   `go test ./internal/baseline -run '^TestEveryBaselineModuleVersionIsRecorded$' -record-module-versions -count=1`
   (it writes the next version of the module; the Spec names no number);
   the derived Baseline files with `make baseline-digests`; and, as the
   Task's last step, this repository's managed guide with
   `go run -buildvcs=false ./cmd/roundfix baseline update --repo . --no-skills --no-history --yes --format text`,
   whose second run reports `current`. The files these commands rewrote in
   the measurement of `_tasks.md` are declared below; any other file they
   rewrite on the tree the Task runs on is recorded by the Daemon.
4. MUST change `TestTheOutliveTheTurnClauseStatesThePhaseBoundary` in
   `internal/baseline/phase_boundary_clause_test.go` so that its phrase
   table holds, each exactly once in the clause, the Standard TypeScript
   golden and this repository's guide:
   - `phase_boundary_after_delivery_and_release`: "The phase boundary of a
     Spec comes after the Spec is delivered and released, or after it
     merges when it releases nothing";
   - `authoring_phase_is_no_boundary`: "An authoring phase is not a phase
     boundary: the session goes on to the next phase";
   - `authoring_skill_says_where_it_runs`: "each authoring skill says when
     that phase runs in a subagent with its own context";
   - the other phrases it asserts today, except the removed
     `phase_boundary_is_recorded`.

   It MUST also assert, in the same three places, that "after each
   authoring phase" occurs zero times.
5. MUST NOT change, by hand or by command, any other module, any template,
   Source Baseline, Setup Snapshot or profile other than
   `standard-typescript-monorepo.json`, `AGENTS.md`, `CLAUDE.md`,
   `docs/agents/specific-repository.md`, `.roundfixrc.yml`, the Makefile, a
   workflow, `go.mod` or a lint configuration. Of the Governed Paths the
   Task changes only those it declares below, all listed in
   `_authorization.md`.
