# One history root under `docs/`

Retired documentation is stored in three places and none of them is right. In this
repository it sits at the repository root, beside the Go source trees. In every
other repository that adopted Roundfix it sits inside the active directories
themselves, one archive folder per documentation tree, so history and live work
share a parent. Retired ADRs never moved at all, so an Agent loading decision
context reads inactive decisions alongside active ones. And Review Artifacts have
no terminal home: a Pull Request whose Spec is known already writes its reviews
inside that Spec and travels with it, but the orphan case — fifty folders here —
accumulates beside the active Spec Root forever, with nothing deciding when one is
finished. This Spec gives every retired family one home under `docs/`, teaches
Roundfix to move a repository there on its own, and settles when an orphan review
is history rather than work in flight.

## Goals

1. One history root under `docs/` holds every retired family, so a reader learns
   one location instead of one per tree and one per repository generation.
2. A repository on an older layout reaches the new one by running Roundfix,
   without a maintainer moving files by hand or knowing which layout it is on.
3. An Agent loading decision context reads only decisions that are still in force.
4. A finished review stops accumulating beside live work.
5. Review never reads history, whether as a diff or as a project rule.
6. The fix reaches the rest of the fleet as a release.

## User Stories

1. As a maintainer, I want retired documentation to live under `docs/`, so that
   the repository root lists what the project is built from rather than what it
   used to be.
2. As a maintainer of a repository adopted before this change, I want Roundfix to
   move my archived material into the new layout when I run it, so that adopting
   the fix costs a command rather than a migration I have to design.
3. As an Agent forming a design recommendation, I want the decision directory to
   contain only decisions still in force, so that I do not weigh a superseded
   decision as if it were current.
4. As a maintainer of a repository that has run many review loops, I want a
   finished review moved into history and an in-flight one left alone, so that the
   active Spec Root shows work rather than accumulation.
5. As a maintainer opening a pull request, I want review to ignore the history
   tree entirely, so that archiving does not re-review content already reviewed
   when it was written.
6. As a maintainer of another repository, I want this as a released version, so
   that I can adopt it without building from source.

## Core Features

1. **One history root under `docs/`.** Every retired family resolves under a
   single root inside the documentation tree: retired Specs, retired findings,
   retired decision records, declined intent entries, and retired Review Artifacts
   each have one directory there. The resolver that answers where a family lives
   remains the single place that knows.
2. **Every retired family relocates.** Retired Specs and findings move from
   wherever the repository holds them. Retired decision records and declined
   intent entries relocate for the first time: a record whose lifecycle status
   retires it, and an intent entry that was declined, leave the active directory.
   A pending proposal stays, and a record with no lifecycle status stays unless its
   body marks it inactive.
3. **A Review Artifact has a terminal home.** A review whose owning Spec is known
   already lives inside that Spec and travels with it; this Spec leaves that path
   unchanged. An orphan review — a Pull Request with no owning Spec — retires into
   the history root when it is finished, and the live root loses its underscore so
   both paths read the same.
4. **Finished is decided locally.** An orphan review is finished when the head its
   round recorded is an ancestor of the default branch, or is unreachable with its
   branch gone. A reachable non-ancestor head, and any head the check cannot
   decide, stays live. The decision uses local Git only, so the migration runs
   offline.
5. **The resolver never writes into history.** A new Round for an already-retired
   Spec's Pull Request writes to the live root, never into the history tree, so
   history is not mutated by ordinary work.
6. **The Baseline migrates a repository it finds on an older layout.** Running the
   Baseline detects retired material in any location a previous layout used and
   moves its contents into the new root. The migration is idempotent: a repository
   already on the new layout is unchanged, and migrating twice reaches the same
   state.
7. **A migration that refuses rather than overwrites.** When a file's destination
   is already occupied, no move is performed for that file and both paths are
   reported with the reason. A repository holding two layouts at once is a reported
   state, never a silent merge.
8. **The migration reports what it moved.** Every relocation appears in the
   Baseline's own output as a change, at the detail it already gives the repository
   bytes it manages.
9. **Review ignores the history tree completely.** No path under the history root
   is reviewed as a diff, and none is read as a project rule. Because the root
   carries no underscore, the diff exclusion is path-anchored on `docs/history/`
   rather than matched by prefix at any depth. The same anchoring covers a review
   directory inside an active Spec, which the current prefix-matched exclusion does
   not reach.
10. **Every carrier that names the old location is updated**, so a reader following
    the documentation reaches the place the tool writes to.

## User Experience

The Baseline is the only surface a maintainer interacts with for the migration.
Running it against a repository on an older layout reports the relocations
alongside the changes it already reports, and applying performs them. Running it
against a repository already on the new layout reports nothing about history. A
refused relocation names the file, the occupied destination, and what to resolve
before the next run — one deterministic next action.

An orphan review left live is reported as live with the reason, so a maintainer
can see that the tool considered it and decided against moving it.

## Non-Goals / Out of Scope

- Changing what archiving means, when a Spec may archive, or what the Archive
  Command verifies before it moves anything.
- Changing any retired artifact's content. Every byte moves unread.
- Changing the decision-record lifecycle vocabulary or how a status is recorded.
- Changing where a Spec-owned Review Artifact is written; that path already works
  and already travels with its Spec.
- Reading Pull Request state from the hosting provider, in the migration or
  anywhere this Spec adds. The refusal is deliberate and recorded.
- Scoping, adding, or removing any consistency-check detector.
- Migrating any repository other than this one as part of delivery.
- Any repository configuration change unrelated to the history root.

## Success Metrics

- The repository root lists no archive directory, and `docs/history/` holds all
  five retired families.
- The active decision directory contains only records active by the lifecycle
  rule.
- A repository on the pre-0085 per-tree layout, which this Spec did not build,
  reaches the new layout by running the released Baseline once, with its archived
  bytes unchanged and its history preserved.
- Running the Baseline twice against one repository produces no second change.
- Of the fifty orphan review folders measured here on 2026-08-12, those whose
  recorded head is an ancestor of the default branch retire, and any still in
  flight stays.
- A review directory inside an active Spec is excluded from review, which the
  current configuration does not achieve.
- The documentation gate and the full verification gate pass with history at its
  new location.
- The fix release publishes, and the version it names is installable.

## Decisions

- The root is `docs/history/`, holding five families. See ADR-0120.
- An orphan review retires on local Git reachability, and the resolver never
  writes into history. See ADR-0123.
- All retired families relocate, finishing the retired-decision relocation Spec
  0085 recorded as assigned to later Tasks. Maintainer decision, 2026-08-12.
- The Baseline performs the migration when it runs, rather than offering a
  separate migration command. Maintainer direction, 2026-08-12.
- The migration recognises an archive root outside the documentation tree as well
  as the per-tree layout, so it is idempotent against a repository that ran an
  interim binary.
- A destination collision refuses that file's relocation and reports both paths.
- This repository migrates locally in this Spec rather than by running the
  released binary on itself, because it is the only repository on the layout the
  release corrects.
- An undecidable review head stays live, because keeping a finished artifact costs
  a directory while retiring a live one breaks a Round in progress.

## Open Questions

- Whether the non-reachability of history from the review tool's rule-source
  patterns can be made mechanical, or stays a reviewed comment. The TechSpec
  decides; until then the comment stands and that half of Core Feature 9 is
  asserted rather than proven.
- Whether relocating retired decision records moves the count a consistency
  detector reports enough to matter before that detector is scoped to active Specs
  in a later Spec. The default is that the count moves and is recorded, not
  suppressed.
- Whether an orphan review whose head is undecidable should be reported once or on
  every run. Once per state change is the default, so a permanently undecidable
  artifact does not become noise.
