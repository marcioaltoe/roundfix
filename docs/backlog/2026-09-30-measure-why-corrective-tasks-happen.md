# Measure why corrective Tasks happen

## Opportunity

Roundfix cannot say how many corrective Tasks and Verification retries come from missing repository knowledge and how many from plain implementation error. The Run Database records retries and outcomes, but nothing classifies their cause.

## Value

The number decides whether a memory layer for Agent Sessions is worth reopening. The maintainer declined one on 2026-09-30 and chose committed guides for cross-Task lessons. Published evidence on agent memory and context files is weak or negative, so the decision needs Roundfix's own data.

## Shape

A read-only report over terminal Runs of a period: for each corrective Task and each failed Verification attempt, the failing check and a cause class drawn from a closed list (scope or authorization fact, shared-section contract, repository convention, implementation defect, environment). The classification uses deterministic signatures only, never a model judgment. Reopen the memory question only if repository-knowledge causes dominate.
