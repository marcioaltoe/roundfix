# The changed-path audit does not know sanctioned fallout

## Symptom

ADR-0081 settles that derived pins regenerated by the sanctioned command are
deterministic fallout of an expressly authorized edit and need no separate
authorization. The QA gate's changed-path audit does not implement that: it reads
the authorization record's exact `paths` and refuses any changed file absent from
it, including the derived artifacts the authorized edit necessarily regenerates.

Measured on Spec 0094 on 2026-08-13. A tooling Task edited an authorized Source
Baseline carrier and regenerated its derived artifacts through the sanctioned
command. The gate refused:

```text
QA-AUTH-PATHS
detail: Task task_15 commit … changes
        internal/baseline/assets/source-baselines/…/baseline.json
        outside the exact bounded files
QA-AUTH-PATHS
detail: … changes internal/baseline/assets/source-baselines/index.json
        outside the exact bounded files
```

Both files are regenerated, never hand-edited. The only way through is to list
every derived artifact in the authorization record, which makes the record
enumerate consequences rather than the cause — exactly what ADR-0081 rejected when
it refused to widen Task authorization boundaries and kept the grant drawn around
the Skill edit with its computable effects following it.

## Where

The QA gate's mechanical stage, where it compares a Task commit's changed paths
against the authorization record's `paths`.

## Expected

The audit recognises a derived artifact as fallout of an authorized source edit,
the way ADR-0081 defines it, and does not require it to be enumerated. A
hand-edited derived value stays an unauthorized mutation, which is the
distinction ADR-0081 already draws and the audit currently cannot make.

Worth settling in the same work: whether the audit should also distinguish
production code, which needs no grant at all, from protected tooling — Spec 0094
had to split a Task because one bounded commit mixed an authorized asset with an
ordinary Go file, and the audit read both as governed.

## Evidence

`docs/specs/0094-one-history-root-under-docs/qa/qa-report-2026-08-13.md`, the
four `QA-AUTH-PATHS` findings against `task_15`. The workaround is recorded in
`docs/workflow/authorizations/2026-08-12-the-archive-root-under-docs.md` under
its 2026-08-13 extension.
