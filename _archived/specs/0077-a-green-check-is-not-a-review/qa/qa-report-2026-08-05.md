## Findings

### F-001 — `watch --help` still teaches that a green status can verify a head

- Impact: `Trust-Damage`.
- Actor and step: a Roundfix operator reads `watch --help` before deciding
  whether `--until-clean` provides the review guarantee.
- Expected: help must say that `verified` requires a recognised
  review-completed current-head signal or CodeRabbit approval, and must not
  present a successful check conclusion alone as accepted review evidence.
- Actual: the built command says Clean accepts “a successful CodeRabbit check
  or commit status, or a CodeRabbit APPROVED review.” The synchronized Skill
  and tested runtime instead require a recognised review-completed signal and
  keep an unknown green signal `pending`.
- Reproduction: build `f894538a`, then run
  `rtk proxy ./bin/roundfix watch --help` from the repository root.
- Evidence: `qa/evidence/2026-08-05-f894538a/command-results.md` and
  `internal/cli/cli.go` in the `watch` usage text.
- Affected row: 18. Runtime rows 02-12 remain valid; this is contradictory
  public guidance, not a runtime-gate regression.
- Required correction: align the built `watch --help` text and its exact CLI
  assertion with the recognised-review-completed contract, then rerun the
  built-help reproduction, the affected CLI help test, `rtk make verify`, and
  one adjacent unknown-green runtime canary.
